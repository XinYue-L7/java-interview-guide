HashMap 底层实现原理（JDK 1.8）？
HashMap高频

底层：数组 + 链表 + 红黑树

  1. 存储：Node<K,V>[] table，每个位置是一个桶。
  2. 哈希：(n-1) & hash定位桶位置。
  3. 冲突：链地址法，同一桶用链表串联。
  4. 树化：链表长度≥8且数组长度≥64时，链表→红黑树，查询O(log n)。
  5. 退化：元素≤6时红黑树→链表。
  6. 扩容：默认容量16，负载因子0.75，超过阈值扩容为2倍，rehash。

💡 JDK7→JDK8变化：头插法→尾插法(解决死循环)，引入红黑树。

HashMap 的 put 方法流程？
HashMap源码
  1. 计算key的hash值：(h = key.hashCode()) ^ (h >>> 16)
  2. 判断table是否初始化，未初始化则调用resize()
  3. 通过(n-1) & hash计算桶下标
  4. 桶为空→直接插入
  5. 桶不为空→判断是链表还是红黑树
  6. 链表：遍历，key相同则覆盖，否则尾插；红黑树：执行树插入
  7. 插入后判断size > threshold，是则扩容

HashMap 为什么线程不安全？如何解决？
HashMap并发

不安全表现：

  • JDK7：扩容时头插法导致链表反转，形成环形链表→死循环。
  • JDK8：多线程put可能导致数据覆盖丢失。

解决方案：

  • ConcurrentHashMap — 分段锁/CAS+synchronized，推荐。
  • Collections.synchronizedMap() — 包装为同步Map。
  • Hashtable — 全表锁，性能差，不推荐。

ConcurrentHashMap 实现原理（JDK 1.8）？
并发容器高频

JDK8：CAS + synchronized + 红黑树

  • 抛弃Segment分段锁，改用Node数组。
  • put：桶为空→CAS插入；桶不为空→synchronized锁住头节点。
  • size：通过baseCount+CounterCell数组计算，避免锁竞争。
  • 扩容：多线程协同扩容(transfer)，每个线程分配一段区间。

💡 JDK7使用Segment分段锁(ReentrantLock)，并发度=Segment数量(默认16)。

HashSet 的实现原理？如何保证元素不重复？
Set源码

HashSet 底层就是 HashMap。

  • add()调用HashMap的put()，元素作为key，value是固定的PRESENT(Object)。
  • 通过HashMap的key唯一性保证元素不重复。
  • 依赖hashCode()和equals()判断重复。

💡 自定义对象存入HashSet必须重写hashCode和equals。

TreeMap 的实现原理？
Map红黑树

  • 有序：按key的自然顺序或自定义Comparator排序。

LinkedHashMap 的实现原理？
MapLRU

继承HashMap，内部维护一个双向链表记录插入顺序。

  • Entry节点多了before和after指针。
  • accessOrder=false：按插入顺序（默认）。
  • accessOrder=true：按访问顺序，可用于实现LRU缓存。

💡 LRU实现：重写removeEldestEntry()方法。

为什么重写 equals 必须重写 hashCode？
基础HashMap

HashMap/HashSet 依赖hashCode定位桶位置。

  • 两个equals相等的对象，hashCode必须相等（规范）。
  • 若只重写equals不重写hashCode，equals相等的两个对象可能hashCode不同→散列到不同桶→HashMap中会被当作不同key。
// 经典bug场景：Person只重写equals不重写hashCode HashMap<Person, String> map = new HashMap<>(); map.put(new Person("张三"), "A"); map.get(new Person("张三")); // null!

CopyOnWriteArrayList 的实现原理？
并发容器COW

写时复制：写操作(add/set/remove)时，先复制一份新数组，在新数组上修改，最后将引用指向新数组。

  • 读：不加锁，直接读原数组，O(1)。
  • 写：加ReentrantLock，复制数组→修改→替换引用。
  • 适用：读多写少场景（如黑名单、监听器列表）。
  • 缺点：写开销大（复制整个数组），内存占用高，数据有延迟（读不到最新写入）。

TreeMap 的底层原理和使用场景？
TreeMap红黑树

TreeMap基于红黑树实现，key必须可比较（实现Comparable或传Comparator）。

  • 有序性：按key的自然顺序或Comparator排序，遍历时有序。

LinkedHashMap 的原理和应用？如何实现LRU？
LRU高频

LinkedHashMap = HashMap + 双向链表，维护插入顺序或访问顺序。

  • accessOrder=false：按插入顺序（默认）。
  • accessOrder=true：按访问顺序，适合LRU缓存。

实现LRU缓存：

class LRUCache<K,V> extends LinkedHashMap<K,V> {
    private final int capacity;
    public LRUCache(int capacity) {
        super(capacity, 0.75f, true); // accessOrder=true
        this.capacity = capacity;
    }
    @Override
    protected boolean removeEldestEntry(Map.Entry e) {
        return size() > capacity;    // 超过容量删除最老元素
    }
}

CopyOnWriteArrayList 的原理和适用场景？
JUCCOW

原理：写时复制。写操作（add/set/remove）时会复制底层数组，在新数组上修改，然后替换旧数组引用。读操作不加锁，直接读旧数组。

  • 优点：读并发无锁，读写分离。
  • 缺点：写操作每次复制整个数组，内存消耗大；数据实时性差（读到旧数据）。

适用场景：读多写极少（如白名单、黑名单、监听器列表），迭代时不需要担心并发修改。

💡 CopyOnWriteArraySet同理，基于CopyOnWriteArrayList实现。

ConcurrentHashMap JDK7 和 JDK8 实现有什么区别？
高频JUC

JDK7（分段锁 Segment）：维护一个Segment数组，每个Segment继承ReentrantLock，锁定单个Segment，默认16段，并发度16。写操作锁Segment，读volatile不加锁。

JDK8（CAS + synchronized）：结构与HashMap一致（Node数组+链表+红黑树）。

  • put：CAS尝试（桶为空时）→失败后synchronized锁住桶头节点。
  • get：不加锁，Node的val和next用volatile保证可见性。
  • 扩容：支持多线程协同迁移（helpTransfer）。

💡 JDK8锁粒度更细（桶级别），扩容支持并发，性能大大优于JDK7。

ConcurrentHashMap 的 put 流程是怎样的？
JUC高频
  1. 计算hash：spread()让高位参与运算，减少冲突。
  2. 空桶CAS：若桶为空，CAS放入Node，成功则结束。
  3. MOVED检测：若hash==MOVED(-1)，说明正在扩容，帮助迁移。
  4. synchronized加锁：锁住桶头节点。
  5. 链表/红黑树插入：遍历链表equals判断，覆盖或尾插；红黑树putTreeVal。
  6. 检查树化：链表长度≥8 且总容量≥64 时转红黑树。
  7. addCount：CAS+CounterCell方式更新size，检查是否需要扩容。

ConcurrentHashMap 的 size() 如何计算？
JUC深入

使用分段计数避免竞争：

  • baseCount：基础计数，CAS更新。
  • CounterCell数组：CAS失败时，在线程probe对应的CounterCell中累加（类似LongAdder）。

size()计算：sum = baseCount + 所有CounterCell.value。不是精确值（并发中可能略小），但大致准确。

mappingCount()：返回long类型（size()返回int，最大值Integer.MAX_VALUE）。推荐用mappingCount()。

Arrays.asList() 有哪些坑？
Arrays高频
  • 不可增删：返回的是Arrays内部类ArrayList（非java.util.ArrayList），固定大小，add/remove抛UnsupportedOperationException。
  • 视图关联：修改原数组会影响List（反之亦然），因为底层共用数组。
  • 基本类型陷阱：Arrays.asList(new int[]{1,2}) 结果是List<int[]>而非List<Integer>！应用Arrays.asList(1,2)或Integer数组。
int[] arr = {1, 2, 3};
List list = Arrays.asList(arr);
System.out.println(list.size()); // 1！只有整个数组一个元素
// 正确做法：List<Integer> list = Arrays.asList(1, 2, 3);

fail-fast 和 fail-safe 机制是什么？
迭代器高频

fail-fast（快速失败）：

  • 迭代时检测modCount，若发现其他线程修改了集合，立即抛ConcurrentModificationException。
  • 典型：ArrayList、HashMap 的Iterator。
  • 单线程中迭代时修改也会触发！

fail-safe（安全失败）：

  • 迭代时操作集合的快照，不影响原集合。
  • 典型：CopyOnWriteArrayList、ConcurrentHashMap（弱一致性迭代）。
  • 不抛异常，但可能读取到过期数据。

💡 如何避免fail-fast？使用Iterator.remove()而非list.remove()；或用CopyOnWriteArrayList。

HashSet 底层如何实现？为什么能保证不重复？
SetHashSet

HashSet底层就是HashMap，元素作为HashMap的key，value是一个固定的PRESENT对象。

去重逻辑：

  • add(E e) → map.put(e, PRESENT)==null。
  • 利用HashMap的key唯一性：hashCode不同→直接放入；hashCode相同→equals比较→true则覆盖（不增加），false则链表/红黑树插入。

💡 自定义对象放入HashSet必须重写hashCode()和equals()，否则无法正确去重。

ArrayDeque 和 LinkedList 作为队列有什么区别？
QueueDeque

ArrayDeque：循环数组实现的双端队列。

  • 不能存null值。
  • 容量动态扩展（翻倍），O(1)均摊。
  • 无内存节点开销，比LinkedList省内存。

LinkedList：双向链表实现，也实现了Deque接口。

  • 允许null。
  • 每个元素有Node开销（prev/next引用）。

💡 作队列/栈时推荐ArrayDeque（性能更好）。Vector/Stack已过时，用ArrayDeque替代栈，用ArrayDeque或LinkedList替代队列。

PriorityQueue 的底层原理？
堆PriorityQueue

PriorityQueue基于二叉小顶堆（数组实现），默认最小堆。

  • 入队：尾部追加→上浮(siftUp)，O(log n)。
  • 出队：取堆顶→尾部元素替换堆顶→下沉(siftDown)，O(log n)。
  • 查堆顶：peek() → O(1)。
  • 不允许null元素。
  • 无序遍历（堆序不等于遍历序），只有出队按优先级。

自定义优先级：构造时传入Comparator，可实现大顶堆。

WeakHashMap 和 IdentityHashMap 是什么？
Map特殊

WeakHashMap：

  • Key为弱引用，只有WeakReference指向key时，GC就会回收。
  • Entry在每次操作时自动清除已被回收的key。
  • 适用场景：缓存，不希望影响GC。

IdentityHashMap：

  • 用==而非equals()比较key（比较引用地址而非内容）。
  • 允许key重复（不同地址的对象可以是不同key）。
  • 底层用Object[]数组，相邻位置存key和value（非链表）。
  • 适用场景：序列化框架、需要区分对象实例的场景。

BlockingQueue 有哪些实现？各自特点？
BlockingQueueJUC

BlockingQueue是线程安全的阻塞队列，常用于生产者-消费者模式：

实现特点
ArrayBlockingQueue有界数组，一把锁两个Condition，必须指定容量
LinkedBlockingQueue可选有界（默认Integer.MAX_VALUE），两把锁(putLock/takeLock)
PriorityBlockingQueue无界，堆排序，take时阻塞等元素
SynchronousQueue容量0，必须配对生产/消费线程，CachedThreadPool使用
DelayQueue延迟队列，元素需实现Delayed接口
LinkedTransferQueuetransfer()方法，生产者可等待消费者接收

💡 LinkedBlockingQueue默认无界可能OOM，生产环境建议指定容量。
