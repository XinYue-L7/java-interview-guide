JVM 内存区域是如何划分的？
内存模型高频

线程私有：

  • 程序计数器：记录当前线程执行字节码的行号，唯一无OOM的区域。
  • 虚拟机栈：存储栈帧(局部变量表、操作数栈等)，方法调用入栈/返回出栈。StackOverflowError / OOM。
  • 本地方法栈：为Native方法服务，HotSpot中与虚拟机栈合二为一。

线程共享：

  • 堆：存放对象实例，GC主要区域。OOM。
  • 方法区/元空间(JDK8+)：存储类信息、常量、静态变量。OOM。
  • 运行时常量池：方法区的一部分，存放编译期生成的字面量和符号引用。

💡 JDK8用元空间(Metaspace)替代永久代(PermGen)，使用本地内存，不再有-XX:MaxPermSize。

2
堆内存的结构是怎样的？
堆分代

分代模型（JDK8）：

  • 新生代(Young Gen)：1/3堆空间
    • Eden区(8/10) + Survivor0(1/10) + Survivor1(1/10)
    • 对象先在Eden分配，Minor GC后存活→S0→S1，每GC一次年龄+1
  • 老年代(Old Gen)：2/3堆空间，年龄达到15(可配置)或大对象直接进入

💡 字符串常量池在JDK7后移到堆中。

3
对象创建的完整流程是怎样的？
对象内存分配
  1. 类加载检查：检查类是否已加载→未加载则先加载。
  2. 分配内存：指针碰撞(Bump Pointer)或空闲列表(Free List)，取决于GC是否有压缩。
  3. 并发安全：CAS+失败重试 或 TLAB(线程本地分配缓冲)。
  4. 初始化零值：内存空间初始化为零。
  5. 设置对象头：Mark Word + 类型指针。
  6. 执行init：构造方法。

如何判断对象是否已死？（GC Roots）
GC高频

两种算法：

  1. 引用计数法：有对象引用+1，引用失效-1。无法解决循环引用，Java不用。
  2. 可达性分析：从GC Roots出发，不可达的对象判定为可回收。

GC Roots 包括：

  • 虚拟机栈中引用的对象
  • 方法区静态属性引用的对象
  • 方法区常量引用的对象
  • 本地方法栈中JNI引用的对象
  • 被同步锁(synchronized)持有的对象

强引用、软引用、弱引用、虚引用的区别？
引用GC
类型回收时机用途
强引用(Strong)永不回收普通对象引用
软引用(Soft)OOM前回收缓存、图片缓存
弱引用(Weak)下次GC即回收WeakHashMap、ThreadLocal
虚引用(Phantom)随时回收，get()始终返回null对象回收跟踪

💡 软引用适合实现内存敏感缓存；弱引用用于ThreadLocal防止内存泄漏。

垃圾回收算法有哪些？
GC算法高频
  • 标记-清除(Mark-Sweep)：标记存活→清除未标记。简单但产生碎片。
  • 标记-复制(Mark-Copy)：标记存活→复制到新空间→清理原空间。无碎片但浪费一半内存。新生代使用。
  • 标记-整理(Mark-Compact)：标记存活→移动到一端→清理边界外。无碎片但耗时。老年代使用。
  • 分代收集：新生代用复制，老年代用标记-清除/整理。

Minor GC、Major GC、Full GC 的区别？
GC基础
  • Minor GC(Young GC)：仅回收新生代，频繁，速度快(复制算法)。
  • Major GC：回收老年代，通常伴随Minor GC，比Minor GC慢10倍+。CMS中特指老年代GC。
  • Full GC：回收整个堆+方法区，最慢，STW最长。应尽量避免。

Full GC触发条件：老年代满、元空间满、System.gc()、大对象分配失败。

类加载的过程是怎样的？双亲委派模型是什么？
类加载高频

类加载过程(5步)：加载 验证 准备 解析 初始化

  • 加载：获取二进制字节流→生成Class对象。
  • 验证：确保字节码符合JVM规范。
  • 准备：为静态变量分配内存并赋零值。
  • 解析：符号引用→直接引用。
  • 初始化：执行clinit方法，静态变量赋值+静态代码块。

双亲委派模型：

类加载请求先委派父类加载器，父类加载不了才自己加载。

层级：Bootstrap Extension Application 自定义加载器

💡 好处：避免重复加载、防止核心API被篡改。

如何排查 OOM 问题？
OOM实战
  1. 配置JVM参数在OOM时自动dump：-XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/path
  2. 分析dump文件：使用MAT/JProfiler/VisualVM
  3. 查看大对象：Histogram查看占用最多的类
  4. 分析引用链：从GC Root到对象的引用路径
  5. 常见原因：内存泄漏(集合未清理)、大对象、死循环创建对象、元空间溢出(动态代理/反射过多)

对象的访问定位有哪两种方式？
对象底层
  • 句柄访问：栈→句柄池(两个指针：对象实例指针+类型数据指针)→堆/方法区。对象移动只需改句柄。
  • 直接指针(HotSpot)：栈→直接指向堆中对象实例，对象头中有类型指针指向方法区。访问快，但对象移动需改引用。

💡 HotSpot使用直接指针方式。

14
什么情况下会出现 StackOverflowError？
异常栈
  • 无限递归：方法不断调用自身，栈帧不断入栈超过栈深度。
  • 大量局部变量：每个栈帧中的局部变量表太大。

解决方法：

  • 检查递归终止条件
  • 增大栈大小：-Xss参数
  • 改用迭代

💡 与OOM的区别：StackOverflow是栈深度超限，OOM是堆/元空间内存不足。

GC Roots 有哪些？
GC高频

GC Roots是可达性分析算法的起点：

  • 虚拟机栈中引用的对象（局部变量表）。
  • 方法区静态属性引用的对象。
  • 方法区常量池引用的对象。
  • 本地方法栈中JNI引用的对象。
  • Java虚拟机内部的引用（Class对象、异常对象等）。
  • 所有被synchronized持有的对象。
  • 内部引用（如StringTable、ClassLoader等）。

引用GC
类型回收时机用途
强引用永不回收new对象
软引用(SoftReference)内存不足时回收缓存、图片缓存

17
CMS 收集器的流程和优缺点？
CMSGC

CMS（Concurrent Mark Sweep）是老年代并发收集器，目标：最短停顿时间。

流程4步：

  1. 初始标记(STW)：标记GC Roots直接关联对象，快。
  2. 并发标记：GC Roots Tracing，耗时长但并发。
  3. 重新标记(STW)：修正并发标记变化，比初始标记长。
  4. 并发清除：清理垃圾，并发。

缺点：产生浮动垃圾（并发标记中产生的新垃圾）、标记-清除算法有碎片、对CPU敏感、预留空间不足时退化为Serial Old。

18
G1 收集器的核心特点和原理？
G1高频

G1（Garbage First）是JDK9+默认收集器，面向服务端大堆内存。

设计思想：将堆分为2048个Region，各Region可动态扮演Eden、Survivor、Old、Humongous。

混合回收(Mixed GC)：不光回收新生代，还回收部分老年代Region（垃圾最多的Region优先→Garbage First）。

核心特点：

  • 可预测停顿：通过-XX:MaxGCPauseMillis设置目标。
  • 标记-整理+复制算法，无内存碎片。
  • Remembered Set解决跨Region引用。
  • SATB(Snapshot-At-The-Beginning)解决并发标记问题。
19
ZGC 和 Shenandoah 的特点？
ZGC低延迟

ZGC：JDK11引入，JDK15生产可用。目标：亚毫秒级停顿，支持TB级堆。

  • 基于染色指针（Colored Pointers）和读屏障。
  • 并发标记、并发整理（Compacting时短暂停顿）。
  • 停顿时间< 1ms，且不随堆大小增加。

Shenandoah：JDK12引入，类似G1但并发整理（移动对象与用户线程并发）。

  • 用Brooks Pointer转发指针实现并发整理。
  • 回收阶段几乎全并发。
20
类加载器的双亲委派模型是什么？为什么破坏它？
类加载高频

三层类加载器：

  • Bootstrap ClassLoader（C++，加载rt.jar）Extension ClassLoader（加载ext）Application ClassLoader（加载classpath）。

双亲委派流程：加载→先委托父加载器→父找不到才自己加载。保证核心类安全（如自定义String不会覆盖核心String）。

破坏场景：

  • JDBC：Bootstrap加载的类需调用SPI实现类（Application加载），通过线程上下文类加载器绕开。
  • Tomcat：WebApp类加载器优先加载应用自己的类，打破委派。
  • OSGi：网状类加载器结构。
21
Tomcat 为什么要打破双亲委派？
类加载Tomcat

Tomcat的WebappClassLoader优先加载应用自己的类，原因：

  1. 隔离性：不同Web应用各自类加载器，同名类互不干扰。
  2. 灵活性：应用可加载自己的Spring版本覆盖Tomcat提供的。
  3. 热部署：单独卸载某个WebappClassLoader即可重载应用。

加载顺序：先查本地缓存→避免JVM核心类→先自己加载→自己找不到才委托父加载器。

22
对象分配内存的过程是怎样的？
内存分配高频

优先TLAB（线程本地分配缓冲区）：

  1. 先在栈上分配（逃逸分析+标量替换），分配在栈上。
  2. 栈上不行→尝试TLAB（Eden区的线程私有区域），CAS分配。
  3. TLAB不够→Eden区CAS分配。
  4. Eden不够→触发Minor GC。
  5. 大对象（如长数组）→直接进老年代。
  6. 年龄够了→晋升老年代。

栈上分配条件：逃逸分析判定对象不会逃出方法+可以被标量替换。-XX:+DoEscapeAnalysis默认开启。

23
对象晋升老年代的几种情况？
GC晋升
  1. 年龄达标：默认15岁（-XX:MaxTenuringThreshold）。
  2. 动态年龄判断：Survivor区中同龄对象总大小 > Survivor空间的50%→直接晋升。
  3. 大对象：超过-XX:PretenureSizeThreshold直接进老年代。
  4. 空间担保：Minor GC时Survivor放不下→通过空间分配担保进老年代。

OOM 有哪些类型？如何排查？
OOM高频

常见OOM类型：

  • Java heap space：堆溢出，大对象或内存泄漏。
  • GC overhead limit exceeded：GC时间超过98%但只回收<2%堆。
  • Metaspace：加载过多类或类加载器泄漏。
  • Direct buffer memory：堆外内存溢出(NIO)。
  • unable to create new native thread：线程数达到上限。

排查步骤：

  1. 留现场：-XX:+HeapDumpOnOutOfMemoryError
  2. 分析dump：MAT/JProfiler查看大对象和GC Root链。
  3. 查日志：GC日志分析频率和效果。
  4. 监控：jstat查看各区域使用情况。

CPU 飙高如何排查？（JVM层面）
排查高频
  1. 找进程：top 找到高CPU的Java进程PID。
  2. 找线程：top -Hp PID 找到具体线程TID。
  3. 转十六进制：printf '%x\n' TID
  4. 查栈：jstack PID | grep 十六进制tid -A30 定位到具体代码行。
  5. 分析原因：死循环、频繁GC、大量计算、锁竞争。

💡 也可用Arthas：thread -n 3直接看最忙的3个线程。

28
full GC 频繁如何排查和优化？
调优高频

排查方向：

  1. 内存泄漏：jmap dump后MAT分析大对象引用链。
  2. 堆太小：增大-Xmx。
  3. 晋升过快：增大新生代(Xmn)或调整晋升阈值。
  4. System.gc()：使用-XX:+DisableExplicitGC禁用手动GC。
  5. 元空间不足：增大-XX:MaxMetaspaceSize。
  6. 大对象多：调整PretenureSizeThreshold。

优化手段：扩大堆内存、换G1收集器、调整Region大小、减少对象创建。

29
类的生命周期（加载过程）是怎样的？
类加载高频

类从加载到卸载共7个阶段：

  1. 加载：通过全限定名获取二进制字节流→方法区生成Class对象。
  2. 验证：文件格式、元数据、字节码、符号引用验证。
  3. 准备：为static变量分配内存并赋零值（final static赋实际值）。
  4. 解析：符号引用→直接引用（可延迟到初始化后）。
  5. 初始化：执行类构造器<clinit>()（static块+static变量赋值）。
  6. 使用。
  7. 卸载。

💡 验证-准备-解析统称链接阶段。

什么情况下会触发类初始化？
类加载

主动引用（触发初始化）：

  • new、getstatic、putstatic、invokestatic指令。
  • 反射：Class.forName()（initialize=true）。
  • 子类初始化先触发父类初始化。
  • 启动类（main方法所在类）。
  • JDK7+ MethodHandle REF_getStatic等。

被动引用（不触发初始化）：

  • 子类引用父类静态字段（只初始化父类）。
  • 数组定义：MyClass[] arr = new MyClass[10]。
  • 引用常量（编译期存入常量池）。
31
Tlab 是什么？有什么作用？
TLAB内存

TLAB（Thread Local Allocation Buffer）是Eden区中为每个线程预留的一小块内存区域。

作用：

  • 线程分配对象时优先在自己的TLAB中分配，无需加锁（CAS仅在线程创建TLAB时）。
  • 极大提升对象分配效率，避免多线程竞争。

相关参数：

  • -XX:+UseTLAB — 默认开启。
  • -XX:TLABSize — TLAB大小。
  • -XX:+PrintTLAB — 打印TLAB使用情况。
32
逃逸分析是什么？有什么作用？
逃逸分析优化

逃逸分析：分析对象动态作用域，判断对象是否逃逸出方法或线程。

优化手段：

  • 栈上分配：不逃逸的对象直接在栈帧中分配，随方法结束自动销毁（减少GC）。
  • 标量替换：将对象拆解为基本类型成员变量，分别分配。
  • 锁消除：检测到锁只被一个线程使用，消除同步代码。

JDK6u23+默认开启逃逸分析。可通过-XX:-DoEscapeAnalysis关闭。

33
JVM 中哪些区域会发生 OOM？
OOM内存

JVM几乎每个内存区域都可能OOM：

  • 堆：对象太多→Java heap space。
  • 虚拟机栈：递归过深→StackOverflowError；线程太多→unable to create new native thread。
  • 方法区/元空间：类太多、动态代理→Metaspace OOM。
  • 直接内存：NIO分配过大→Direct buffer memory。
  • GC overhead：频繁GC但仍内存不足。

💡 元空间默认无上限（受限于物理内存），生产环境建议设置-XX:MaxMetaspaceSize。

34
什么是直接内存？和堆内存有什么区别？
直接内存NIO

直接内存是堆外内存，不属于JVM运行时数据区，通过ByteBuffer.allocateDirect()或Unsafe.allocateMemory()分配。

特点：

  • 减少Java堆和Native堆之间的数据拷贝，零拷贝→NIO性能高。
  • 不受-Xmx限制，但受物理内存限制。
  • GC不直接管理，需手动释放或用Cleaner机制。
  • 分配和回收成本高（系统调用）。

用-XX:MaxDirectMemorySize限制直接内存大小。

35
JVM 如何判断一个类是否可以被卸载？
类卸载

类卸载需要同时满足3个条件：

  1. 该类的所有实例已被回收。
  2. 加载该类的ClassLoader已被回收。
  3. 该类的Class对象没有被引用。

Bootstrap加载的核心类不会被卸载。通常只在动态代理、JSP热部署、OSGi等场景下才可能卸载类。

💡 -Xnoclassgc可禁止类卸载。
