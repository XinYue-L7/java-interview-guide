JDK、JRE、JVM 的区别与联系？
JVM基础 基础概念 高频

JDK（Java Development Kit） — Java 开发工具包，包含 JRE + 开发工具（javac、java、jar、javadoc 等），面向开发者。

JRE（Java Runtime Environment） — Java 运行环境，包含 JVM + 核心类库，面向用户。

JVM（Java Virtual Machine） — Java 虚拟机，负责执行字节码，是 Java 跨平台的核心。

对比维度JDKJREJVM
包含关系最全面JVM + 类库最底层
用途开发 + 运行仅运行执行字节码
包含 javac✅❌❌

一句话总结：JDK ⊃ JRE ⊃ JVM

== 和 equals() 的区别？
基础语法 高频

== 比较的是两个对象的内存地址（引用是否相同）；

equals() 默认也是比较地址，但 String、Integer 等包装类已重写了该方法，比较的是内容是否相同。

// 示例 String a = new String("hello"); String b = new String("hello"); System.out.println(a == b); // false — 不同对象 System.out.println(a.equals(b)); // true — 内容相同

接口（interface）和抽象类（abstract class）的区别？
面向对象 设计模式 高频
  • 实现方式：一个类可以实现多个接口，但只能继承一个抽象类。
  • 构造方法：接口不能有构造方法；抽象类可以有。
  • 成员变量：接口中的变量默认是 public static final；抽象类可以有普通成员变量。
  • 方法：Java 8+ 接口可以有 default / static 方法；抽象类可以有抽象方法 + 具体方法。
  • 设计理念：接口定义行为规范（can-do）；抽象类体现is-a 关系，代码复用。

💡 一般优先使用接口，需要共享代码时用抽象类。

final、finally、finalize 的区别？
关键字 异常处理 经典

final：修饰类 → 不可被继承；修饰方法 → 不可被重写；修饰变量 → 基本类型值不可变，引用类型引用不可变（但对象内容可变）。

finally：异常处理中 try-catch 后的代码块，无论是否异常都会执行（除 System.exit(0) 外）。

finalize()：Object 类的方法，GC 回收对象前调用（已废弃 JDK 9+），不推荐使用，因为调用时机不确定。

HashMap 的底层实现原理？（JDK 1.8）
集合框架 数据结构 高频

底层：数组 + 链表 + 红黑树

  1. 存储结构：Node<K,V>[] table 数组，每个位置是一个桶。
  2. 哈希计算：(n-1) & hash 定位桶位置（n 为数组长度）。
  3. 冲突解决：链地址法 — 同一桶内的元素用链表串联。
  4. 链表 → 红黑树：链表长度 ≥ 8 且数组长度 ≥ 64 时，链表转为红黑树，提高查询效率到 O(log n)。
  5. 红黑树 → 链表：元素数量 ≤ 6 时退化回链表。
  6. 扩容：默认容量 16，负载因子 0.75，超过阈值时扩容为原来的 2 倍，rehash 重新分配位置。

💡 JDK 1.7 vs 1.8：1.7 只有数组+链表，头插法导致死循环；1.8 引入红黑树，尾插法解决死循环。

创建线程有哪几种方式？
多线程 并发基础 高频

4 种方式：

  1. 继承 Thread 类 — 重写 run()，调用 start() 启动。
  2. 实现 Runnable 接口 — 更灵活，可继承其他类，避免单继承限制。
  3. 实现 Callable 接口 — 有返回值 + 可抛异常，配合 FutureTask 使用。
  4. 线程池（ExecutorService） — 实际开发首选，复用线程、管理生命周期。
// 推荐：线程池方式 ExecutorService pool = Executors.newFixedThreadPool(5); pool.submit(() -> System.out.println("线程执行中...")); pool.shutdown();

💡 实际开发中严禁直接 new Thread()，必须使用线程池管理。

Java 中的异常体系是怎样的？
异常处理 基础语法 经典

Java 异常分为两大类：

  • Error：JVM 级别的严重错误（OutOfMemoryError、StackOverflowError），不处理。
  • Exception：程序可处理的异常，分两种：
    • Checked Exception（编译时异常）：必须 try-catch 或 throws，如 IOException、SQLException。
    • Unchecked Exception（运行时异常）：RuntimeException 及其子类，如 NullPointerException、IndexOutOfBoundsException、IllegalArgumentException，编译期不强制处理。

💡 try-catch-finally 执行顺序：有 return 时，finally 在 return 之前执行（但 finally 中最好不要写 return，会覆盖 catch 中的返回值）。
