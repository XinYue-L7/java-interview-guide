JDK、JRE、JVM 的区别与联系？
JVM基础高频

JDK — Java开发工具包，包含JRE + 开发工具(javac/java/jar/javadoc等)，面向开发者。

接口（interface）和抽象类（abstract class）的区别？
面向对象高频
  • 多实现：一个类可实现多个接口，但只能继承一个抽象类。
  • 构造方法：接口不能有；抽象类可以有。
  • 成员变量：接口中默认public static final；抽象类可有普通变量。
  • 方法：Java8+接口可有default/static方法；抽象类可有抽象+具体方法。
  • 设计理念：接口定义行为规范(can-do)；抽象类体现代码复用(is-a)。

final、finally、finalize 的区别？
关键字经典

final：修饰类→不可继承；方法→不可重写；变量→基本类型值不可变/引用类型引用不可变。

finally：try-catch后必执行的代码块(除System.exit(0)外)。

finalize()：Object类方法，GC回收前调用，JDK9已废弃，不推荐使用。

Java 是值传递还是引用传递？
基础语法高频

Java只有值传递。

  • 基本类型：传递值的副本，不改变原值。
  • 引用类型：传递引用的副本（地址值的拷贝），可通过该引用修改对象内容，但无法让原引用指向新对象。

本质：传递的都是栈中存储的值（基本类型的值 or 引用的地址值），都是值的副本。

深拷贝和浅拷贝的区别？
基础语法Cloneable

浅拷贝：只拷贝对象本身，引用类型字段仍指向原对象。

深拷贝：完全拷贝，包括引用类型字段指向的对象也复制一份。

实现方式：

  • 浅拷贝：实现Cloneable，重写clone()。
  • 深拷贝：序列化反序列化、手动递归拷贝、使用工具类(如BeanUtils)。

static 关键字的作用？
关键字内存模型

static修饰的内容属于类而非实例，在类加载时初始化。

  • 静态变量：类级别共享，存储在方法区/元空间。
  • 静态方法：不能访问非静态成员，不能使用this。
  • 静态代码块：类加载时执行一次，用于初始化静态变量。
  • 静态内部类：不依赖外部类实例。

💡 执行顺序：父类静态块 子类静态块 父类代码块/构造 子类代码块/构造。

Java 中 IO 流分为哪几种？
IO流基础
  • 按流向：输入流(InputStream/Reader)、输出流(OutputStream/Writer)。
  • 按单位：字节流(Stream后缀)、字符流(Reader/Writer后缀)。
  • 按功能：节点流(直接操作数据源)、处理流(装饰器模式，如BufferedInputStream)。

BIO/NIO/AIO：

  • BIO：同步阻塞，一请求一线程。
  • NIO：同步非阻塞，Channel+Buffer+Selector，多路复用。
  • AIO：异步非阻塞，回调机制。

Java 是值传递还是引用传递？
基础语法高频

Java 只有值传递，没有引用传递。

  • 基本类型：传递值的副本，修改不影响原变量。
  • 引用类型：传递的是引用地址的副本，形参和实参指向同一对象，修改对象内容会生效，但修改引用本身（如指向新对象）不生效。

💡 容易误解：能修改对象内容≠引用传递，这是共享对象引用而非传递引用本身。

public void swap(Integer a, Integer b) { Integer t=a; a=b; b=t; } // 不生效
public void modify(User u) { u.setName("new"); }            // 生效

String 常量池（String Pool）是什么？
StringJVM

String常量池是JVM在堆内存中维护的一个字符串缓存区域（JDK7+ 移到堆中）。

  • 字面量赋值：String s="abc" 先去常量池找，有则复用，无则创建。
  • new String("abc")：堆中创建对象，再检查常量池（无则创建），共创建1-2个对象。
  • intern()：手动将字符串加入常量池，返回池中引用。
  • + 拼接：字面量拼接→编译期优化；变量拼接→StringBuilder→new String。
String s1="a"+"b";      // 编译优化→"ab"，常量池
String s2=new String("a")+new String("b"); // 堆中新建
String s3=s2.intern(); // 将s2放入常量池，返回池中引用
System.out.println(s1==s3); // true

try-catch-finally 的执行顺序？finally 一定会执行吗？
异常处理高频

执行顺序：try (异常→catch) finally (正常后续代码)。

finally不执行的情况：

  • try之前System.exit(0)退出JVM。
  • 守护线程退出时finally可能不执行。
  • try/catch中执行System.exit()。
  • JVM崩溃或断电等不可恢复错误。

return 与 finally：

  • try有return值时，先计算return表达式，再执行finally，最后返回。
  • finally中有return会覆盖try的return！
public int test() { try { return 1; } finally { return 2; } } // 返回2！

什么是泛型擦除？泛型的上下界是什么？
泛型高频

泛型擦除：编译后泛型信息被擦除，List<String>和List<Integer>在运行时都是List。

  • 上界 extends：T extends Number 擦除后上界为Number。
  • 下界 super：T super Integer 擦除后下界为Integer（PECS原则：Producer Extends, Consumer Super）。

注意事项：

  • 不能new泛型数组T[]。
  • 不能用基本类型作泛型参数。
  • 不能instanceof泛型类型。
  • 静态方法中不能用类的泛型参数。

Java 中有哪几种内部类？各自特点？
内部类基础
  • 成员内部类：作为外部类成员，可访问外部类所有成员。创建需外部类实例：outer.new Inner()。
  • 静态内部类：static修饰，不依赖外部类实例，只能访问外部类静态成员。
  • 局部内部类：定义在方法中，仅方法内可见，访问的局部变量需final。
  • 匿名内部类：无类名，一次性使用，常用于接口/抽象类实例化。必须实现所有抽象方法。

💡 内部类编译后生成独立class文件：Outer$Inner.class。匿名内部类生成Outer$1.class。

反射机制原理和应用场景？
反射高频

原理：类加载时JVM在方法区生成Class对象，反射通过Class对象获取类信息（构造器、方法、字段），并在运行时动态调用。

获取Class的方式：

  • Class.forName("全限定名") — 静态方法，会初始化类。
  • 对象.getClass() — 实例方法。
  • 类名.class — 不会触发类初始化。

应用场景：Spring IOC、动态代理、JDBC驱动加载、注解解析、框架配置注入。

动态代理有哪几种实现方式？
代理AOP

1. JDK动态代理（接口代理）：

  • 基于反射，要求目标类必须实现接口。
  • 核心类：Proxy.newProxyInstance() + InvocationHandler。
  • 运行时动态生成代理类$Proxy0。

2. CGLIB动态代理（子类代理）：

  • 基于ASM字节码生成，通过继承目标类生成子类。
  • 不需要接口，但目标类不能是final。
  • 核心类：Enhancer + MethodInterceptor。

Spring选择策略：有接口→JDK代理；无接口→CGLIB。Spring Boot 2.x 默认使用CGLIB。

Integer 的缓存机制是怎样的？
包装类高频

Integer内部维护了IntegerCache，默认缓存-128 ~ 127之间的Integer对象。

  • 自动装箱Integer i=100 从缓存取，返回同一对象。
  • new Integer(100) 强制创建新对象，不在缓存中。
  • 最大值可通过-XX:AutoBoxCacheMax=调整。
Integer a=100, b=100;   System.out.println(a==b); // true (缓存)
Integer c=200, d=200;   System.out.println(c==d); // false (超出缓存)

💡 同样有缓存的包装类：Byte/Short/Long(-128~127)、Character(0~127)、Boolean(TRUE/FALSE)。Double/Float没有缓存。

自动装箱和自动拆箱的原理及注意事项？
包装类语法糖
  • 自动装箱：基本类型→包装类，编译器调用Integer.valueOf(int)。
  • 自动拆箱：包装类→基本类型，编译器调用Integer.intValue()。

注意事项（坑）：

  • NPE风险：包装类为null时自动拆箱抛NullPointerException。
  • == 比较：包装类==是比较地址，应使用equals()。
  • 三目运算符：flag ? 1 : new Integer(2) 结果自动拆箱为int。
  • 性能开销：循环中大量自动装箱/拆箱产生大量临时对象，应避免。

BigDecimal 使用有哪些坑？如何正确比较？
精度高频

常见坑：

  • 构造方式：new BigDecimal(0.1) 不精确！浮点数本身不精确。应使用new BigDecimal("0.1") 或 BigDecimal.valueOf(0.1)。
  • equals比较：BigDecimal(1.0)!=BigDecimal(1.00)，因为scale不同。应使用compareTo()。
  • 除法：必须指定精度，否则无限小数抛异常：divide(bd, 2, RoundingMode.HALF_UP)。
  • 不可变性：所有运算返回新对象，原对象不变。
BigDecimal a=new BigDecimal("1.0"), b=new BigDecimal("1.00");
System.out.println(a.equals(b));    // false
System.out.println(a.compareTo(b)); // 0 (相等)

this 和 super 关键字有哪些使用场景？
关键字基础

this：

  • 区分成员变量和局部变量：this.name = name。
  • 调用本类构造方法：this()，必须放构造器首行。
  • 返回当前对象：return this（链式调用）。
  • 作为参数传递：method(this)。

super：

  • 访问父类成员：super.name。
  • 调用父类构造方法：super()，必须放构造器首行（不写时默认调用无参）。
  • 调用父类方法：super.method()。

💡 this()和super()不能同时出现，且必须放在构造器第一行。

Lambda 表达式的原理是什么？有什么限制？
Java8Lambda

原理：Lambda不是匿名内部类的语法糖，编译后不会生成新的class文件，而是通过invokedynamic指令在运行时动态生成方法句柄。JVM在首次调用时通过LambdaMetafactory生成一个函数式接口的实现类。

相比匿名内部类：

  • 不会生成额外的class文件，减少Jar包大小。
  • 不创建新对象（无捕获时），性能更好。
  • this指向外层类而非匿名内部类自身。

限制：只能用于函数式接口；不能修改外部局部变量（需effectively final）；不能抛出受检异常（除非接口声明）。

Stream 流的中间操作和终端操作有哪些？
Java8Stream

中间操作（惰性）：返回Stream，不触发计算。

  • 筛选：filter()、distinct()、limit()、skip()。
  • 映射：map()、flatMap()。
  • 排序：sorted()。

Optional 类的主要用法是什么？
Java8Optional

Optional是容器对象，解决null判断问题，避免NPE。

创建：

  • Optional.of(T) — 值不能为null。
  • Optional.ofNullable(T) — 值可为null。
  • Optional.empty() — 创建空Optional。

使用：

  • isPresent() — 是否有值。
  • ifPresent(Consumer) — 有值时执行。
  • orElse(T) — 为空返回默认值（注意：orElse一定会执行参数！）。
  • orElseGet(Supplier) — 为空时懒加载默认值（推荐）。
  • orElseThrow() — 为空抛异常。
  • map()/flatMap() — 值转换。
  • filter() — 条件过滤。

💡 不要用Optional作字段类型或方法参数，主要用于返回值。

Java 中如何实现不可变类？String 为什么被设计为不可变？
不可变类String

实现不可变类步骤：

  1. 类声明为final，防止继承。
  2. 所有字段private final。
  3. 不提供setter方法。
  4. 构造方法中防御性拷贝（引用类型字段）。
  5. getter返回引用类型时返回拷贝而非原引用。

String不可变的原因：

  • 字符串常量池：可共享，节省内存。
  • 安全性：避免被篡改（如类加载、网络连接参数）。
  • 线程安全：天生不可变→多线程安全。
  • Hash缓存：hashCode可缓存，HashMap key性能高。

Java 的 SPI 机制是什么？
SPI设计模式

SPI（Service Provider Interface）是Java内置的服务发现机制，用于解耦接口与实现。

核心思想：在META-INF/services/下创建以接口全限定名命名的文件，内容为实现类全限定名。ServiceLoader自动加载所有实现。

典型应用：JDBC驱动（java.sql.Driver）、SLF4J日志门面、Spring Boot自动配置（spring.factories）、Dubbo扩展点加载。

缺点：会加载所有实现类，无法按需加载；不支持懒加载；ServiceLoader不是线程安全的。

  3. clone()：需实现Cloneable接口，浅拷贝。
  4. 反序列化：从文件/网络流中ObjectInputStream.readObject()。
  5. Unsafe类：Unsafe.allocateInstance()，只分配内存不调用构造器。

💡 反序列化和Unsafe创建对象时不调用构造方法，可能导致字段未初始化。

Error 和 Exception 的区别？常见有哪些？
异常基础

Error：程序无法处理的严重错误，JVM层面问题，不要求捕获。

  • OutOfMemoryError、StackOverflowError、NoClassDefFoundError。

Exception：程序可以处理的异常。

  • 检查异常(Checked)：编译时强制处理，如IOException、SQLException、ClassNotFoundException。
  • 运行时异常(Runtime)：可选处理，如NullPointerException、ArrayIndexOutOfBoundsException、IllegalArgumentException、ClassCastException。

💡 try-catch处理不了Error（如OOM），应避免而非捕获。

switch 支持哪些数据类型？原理是什么？
基础语法switch

switch支持的参数类型：

  • 基本类型：byte、short、char、int（以及对应的包装类）。
  • JDK 7+：String。
  • JDK 14+：增强switch表达式，支持case ->语法和yield返回值。
  • 枚举类型：enum。

String实现原理：编译后分为两个switch——先switch(hashCode)，case匹配字符串哈希值；哈希冲突分支再switch(equals)精确匹配。即先hashCode再equals。

transient、volatile、synchronized 关键字的区别？
关键字综合
关键字作用场景
transient修饰字段，序列化时忽略该字段敏感信息不序列化、不可序列化对象
volatile保证变量可见性和禁止指令重排序，不保证原子性状态标志位、DCL单例
synchronized保证原子性、可见性、有序性（加锁）多线程同步、线程安全

💡 关键区别：transient是序列化关键字，volatile是轻量级同步（仅可见性），synchronized是重量级同步（原子性+可见性+有序性）。volatile不保证原子性，i++操作仍需synchronized或AtomicInteger。
