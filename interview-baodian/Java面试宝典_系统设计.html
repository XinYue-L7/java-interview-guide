如何设计一个秒杀系统？
系统设计实战
  1. 前端：静态化+CDN，按钮防重复点击。
  2. 网关：限流(Sentinel/令牌桶)，恶意请求拦截。
  3. 业务：Redis预减库存→消息队列异步下单→DB扣库存。
  4. 防超卖：Redis Lua脚本原子扣减 + DB乐观锁(version/条件update)。
  5. 削峰：验证码/答题→消息队列平滑流量。
  6. 隔离：秒杀独立部署，不影响主业务。

限流算法有哪些？
限流算法
  • 计数器固定窗口：固定时间窗口内计数，边界突刺问题。
  • 计数器滑动窗口：将窗口细分，解决边界问题。
  • 漏桶(Leaky Bucket)：恒定速率处理，超出入桶排队/丢弃。平滑但无法应对突发。
  • 令牌桶(Token Bucket)：恒定速率生成令牌，可应对一定突发。最常用(Sentinel/Guava RateLimiter)。

OAuth 2.0 和 SSO 单点登录原理？
认证OAuth2

OAuth 2.0四种授权模式：

  • 授权码模式（最安全）：第三方→授权服务器→获取授权码→换AccessToken。适用于有后端的应用。
  • 隐式模式：直接返回Token（已不推荐）。
  • 密码模式：用户直接把密码给第三方（内部系统登录）。
  • 客户端凭证：服务器间调用。

SSO原理：多个系统共用认证中心（CAS）。A系统登录→认证中心建Session+发Ticket→B系统校验Ticket→免登录。

DDD 领域驱动设计核心概念？
DDD架构

核心概念：

  • 实体(Entity)：有唯一标识，可变。
  • 值对象(Value Object)：无唯一标识，不可变（如地址、金额）。
  • 聚合(Aggregate)：一组相关对象的集合，聚合根是入口。
  • 仓储(Repository)：领域对象的持久化接口。
  • 领域服务：不适合放在实体/值对象中的业务逻辑。
  • 领域事件：领域内发生的有意义事件。
  • 限界上下文(Bounded Context)：领域模型的边界，微服务拆分的依据。

Maven 依赖传递和冲突解决？
Maven构建

依赖传递：引入A→A依赖B→B也被引入。scope影响传递（compile可传，provided/test不传）。

冲突解决：

  • 最短路径优先：A→B→C(1.0) > A→D→E→C(2.0) →选C(1.0)。
  • 第一声明优先：同路径深度，先声明的依赖优先。
  • 手动排除：<exclusions><exclusion>排除不需要的传递依赖。
  • 指定版本：<dependencyManagement>统一管理版本。
  • mvn dependency:tree查看依赖树，定位冲突。
