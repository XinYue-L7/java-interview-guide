Java 1.8 相对于之前旧版本有什么新特性？
Java基础高频

1. 定义：Java 1.8（JDK 8）是 Java 语言的一次重大版本更新，引入了函数式编程思想、新的 API 和语法糖，极大提升了开发效率和代码简洁性。

2. 作用：

  • 简化集合操作与并行处理。
  • 支持函数式编程范式，减少样板代码。
  • 解决旧版日期时间 API 的线程安全问题。
  • 增强接口的表达能力，便于接口演进。

3. 原理：

  • Lambda 表达式：基于 invokedynamic 字节码指令和函数式接口实现，编译器将 Lambda 转换为私有静态方法，通过 LambdaMetafactory 动态生成实现类。
  • Stream API：基于管道（Pipeline）和惰性求值，数据源 → 中间操作（过滤/映射）→ 终止操作（聚合/收集），支持并行流（parallelStream）利用 Fork/Join 框架拆分任务。
  • 默认方法：通过 default 关键字在接口中提供默认实现，编译后生成桥接方法，解决接口扩展与已有实现的兼容性问题。
  • 新时间日期 API：java.time 包基于 Joda-Time 设计，核心类均为不可变对象，线程安全。
  • 接口静态方法：允许在接口中定义静态工具方法。

你具体是怎么用 Lambda 表达式的？可以举个例子说明吗？
Java基础

1. 定义：Lambda 表达式是一种匿名函数的简洁写法，允许将函数作为参数传递，是函数式编程在 Java 中的核心体现。

2. 作用：替代冗长的匿名内部类写法，使代码更简洁、可读性更高，尤其适用于集合遍历、事件监听、Stream 操作等场景。

3. 原理：编译器将 Lambda 体转换为类的私有方法，通过 invokedynamic 指令在运行时由 LambdaMetafactory 生成对应的函数式接口实现对象，避免每次编译都生成匿名类的字节码膨胀问题。

示例：

// 遍历集合
list.forEach(o -> System.out.println(o));
// 排序
list.sort((a, b) -> a.getAge() - b.getAge());
// Stream 过滤 + 映射
list.stream()
    .filter(e -> e.getSalary() > 5000)
    .map(e -> e.getName())
    .collect(Collectors.toList());
// Runnable 线程
new Thread(() -> System.out.println("Running")).start();

你们项目中平时用得比较多的集合有哪些？
Java基础

1. 定义：Java 集合框架（Java Collections Framework）是一组用于存储和操作对象组的接口和类，分为单列集合（Collection）和双列集合（Map）。

2. 作用：提供统一、高效、可复用的数据结构，满足不同场景下的数据存储、检索、排序和去重需求。

3. 原理：

  • ArrayList：基于动态数组，扩容时创建 1.5 倍新数组并复制元素。
  • HashSet：基于 HashMap 实现，元素作为 Key，Value 为一个固定对象 PRESENT，利用哈希表去重。
  • HashMap：基于哈希表（数组 + 链表/红黑树），通过 (n - 1) & hash 定位桶，解决哈希冲突。
  • ConcurrentHashMap：JDK 1.7 采用分段锁（Segment），1.8 改为 CAS + synchronized 锁单个桶节点，提升并发性能。

ArrayList 和 LinkedList 的区别？
Java基础高频

1. 定义：两者都是 List 接口的实现类，ArrayList 基于动态数组，LinkedList 基于双向链表。

2. 作用：ArrayList 适用于随机访问频繁的场景；LinkedList 适用于频繁插入、删除的场景（尤其是头部/尾部）。

3. 原理：

对比项ArrayListLinkedList
底层结构Object[] 数组双向链表（Node：prev + data + next）
查询随机访问 O(1)需遍历 O(n)
插入/删除尾部 O(1)（均摊），中间需移动元素 O(n)只需修改指针 O(1)（已知节点位置）
内存占用连续内存，有扩容开销每个节点额外存储两个指针，内存碎片化
适用场景读多写少、随机访问频繁增删、实现队列/栈

请简单介绍一下 HashMap，它和旧版本 JDK 中的 HashMap 有什么大的改进或区别？
Java基础高频

1. 定义：HashMap 是基于哈希表实现的键值对存储结构，允许一个 null 键和多个 null 值，非线程安全，查询/插入平均时间复杂度为 O(1)。

2. 作用：提供高效的键值对存取，是 Java 中最常用的 Map 实现，广泛应用于缓存、索引、数据映射等场景。

3. 原理（JDK 1.7 vs 1.8）：

  • JDK 1.7：数组 + 链表，哈希冲突采用头插法。并发扩容时可能出现环形链表，导致 get() 死循环。
  • JDK 1.8：数组 + 链表/红黑树：当链表长度 ≥ 8 且数组长度 ≥ 64 时，链表转为红黑树，查询复杂度从 O(n) 降为 O(log n)。
  • 哈希冲突采用尾插法，避免并发扩容死循环。
  • 扩容时通过 (hash & oldCap) == 0 判断是否需要移动位置，减少元素迁移量。

你了解红黑树是一个什么样的结构吗？
Java基础

1. 定义：红黑树（Red-Black Tree）是一种自平衡二叉搜索树（BST），在每个节点上增加一个颜色属性（红或黑），通过颜色约束维持树的平衡。

2. 作用：保证最坏情况下查找、插入、删除的时间复杂度均为 O(log n)，避免普通 BST 退化为链表（O(n)）。

3. 原理：红黑树通过 5 条性质限制树的最大高度不超过 2log(n+1)：

  1. 节点是红色或黑色。
  2. 根节点是黑色。
  3. 所有叶子（NIL）是黑色。
  4. 红色节点的两个子节点都是黑色（不能连续红）。
  5. 从任一节点到其每个叶子的所有路径包含相同数目的黑色节点（黑高相同）。

当插入或删除破坏性质时，通过变色和旋转（左旋、右旋）恢复平衡。JDK 1.8 HashMap 利用红黑树优化长链表性能问题。

你了解 JVM 内存结构吗？可以简单介绍一下它包含哪些区域吗？
Java基础高频

1. 定义：JVM 内存结构（运行时数据区）是 Java 虚拟机在执行 Java 程序时划分的内存区域，用于存储数据、指令和对象。

2. 作用：为 Java 程序的运行提供内存分配、线程隔离、对象生命周期管理和垃圾回收的基础环境。

3. 原理：运行时数据区分为线程私有和线程共享两大类。

线程私有：

  • 程序计数器（PC Register）：记录当前线程执行的字节码行号，线程切换时恢复执行位置。唯一不会发生 OOM 的区域。
  • 虚拟机栈（VM Stack）：每个方法执行时创建一个栈帧，存储局部变量表、操作数栈、动态链接、方法返回地址。方法调用即入栈，返回即出栈。
  • 本地方法栈（Native Method Stack）：为 Native 方法（C/C++）服务，HotSpot 中与虚拟机栈合并。

线程共享：

  • 堆（Heap）：存放对象实例和数组，是 GC 的主要工作区域。逻辑上分为新生代（Eden、Survivor）和老年代。
  • 方法区（Method Area）：存储类信息、常量、静态变量、即时编译器编译后的代码。JDK 8 之前为永久代（PermGen），JDK 8 起改为元空间（Metaspace），使用本地内存。

除了堆和栈，还有其他区域吗？
Java基础

1. 定义：直接内存（Direct Memory）不属于 JVM 运行时数据区，是操作系统本地内存的一部分，通过 java.nio.ByteBuffer 的 allocateDirect() 方法分配。

2. 作用：避免在 Java 堆和 Native 堆之间来回复制数据，提升 I/O 操作性能，常用于 NIO、Netty、MappedByteBuffer 等高性能 I/O 场景。

3. 原理：DirectByteBuffer 通过 Unsafe.allocateMemory() 在堆外分配内存，其引用存储在 Java 堆中的 DirectByteBuffer 对象里。GC 回收该对象时会触发 Cleaner 释放堆外内存。直接内存不受 -Xmx 限制，但受限于系统总内存，分配过大会导致 OOM（OutOfMemoryError: Direct buffer memory）。

你了解 Java 垃圾回收吗？
Java基础高频

1. 定义：垃圾回收是 Java 虚拟机自动管理堆内存的机制，负责回收不再被引用的对象所占用的内存，无需程序员手动释放。

2. 作用：防止内存泄漏和悬空指针，降低内存管理复杂度。

3. 原理：

（1）判断对象是否存活：

  • 引用计数法：每个对象维护引用计数器，为 0 时回收。缺点：无法解决循环引用。
  • 可达性分析：从 GC Roots 出发向下搜索，不可达的对象标记为垃圾。GC Roots 包括：虚拟机栈局部变量、本地方法栈 JNI 引用、方法区静态变量/常量、同步锁持有的对象、活跃线程。

（2）垃圾回收算法：

  • 标记-清除：标记存活对象，清除未标记对象。缺点：产生内存碎片。
  • 复制算法：内存分两块，存活对象复制到另一块。无碎片，但空间利用率 50%，用于新生代（Eden → Survivor）。
  • 标记-整理：标记存活对象并向一端移动，清理边界外内存。无碎片，用于老年代。
  • 分代收集：新生代用复制算法，老年代用标记-整理/清除。

（3）常见垃圾收集器：

收集器特点适用场景
Serial单线程，STW客户端模式
Parallel多线程并行，高吞吐量后台计算
CMS并发标记清除，低延迟互联网应用（JDK 14 废弃）
G1区域化堆，可预测停顿大堆（JDK 9+ 默认）
ZGC/Shenandoah超低延迟（<10ms）超大堆、低停顿

请简单说一下两个等号（==）和 equals 的区别。
Java基础高频

1. 定义：== 是 Java 中的比较运算符；equals() 是 Object 类定义的方法，用于对象内容的比较。

2. 作用：== 判断两个变量是否指向同一内存地址；equals 判断两个对象是否在逻辑上相等。

3. 原理：

  • ==：基本类型比较值是否相等；引用类型比较内存地址是否相同。
  • equals()：Object 类默认实现与 == 相同（比较地址）；若类重写了 equals()（如 String、Integer），则比较对象的内容/状态。
  • 重写 equals() 必须同时重写 hashCode()，以维护 hashCode 契约：相等对象必须有相等哈希码。

你们使用 Java 时怎么考虑线程安全？怎么实现线程安全？
Java基础并发

1. 定义：线程安全指在多线程环境下，对共享数据的访问和操作不会导致数据不一致或程序异常。

2. 作用：保证并发场景下数据的正确性、原子性、可见性和有序性。

3. 原理：多线程安全问题的根源是多线程并发读写共享可变变量，破坏了三大特性：

  • 原子性：操作不可中断。
  • 可见性：一个线程修改对其它线程立即可见。
  • 有序性：禁止指令重排序。

分层解决方案：

层级方案原理
1. 避免共享局部变量、ThreadLocal栈私有或线程绑定副本，无竞争
2. 不可变对象String、final 类状态不可变，天然线程安全
3. 原子操作AtomicInteger 等 CAS 类Unsafe 的 CAS 自旋，无锁原子更新
4. 可见性/有序性volatile内存屏障保证可见性，禁止重排序
5. 互斥锁synchronized、ReentrantLockMonitor（对象头 Mark Word）；AQS 队列同步器
6. 并发容器ConcurrentHashMap、CopyOnWriteArrayList分段锁/CAS/写时复制
7. 线程封闭单线程执行消除共享，从根本上避免竞争

请简单介绍一下线程池有哪几大参数？
Java基础并发

1. 定义：线程池是预先创建一组线程并复用它们执行任务的机制，由 ThreadPoolExecutor 实现。

2. 作用：减少线程创建/销毁开销，控制并发数量，便于线程管理和资源调度。

3. 原理：ThreadPoolExecutor 的 7 大核心参数：

参数说明
1. corePoolSize核心线程数，即使空闲也保留（除非 allowCoreThreadTimeOut）
2. maximumPoolSize最大线程数，当队列满时创建救急线程
3. keepAliveTime非核心线程空闲存活时间
4. unit时间单位
5. workQueue阻塞队列（ArrayBlockingQueue、LinkedBlockingQueue、SynchronousQueue 等）
6. threadFactory线程工厂，自定义线程名称、优先级、守护状态
7. handler拒绝策略

4 种内置拒绝策略：

  • AbortPolicy：直接抛出 RejectedExecutionException（默认）。
  • CallerRunsPolicy：由提交任务的线程（调用者）自己执行。
  • DiscardPolicy：静默丢弃任务，无异常。
  • DiscardOldestPolicy：丢弃队列中最老的任务，尝试重新提交。

执行流程：提交任务 → 核心线程数未满则创建线程 → 已满则入队列 → 队列满则创建救急线程 → 达到最大线程数则执行拒绝策略。

请简单介绍一下 Spring 的 AOP 和 IOC。
Spring高频

1. IOC（控制反转）：

  • 定义：IOC 是一种设计思想，将对象的创建、依赖关系的管理从程序内部转移到外部容器。
  • 作用：实现组件解耦，降低类与类之间的依赖，便于单元测试和模块化开发。
  • 原理：Spring 通过依赖注入（DI）实现：容器读取配置（XML/注解/配置类）生成 BeanDefinition → 利用反射实例化 Bean，通过构造器/Setter/字段注入依赖 → 维护 Bean 生命周期（单例/原型），管理循环依赖（三级缓存：singletonObjects → earlySingletonObjects → singletonFactories）。

2. AOP（面向切面编程）：

  • 定义：AOP 是一种编程范式，将横切关注点（日志、事务、权限、监控）从业务逻辑中剥离，实现无侵入增强。
  • 作用：减少代码重复，提高模块化程度，使业务代码更纯粹。
  • 原理：基于动态代理实现运行时增强：Bean 需要被增强时，Spring 创建代理对象替代原对象；方法调用时拦截并先执行切面逻辑（Before/After/Around），再调用目标方法。代理类型：JDK 动态代理（目标类实现接口）或 CGLIB 代理（目标类无接口，生成子类）。

你知道 Spring IoC 容器的加载流程是怎样的吗？
Spring

1. 定义：IoC 容器加载流程指 Spring 从启动到就绪，完成所有 Bean 定义解析、加工、实例化和初始化的完整过程。

2. 作用：确保所有配置正确解析，Bean 按依赖顺序正确创建，容器处于可用状态。

3. 原理（以 AnnotationConfigApplicationContext 为例）：

  1. 刷新容器：调用 refresh() 方法。
  2. 加载配置资源：解析 @Configuration 类或 XML 配置文件。
  3. 生成 BeanDefinition：通过 BeanDefinitionReader 扫描并注册所有 Bean 定义到 BeanDefinitionRegistry。
  4. 执行 BeanFactoryPostProcessor：如 ConfigurationClassPostProcessor 处理 @ComponentScan、@Import、@Bean 等。
  5. 注册 BeanPostProcessor：实例化并注册所有后置处理器。
  6. 实例化单例 Bean：反射调用构造器创建对象 → populateBean() 依赖注入（@Autowired、@Value）→ 初始化（Aware 接口、BeanPostProcessor.before()、@PostConstruct/InitializingBean、BeanPostProcessor.after()）。
  7. 容器就绪：对外提供 getBean() 获取对象。

AOP 是通过什么原理实现的？你知道常用的动态代理实现有哪几种吗？
Spring高频

1. 定义：AOP 通过动态代理在运行时生成代理对象，拦截目标方法调用，织入增强逻辑。

2. 作用：在不修改源代码的情况下，为方法添加前置、后置、环绕等横切逻辑。

3. 原理：

代理方式原理适用场景
JDK 动态代理基于 java.lang.reflect.Proxy，运行时生成实现相同接口的代理类，通过 InvocationHandler.invoke() 拦截方法目标类有接口
CGLIB 代理基于 ASM 字节码库生成目标类的子类，通过 MethodInterceptor.intercept() 拦截方法。不能代理 final 类和 final 方法目标类无接口

Spring 默认策略：若目标类实现了接口，优先使用 JDK 代理；否则使用 CGLIB。可通过 @EnableAspectJAutoProxy(proxyTargetClass = true) 强制使用 CGLIB。

比如配了 @Transactional 注解，什么情况下会导致事务失效？
Spring高频

1. 定义：事务失效指方法上标注了 @Transactional，但事务并未生效，异常时数据未回滚。

2. 作用：理解事务边界和代理机制，避免生产环境数据不一致。

3. 原理：@Transactional 通过 AOP 代理实现，事务失效通常是因为代理未被触发或配置错误：

失效场景原理说明
同类内部方法调用this.method() 调用的是原对象，非代理对象，代理逻辑未被触发。解决方案：注入自身代理，或拆分到另一个 Bean
非 public 方法Spring 事务代理基于 AOP，只能拦截 public 方法
异常被 try-catch 吞掉代理只在异常抛出到外层时回滚，若被捕获则视为正常完成
未指定 rollbackFor默认只回滚 RuntimeException 和 Error，受检异常（如 IOException）不回滚，需配置 rollbackFor = Exception.class

异步方法@Async 方法在新线程执行，与原线程事务上下文隔离

请简单描述一下 Spring Boot 有什么优点？
SpringBoot

有没有遇到生产环境查询特别慢的情况？一般怎么排查问题？
数据库调优

1. 定义：慢查询是执行时间超过阈值（long_query_time，默认 10 秒）的 SQL 查询，影响系统响应和用户体验。

2. 作用：定位性能瓶颈，优化 SQL 和数据库配置，提升查询效率。

3. 原理（排查步骤）：

  1. 开启慢查询日志：SET GLOBAL slow_query_log = 'ON'; SET GLOBAL long_query_time = 1; 或使用 mysqldumpslow、pt-query-digest 分析。
  2. 使用 EXPLAIN 分析执行计划：关注 type（避免 ALL）、key（是否用索引）、rows（扫描行数）、Extra（是否有 Using filesort、Using temporary）。
  3. 检查索引使用情况：是否缺少索引；索引是否失效（函数操作、类型转换、like '%xx'）；是否选错索引（FORCE INDEX 干预）。
  4. 分析锁竞争：SHOW ENGINE INNODB STATUS 查看死锁和锁等待；information_schema.INNODB_TRX 查看活跃事务。
  5. 检查服务器资源：SHOW GLOBAL STATUS 查看 QPS、TPS、连接数；监控 CPU、内存、磁盘 I/O（iostat、vmstat）。
  6. 优化措施：加索引、优化 SQL（避免 SELECT *、大分页用覆盖索引/延迟关联）；读写分离、分库分表、引入缓存（Redis）。

请简单介绍一下索引的使用场景，索引是不是越多越好？它有什么缺点？
数据库高频

1. 定义：索引是帮助数据库高效获取数据的数据结构，类似书籍的目录。

2. 作用：加速数据检索（SELECT/UPDATE/DELETE 的 WHERE 条件），减少全表扫描。

3. 原理：MySQL 索引通常以 B+ 树存储：非叶子节点存储键值和指针，叶子节点存储实际数据（聚簇索引）或主键值（非聚簇索引）；查询时从根节点二分查找，时间复杂度 O(log n)。

索引不是越多越好，缺点如下：

缺点说明
降低写性能插入、删除、更新时需维护索引结构（B+ 树分裂/合并），增加额外开销
占用磁盘空间每个索引都是一份独立数据结构，大表索引可能占用大量空间
增加优化器选择成本索引过多时，优化器评估成本增加，可能选错索引
缓存效率下降索引页占用 Buffer Pool，减少数据页缓存空间

使用场景：WHERE、ORDER BY、GROUP BY、JOIN 条件中的列；区分度高的列（cardinality 高）；频繁查询、较少更新的列。

哪些场景下索引会失效？
数据库高频

1. 定义：索引失效指 SQL 语句虽然存在索引，但优化器选择不走索引，改为全表扫描。

2. 作用：了解失效场景，编写高效的 SQL，避免性能陷阱。

3. 原理（失效场景）：

失效场景原理
对索引列使用函数/表达式WHERE YEAR(create_time) = 2024，B+ 树无法对函数结果排序定位
隐式类型转换字符串字段传数字，MySQL 将字段转为数字再比较，破坏索引
like 以 % 开头WHERE name LIKE '%张%'，前缀不确定，无法利用 B+ 树有序性
OR 条件部分列无索引只要一个条件无可用索引，可能全表扫描
!=、<>、NOT IN范围太广，优化器认为全表扫描更快
IS NULL / IS NOT NULL数据分布不均时可能失效
复合索引未遵循最左前缀索引 (a,b,c)，查询条件只有 b 和 c，缺少最左列 a

你知道索引在 MySQL 中以什么样的数据结构存储？
数据库高频

1. 定义：MySQL（InnoDB）索引主要采用 B+ 树（Balanced Plus Tree）作为底层数据结构。

2. 作用：支持高效的范围查询、等值查询和顺序访问，同时保持树的平衡，避免退化为链表。

3. 原理（B+ 树特点）：

  • 多路平衡树：每个节点可包含多个键值和指针，降低树高，减少磁盘 I/O。
  • 数据只在叶子节点：非叶子节点仅存储键值和子节点指针，可存储更多键，树更矮。
  • 叶子节点双向链表：支持高效的范围查询和顺序遍历。
  • 聚簇索引：叶子节点存储完整行数据；非聚簇索引：叶子节点存储主键值，需回表查询。

为什么不用哈希表？哈希表等值查询 O(1) 快，但不支持范围查询和排序。

为什么不用 B 树？B 树数据分散在各节点，范围查询需中序遍历，效率低；B+ 树叶子节点链表更适合范围查询和全表扫描。

你知道 MySQL 的聚簇索引和非聚簇索引吗？它们在存储数据时结构有什么不一样？
数据库高频

1. 定义：聚簇索引（Clustered Index）数据行和索引存储在一起，叶子节点即数据页；非聚簇索引（Secondary Index）索引和数据分离，叶子节点存储主键值。

2. 作用：聚簇索引决定数据物理存储顺序；非聚簇索引加速特定列查询，但可能需要回表。

3. 原理：

对比项聚簇索引非聚簇索引
数量一张表只能有一个（主键索引）可以有多个
叶子节点内容存储完整的行数据存储索引列值 + 主键值
数据存储数据即索引，索引即数据索引与数据分离
查询方式直接定位数据先查索引得主键，再回表查聚簇索引（覆盖索引除外）
插入性能需按主键顺序维护，随机主键导致页分裂影响较小
空间占用无额外存储（数据本身）需额外存储空间

覆盖索引：若查询列全在非聚簇索引中（如 SELECT name FROM user WHERE name = 'xxx'，且 name 有索引），无需回表，直接返回结果。

你在项目中是怎么进行 SQL 调优的？
数据库调优

1. 定义：SQL 调优是通过分析、改写 SQL 和优化数据库配置，降低查询响应时间和资源消耗。

2. 作用：提升系统吞吐量，降低数据库负载，改善用户体验。

3. 原理（调优步骤）：

  1. 定位慢 SQL：开启慢查询日志，使用 pt-query-digest 分析；SHOW PROCESSLIST 查看执行中的慢查询。
  2. 分析执行计划：EXPLAIN ANALYZE（PostgreSQL）或 EXPLAIN（MySQL）；关注扫描方式（Seq Scan → Index Scan → Index Only Scan 优化方向）。
  3. 索引优化：为 WHERE、JOIN、ORDER BY 列创建索引；使用覆盖索引避免回表；删除冗余/未使用索引。
  4. SQL 改写：避免 SELECT *；大分页优化（LIMIT 1000000, 10 改为基于主键的范围查询）；用 EXISTS 替代 IN（子表大时）；避免在索引列上做函数运算。
  5. 表结构优化：选择合适的数据类型；适当反范式设计减少 JOIN；大表水平/垂直拆分。
  6. 配置与架构优化：调整 Buffer Pool、连接池大小；读写分离、分库分表；引入缓存（Redis）减少数据库压力。

Docker、K8S 这些有没有用过？

1. Docker：

  • 定义：基于容器技术的轻量级虚拟化平台，将应用及其依赖打包为镜像，实现一次构建、到处运行。

如果让你去开发一个 Pipeline（流水线）去打包、打镜像、推送，你会怎么做？有没有了解过具体的脚本配置？
云平台CI/CD

1. 定义：CI/CD Pipeline（持续集成/持续部署流水线）自动化完成代码构建、测试、镜像打包和部署。

2. 作用：减少人工干预，提升交付效率，保证构建和部署的一致性。

3. 原理：以 GitLab CI 为例（.gitlab-ci.yml）：

stages:
  - build
  - test
  - package
  - deploy

variables:
  MAVEN_OPTS: "-Dmaven.repo.local=.m2/repository"
  IMAGE_NAME: "registry.example.com/myapp"

# 1. 编译打包
build:
  stage: build
  image: maven:3.8-openjdk-17
  script:
    - mvn clean package -DskipTests
  artifacts:
    paths:
      - target/*.jar

# 2. 单元测试
test:
  stage: test
  image: maven:3.8-openjdk-17
  script:
    - mvn test

# 3. 构建并推送镜像
package:
  stage: package
  image: docker:20-dind
  services:
    - docker:20-dind
  script:
    - docker build -t $IMAGE_NAME:$CI_COMMIT_SHA .
    - docker push $IMAGE_NAME:$CI_COMMIT_SHA
    - docker tag $IMAGE_NAME:$CI_COMMIT_SHA $IMAGE_NAME:latest
    - docker push $IMAGE_NAME:latest

# 4. 部署到 K8s
deploy:
  stage: deploy
  image: bitnami/kubectl:latest
  script:
    - kubectl set image deployment/myapp myapp=$IMAGE_NAME:$CI_COMMIT_SHA
    - kubectl rollout status deployment/myapp
  only:
    - main

Jenkins Pipeline（Jenkinsfile）示例：

pipeline {
  agent any
  environment {
    IMAGE_NAME = 'registry.example.com/myapp'
  }
  stages {
    stage('Build') {
      steps { sh 'mvn clean package -DskipTests' }
    }
    stage('Docker Build & Push') {
      steps {
        script {
          docker.build("${IMAGE_NAME}:${BUILD_NUMBER}")
          docker.withRegistry('https://registry.example.com', 'docker-creds') {
            docker.image("${IMAGE_NAME}:${BUILD_NUMBER}").push()
            docker.image("${IMAGE_NAME}:${BUILD_NUMBER}").push('latest')
          }
        }
      }
    }
    stage('Deploy') {
      steps {
        sh 'kubectl set image deployment/myapp myapp=${IMAGE_NAME}:${BUILD_NUMBER}'
      }
    }
  }
}

假如说我现在有 10 个大写字母，然后我想对这 10 个大写字母按照从前 ABCD 这种顺序去排，你不用那种工具类提供的 sort 方法，你自己写方法去排这个顺序，你要怎么去做呢？
算法

1. 定义：排序是将一组数据按特定顺序（升序/降序）重新排列的算法。

2. 作用：将无序数据变为有序，便于查找、去重和展示。

3. 原理：大写字母 A-Z 的 ASCII 码连续（65-90），可利用计数排序（Counting Sort）或冒泡排序实现。计数排序时间复杂度 O(n)，适合范围有限的数据。

计数排序实现：

public class LetterSort {
    public static char[] sortLetters(char[] arr) {
        // A-Z 共 26 个字母，计数数组大小为 26
        int[] count = new int[26];
        // 统计每个字母出现次数
        for (char c : arr) {
            count[c - 'A']++;
        }
        // 按顺序回填
        int index = 0;
        for (int i = 0; i < 26; i++) {
            while (count[i] > 0) {
                arr[index++] = (char) (i + 'A');
                count[i]--;
            }
        }
        return arr;
    }

    public static void main(String[] args) {
        char[] letters = {'C', 'A', 'Z', 'B', 'A', 'M', 'K', 'D', 'Y', 'B'};
        sortLetters(letters);
        System.out.println(letters); // AABBC DKM YZ
    }
}

冒泡排序实现（通用）：

public static char[] bubbleSort(char[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        for (int j = 0; j < arr.length - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                char temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
    return arr;
}
