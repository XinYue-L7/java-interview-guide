什么是大模型（LLM）？GPT 中的 175B 指什么？
LLM基础

1. 定义：

大模型一般指参数量 1 亿以上的深度学习模型（标准还在升级，已有万亿参数模型）；LLM 特指面向语言的大模型，在海量无标注文本上自监督预训练，具备通用语言理解与生成能力。

2. 175B、60B、540B 指参数个数：

B = Billion（十亿）。175B = 1750 亿参数，约为 GPT-3 / ChatGPT 的规模。参数量级决定了模型的容量与涌现能力，也决定了训练成本（GPT-3 训练约 30 万美元、碳排放约 284 吨）。

3. 生成式大模型的两个特点：

参数量达 Billion 级别；能通过条件/上下文（prompt）引导生成文本、图片、音频等新内容 —— prompt engineering 由此而来。

2
为什么现在的大模型大部分是 Decoder-only 结构？
架构高频

1. 三种结构的区别（attention mask）：

结构注意力方式特点
Encoder-Decoder（T5）输入双向注意力理解任务好，长文本生成差、训练效率低
causal Decoder（GPT）自回归，只看前文预训练与下游一致，生成与 zero-shot 强
prefix Decoder（GLM/PaLM）前缀内互相可见折中，训练效率低

2. Decoder-only 胜出的原因：

  • zero-shot 能力最好：不微调也有不错表现；而 encoder-decoder 需要一定量标注数据做多任务微调才能激发最佳性能，与"大规模无标注语料自监督预训练"的范式不匹配。
  • 双向注意力的低秩问题：Encoder 双向注意力容易退化为低秩矩阵，削弱表达能力；因果 mask 天然是满秩下三角，理论表达能力更强。
  • 训练与生成完全一致（预测下一个词），工程实现简单（KV Cache 加速友好）。
3
大模型 LLM 的训练目标是什么？
预训练

1. 两大类目标：

  • 语言模型（自回归）：根据已有词预测下一个词，目标为最大似然 —— GPT 系列在所有 token 上计算损失。
  • 去噪自编码器：随机替换/遮盖文本段，让模型恢复被破坏的内容，难度更高 —— T5、GLM-130B 采用；Prefix Decoder 类只在输出部分计算损失。

2. 训练三部曲：

  • 预训练（Pre-train）：海量语料学知识。
  • SFT 指令微调：在高质量问答对上学习"按指令作答"的形式，激发已学到的能力。
  • RLHF：用人类反馈对齐模型的意图与偏好（可选）。

大模型有哪些优点和缺点？
LLM幻觉

1. 优点：

  • 可用海量无标注数据预训练 + 少量标注微调，大幅降低标注成本、提升泛化能力。
  • 能生成文本、图像、音乐等新内容。
  • 凭涌现能力完成数学应用题、常识推理、符号操作等复杂任务（模型规模跨过临界点后能力突增 —— 一种解释：整体任务是多个子任务的乘积，各子任务平滑提升，整体表现为"涌现"）。

2. 缺点：

  • 算力与存储开销大：训练贵、推理慢。
  • 幻觉：逐 token 概率采样，难免"一本正经地胡说八道"。
  • 时效性：训练周期长，最新信息（如"热映电影推荐"）无法直接回答。
  • 数据偏见、隐私泄露、滥用的风险；可解释性差。

什么是 RAG？为什么需要 RAG？
RAG高频

1. 定义：

检索增强生成（Retrieval Augmented Generation）：模型回答前先从知识库检索相关信息，再基于检索内容生成回答。两部分组成：

  • 检索器：从知识库召回最相关的前 k 个文档（Embedding 向量化 + 向量库相似度检索）。
  • 生成器：把检索片段与用户 query 一起作为输入，产出最终回答。

2. 为什么需要：

  • 缓解幻觉：让回答贴着可信数据源生成。
  • 解决时效性：不用重新训练即可接入最新数据；企业私域知识（文档、手册）通过"与文档对话"落地。
  • 可引用来源，便于查证。

3. 局限：检索质量依赖 embedding 与切分策略，检索到无关信息反而干扰生成；无法引用来源时难以查证。进阶方案：RAG-Fusion（多查询改写 + RRF 重排）、Graph RAG（知识图谱检索子图做上下文）。

6
RAG 和微调（SFT）如何选择？
RAGSFT高频

核心判断：知识更新 vs 行为调整

维度RAGSFT/微调
解决什么注入/更新知识（外部数据、实时信息）调整行为/风格/格式（激发预训练已有能力）
成本建向量库 + 检索链路，改动小要高质量标注数据 + GPU 资源
时效数据实时可更新训练后固化，更新需再训
风险检索质量决定上限数据少任务杂易过拟合/灾难性遗忘

结论：让模型"知道新东西"（企业文档、新闻）→ RAG；让模型"说话方式/输出格式/领域话术"改变 → 微调；两者常组合使用。注意 LoRA 等高效微调是低秩的，只能改风格、改不了知识，要注入知识需全量微调或 RAG。

什么是 LangChain？包含哪些核心概念？
LangChain

1. 定义：

帮助开发者用语言模型构建端到端应用的框架：提供工具、组件和接口，简化基于 LLM 的应用开发，可管理模型交互、把多个组件链接（Chain）起来，并集成 API、数据库等外部资源。

2. 核心概念：

  • Components 与 Chain：组件 + 调用序列的标准接口。
  • Prompt Templates：模板化生成 Prompt；Output Parsers：解析结构化输出。
  • Indexes 与 Retrievers：文档索引与检索（RAG 落地的载体）。
  • Chat Message History：维护对话记忆/状态。
  • Agents 与 Toolkits：由 LLM 决策调用哪些工具。

3. 三类模型抽象：LLM（文本进文本出）、Chat Model（消息列表进消息出）、Text Embedding Model（文本进向量出，用于检索与相似度）。

什么是 Agent？LangChain Agent 是什么？
Agent高频

1. 概念：

Agent = LLM 作为"大脑" + 工具集 + 规划循环：模型不再只生成文本，而是能感知任务 → 拆解步骤 → 决定调用哪个工具（搜索、代码执行、API）→ 观察结果 → 迭代直到完成目标。

2. LangChain Agent：

是框架中驱动决策制定的实体：可访问一组工具（Toolkits），根据用户输入决定调用哪个工具、以什么参数调用。适合"交互链未知、需要自适应"的复杂应用 —— 与固定流程的 Chain 相反，Agent 的下一步行动由 LLM 动态决定（ReAct 模式：思考 → 行动 → 观察）。

3. Function Call：

模型厂商提供的能力：在请求里声明可用的函数 schema，模型判断需要时输出"函数名 + 结构化参数"，由应用执行后把结果回传给模型继续推理 —— 是 Agent 调用工具的标准化通道。

什么是 PEFT？它和全量微调有什么区别？
PEFTLoRA

1. 定义：

Parameter-Efficient Fine-Tuning（参数高效微调）：冻结原模型绝大部分参数，只训练少量新增参数完成下游任务适配。代表方法 LoRA（在权重旁加低秩矩阵 A×B，只训 A、B）、P-tuning 系列（可学习的连续 Prompt 向量）、Prefix-tuning 等。

2. 与全量微调的区别：

  • 能力边界：全量微调可以改变知识；LoRA 这类高效微调本质是低秩的，只能改变风格、无法对模型产生决定性改变（不能注入知识）。
  • 资源：LoRA 显存与算力需求低一个数量级，单卡可微调 7B 模型。
  • 优点：缓解灾难性遗忘（原参数不动）、可插拔（一个基座挂多个 LoRA 适配器）、算力受限下性价比极高。

SFT 之后模型变傻、灾难性遗忘是怎么回事？如何避免？
SFT微调高频

1. 原理认知：

SFT 的作用是激发/解锁模型能力，而不是灌注知识。SFT 数据通常只有 alpaca 52k 这种量级，远小于预训练数据 —— 抱着"灌领域知识"的目的做 SFT，容易把模型弄傻。

2. 灾难性遗忘：

学了新任务后几乎彻底忘掉原有能力（例：ChatGLM-6B 用拼写纠错数据微调后，问"失眠怎么办"答非所问）。常见诱因是学习率过高。

3. 解决方案：

  • 初始学习率用 2e-5 或更小，不超过预训练学习率；按 batch size 缩放（batch 增 4 倍、lr 增 2 倍）。
  • 混入通用数据一起训练：领域数据不多时，领域数据与通用数据按 1:5 到 1:10 混合比例。
  • 数据量少（<10k）用 Chat 模型做基座微调；有 100k 数据且资源充足才考虑 Base 模型。
  • 改知识用 Continue PreTrain（可配 MIP：预训练阶段同步混入 SFT 数据）。
11
SFT 指令微调数据如何构建？
微调数据

三点原则：

  • 代表性：覆盖多个有代表性的任务类型（问答、摘要、代码、推理等），让模型学到通用的"指令跟随"模式。
  • 数据量适中：每个任务实例数百个即可，过多易过拟合（模型只会这几类任务的答题套路）。
  • 质量优先：答案准确、格式统一、指令多样（同一任务换不同问法），必要时人工审核清洗。

💡 数据格式通常是 instruction / input / output 三元组（Alpaca 格式）；SFT 只对 output 部分计算损失。

微调大模型时 batch size 如何设置？太大太小有什么问题？显存怎么估算？
训练调优

1. batch size 太小：

对真实梯度的近似方差很大，单次更新方向主要是噪声；虽然多次更新会相互抵消、总体仍朝正确方向前进，但单次更新价值低，相当于把多次小更新合并成一次大 batch 更新。

2. batch size 太大：

超过临界值后继续增大几乎不提升性能（任意两组抽样都已近似真实梯度），只增加每步数据量与 FLOPS；固定 epoch 预算下模型性能反而随 batch 增大而下降。

3. 显存估算（全量微调）：

  • 粗略公式：模型参数按 20n GB 准备（n 为参数量，单位十亿）：FP16 权重 2n + 梯度 2n + AdamW 优化器状态 12n；activation 随 max length、batch size 变化。
  • 7B 模型全量微调在 FSDP 下约需 160GB；资源不够用 LoRA + 梯度累积（等效放大 batch size，注意 loss 除以累积步数）+ 梯度检查点（时间换空间：反向时重算激活值）。
