Spring IOC 的实现原理？
Spring高频

IOC(Inversion of Control)控制反转：将对象创建和依赖关系的管理交给Spring容器。

核心：BeanFactory + 反射

  1. 资源定位：加载XML/注解配置。
  2. BeanDefinition解析：将配置解析为BeanDefinition。
  3. Bean注册：注册到BeanDefinitionRegistry(Map)。
  4. Bean创建(DI)：反射创建实例→填充属性→初始化。

💡 ApplicationContext是BeanFactory的子接口，功能更丰富(国际化、事件发布等)。

Spring AOP 的实现原理？
Spring高频

AOP(Aspect Oriented Programming)面向切面编程：将横切关注点(日志/事务/权限)与业务逻辑分离。

两种实现：

  • JDK动态代理：基于接口，Proxy+InvocationHandler。目标类必须实现接口。
  • CGLIB代理：基于继承，ASM字节码生成子类。不能代理final类/方法。

💡 Spring默认：有接口用JDK代理，无接口用CGLIB。SpringBoot 2.0+默认使用CGLIB。

Spring 事务的实现原理和传播行为？
Spring事务

原理：AOP代理 + ThreadLocal

7种传播行为：

  • REQUIRED：有事务则加入，无则新建（默认）。
  • REQUIRES_NEW：总是新建事务，挂起当前事务。
  • SUPPORTS：有事务则加入，无则以非事务运行。
  • NOT_SUPPORTED：非事务运行，挂起当前事务。
  • MANDATORY：必须在事务中，无则抛异常。
  • NEVER：必须非事务，有则抛异常。
  • NESTED：嵌套事务，有savepoint可部分回滚。

Spring 事务失效的场景有哪些？
Spring实战

事务失效本质：@Transactional基于AOP动态代理，只要请求没经过代理或异常没被正确传播，事务就会失效。

  1. 同类自调用：类A无事务方法调本类有事务方法B，走的是this调用绕过代理 → 失效。解决：AopContext.currentProxy()或注入自身。
  2. 方法非public：默认代理只能拦截public方法。
  3. 异常被吞：try-catch后未重新抛出，Spring感知不到异常 → 不回滚。
  4. 异常类型不匹配：默认只回滚RuntimeException和Error，受检异常(如IOException)需@Transactional(rollbackFor = Exception.class)。
  5. 数据库引擎不支持：MyISAM不支持事务，需InnoDB。
  6. 类未被容器管理：没加@Component/@Service，或new出来的对象，无代理。
  7. 多线程：新线程不在同一事务上下文，事务不回滚。
  8. 切面顺序错误：事务切面与自定义切面顺序不当，异常被其他切面拦截。
  9. 父子容器问题：事务方法被非本容器的Bean调用（多容器环境）。
  10. synchronized锁失效：分布式环境下本地锁无法保证并发事务一致。

💡 核心口诀：内部调用绕过代理、异常没抛出/类型不对、类/方法/引擎不支持、多线程/切面/容器出问题。

Spring 中 @Autowired 和 @Resource 的区别？
Spring注解
对比@Autowired@Resource
来源Spring（org.springframework）JDK 标准（JSR-250，javax.annotation）
注入方式默认 byType（找不到再按name回退）默认 byName（找不到再按type回退）
指定名称+@Qualifier 指定 Bean 名称name 属性直接指定
支持位置字段 / setter / 构造器字段 / setter（不支持构造器）
required支持（默认 true，找不到报错）不支持
兼容性仅 Spring 框架可用JSR 标准，脱离 Spring 也可用

查找逻辑补充：

  • @Autowired：先按类型找，多个同类型Bean时若只有一个@Primary或主Bean则注入它，否则需@Qualifier指定，再不行抛NoUniqueBeanDefinitionException。
  • @Resource：先按字段名找Bean，找不到再按类型找，都找不到抛异常。它是字段名与Bean名一致时的首选。

💡 推荐：团队约定优先用构造器注入（配合@Autowired），避免字段注入导致的循环依赖和难以测试问题；如用@Resource，字段名尽量与Bean名一致以命中byName。

Spring 的循环依赖是如何解决的？
Spring高频

三级缓存解决单例Bean的循环依赖：

  • 一级缓存 singletonObjects：完全初始化好的Bean。
  • 二级缓存 earlySingletonObjects：早期暴露的半成品Bean（已实例化但未注入属性）。
  • 三级缓存 singletonFactories：ObjectFactory，可生成Bean的早期引用（支持代理对象）。

流程：A创建→实例化→放入三级缓存→填充属性发现需要B→触发B创建→B填充属性需要A→从三级缓存获取A的早期引用→B完成→A完成。

💡 限制：只能解决单例setter注入的循环依赖，构造器注入不行（实例化阶段就需要依赖）。Prototype作用域也不支持。

Spring 事务传播行为有哪些？
事务高频

7种传播行为（Propagation）：

  1. REQUIRED（默认）：有则加入，无则新建。最常用。
  2. REQUIRES_NEW：挂起当前，新建事务。内部和外部事务独立。
  3. SUPPORTS：有则加入，无则非事务运行。
  4. NOT_SUPPORTED：非事务运行，挂起当前事务。
  5. MANDATORY：必须有事务，无则抛异常。
  6. NEVER：必须非事务，有则抛异常。
  7. NESTED：嵌套事务，内部事务依赖外部事务（savepoint回滚）。

💡 REQUIRES_NEW完全独立，外部回滚不影响内部；NESTED外部回滚会回滚内部。

Spring 事件监听机制？
Spring事件

基于观察者模式，三个核心角色：

  • 事件：ApplicationEvent（如ContextRefreshedEvent）。
  • 发布者：ApplicationEventPublisher（ApplicationContext实现了）。
  • 监听者：ApplicationListener（或用@EventListener注解）。

默认同步执行，可通过@Async+@EnableAsync实现异步事件。

Spring Boot Starter 原理？如何自定义Starter？
Starter

原理：Spring Boot通过@EnableAutoConfiguration扫描引入的Starter，Conditional条件判断，自动装配Bean。

自定义Starter步骤：

  1. 创建autoconfigure模块：写配置类+Properties类。
  2. 在META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports中注册配置类。
  3. 创建starter模块：只含pom.xml，引入autoconfigure模块。
  4. 使用者只需引入starter依赖，配置yml即可自动装配。

Spring AOP 的原理？JDK代理和CGLIB代理的区别？
AOP高频

AOP基于动态代理，在BeanPostProcessor.postProcessAfterInitialization中创建代理。

JDK动态代理：

  • 目标类必须实现接口。
  • 基于反射+接口，生成Proxy$类。
  • 性能略低（反射调用）。

CGLIB代理：

  • 基于ASM字节码，生成子类。
  • 不需要接口，但不能代理final类/方法。
  • 性能略高（直接方法调用）。

💡 Spring Boot 2.x默认使用CGLIB。@EnableAspectJAutoProxy(proxyTargetClass=true)强制CGLIB。

@Configuration 和 @Component 的区别？full模式和lite模式？
SpringBean

@Configuration（full模式）：通过CGLIB增强，确保@Bean方法内部调用仍然走容器（单例）。

@Component（lite模式）：不走CGLIB代理，内部调用@Bean方法会创建新实例。

@Configuration // full模式
public class Config {
    @Bean A a() { return new A(b()); } // b()走代理，同一实例
    @Bean B b() { return new B(); }
}
@Component // lite模式
// a()中b()不会走代理，new新B()
