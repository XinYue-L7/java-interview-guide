手写快速排序，并说明它的复杂度与稳定性？
排序分治高频

1. 核心思想（分治 + 分区）：

  • 从数组中挑一个元素作为基准（pivot）。
  • partition（分区）：把小于基准的放左边，大于基准的放右边，基准落到最终有序位置。
  • 对左右两个子区间递归执行同样操作，直到区间长度 ≤ 1。

2. 复杂度：

  • 平均 O(n log n)：每次划分大致对半，递归深度 log n，每层总比较 n 次。
  • 最坏 O(n²)：数组已有序且总取首/尾元素为基准，每次划分只减少一个元素，退化成冒泡。工程上用随机取基准或三数取中规避。
  • 空间 O(log n)：递归调用栈；最坏 O(n)。属于原地排序（不需额外数组）。

3. 稳定性：不稳定。分区时的交换（如 Hoare 双指针交换）会跨越多个位置搬运元素，可能把相等元素的相对顺序打乱。例如 [2a, 1, 2b] 分区后可能变成 [1, 2b, 2a]。

4. Java 代码（Lomuto 分区 + 随机基准）：

public static void quickSort(int[] a, int l, int r) { if (l >= r) return; // 随机基准：打乱后把基准换到最右，避免有序数组退化 int k = l + (int)(Math.random() * (r - l + 1)); swap(a, k, r); int pivot = a[r], i = l; // i 指向"小于基准区"的下一个位置 for (int j = l; j < r; j++) { if (a[j] < pivot) swap(a, i++, j); } swap(a, i, r); // 基准归位 quickSort(a, l, i - 1); quickSort(a, i + 1, r); } private static void swap(int[] a, int i, int j) { if (i != j) { int t = a[i]; a[i] = a[j]; a[j] = t; } }

5. 面试常追问：

  • Arrays.sort() 用的什么？基本类型用双轴快排（Dual-Pivot QuickSort），对象数组用 TimSort（归并 + 插入的优化，稳定）。
  • 为什么基本类型不用归并？快排原地、常数小、缓存友好；基本类型没有稳定性诉求。
  • 如何优化？小区间（< 47）切换插入排序；三数取中选基准；递归深度过大时转堆排（这正是 introsort 的做法）。

归并排序的思路与复杂度？它和快排有什么区别？
排序分治高频

1. 核心思想（分治 + 合并）：

  • 分：把数组对半拆成两个子数组，递归拆分到长度为 1（天然有序）。
  • 治（merge）：用双指针把两个已有序的子数组按序合并到一个临时数组，再拷回原数组。

2. 复杂度：

  • 时间 O(n log n)：递归深度 log n，每层合并总代价 O(n)。最好/最坏/平均都是 O(n log n)——这是它相对快排最大的优势（性能可预期）。
  • 空间 O(n)：需要一个辅助数组（这是它相对快排最大的劣势）。
  • 稳定：合并时相等元素优先取左边，相对顺序不变。

3. Java 代码：

public static void mergeSort(int[] a, int l, int r, int[] tmp) { if (l >= r) return; int mid = l + (r - l) / 2; // 防溢出的写法 mergeSort(a, l, mid, tmp); mergeSort(a, mid + 1, r, tmp); int i = l, j = mid + 1, k = l; while (i <= mid && j <= r) { tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++]; // <= 保证稳定性 } while (i <= mid) tmp[k++] = a[i++]; while (j <= r) tmp[k++] = a[j++]; for (int p = l; p <= r; p++) a[p] = tmp[p]; }

4. 与快排对比：

  • 快排原地、常数小、平均快，但最坏 O(n²) 且不稳定；归并稳定、最坏也是 O(n log n)，但需 O(n) 额外空间。
  • 归并的合并过程是顺序访问，非常适合链表排序（链表快排反而难写）和外部排序（大文件排序，无法一次性载入内存）。
  • Java 对象数组的 Arrays.sort() 用 TimSort，本质就是归并思想的工程优化版。

5. 典型追问：如何求数组中的逆序对？在 merge 的比较阶段统计：当 a[i] > a[j] 时，左边剩余 mid - i + 1 个元素都与 a[j] 构成逆序对，累加即可，整体仍是 O(n log n)。

堆排序是怎么做的？如何用它求 TopK？
排序堆高频

1. 堆的性质：完全二叉树，用数组存储。下标 i 的左右孩子为 2i+1、2i+2，父节点为 (i-1)/2。大顶堆：每个节点 ≥ 其孩子，堆顶是最大值。

2. 堆排序两步：

  • 建堆：从最后一个非叶子节点 (n/2 - 1) 开始向前做 siftDown，O(n)。
  • 排序：重复 n-1 次"把堆顶（最大值）与末尾元素交换，堆长度减 1，再对堆顶 siftDown"，最终得到升序数组。每次 siftDown O(log n)，共 O(n log n)。

3. 复杂度：时间 O(n log n)（建堆 O(n) + 排序 O(n log n)）；空间 O(1)；不稳定。

4. Java 代码：

public static void heapSort(int[] a) { int n = a.length; for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n); // 建大顶堆 for (int end = n - 1; end > 0; end--) { swap(a, 0, end); // 堆顶最大值换到末尾 siftDown(a, 0, end); // 对剩余 [0,end) 重新下沉 } } private static void siftDown(int[] a, int i, int len) { while (true) { int l = 2 * i + 1, r = l + 1, max = i; if (l < len && a[l] > a[max]) max = l; if (r < len && a[r] > a[max]) max = r; if (max == i) break; swap(a, i, max); i = max; } }

5. TopK 问题（海量数据场景必考）：

求最大的 K 个元素，不要整体排序，用容量为 K 的小顶堆：

  • 遍历数据，堆不满 K 个就入堆；堆满后，若当前元素 > 堆顶，则弹出堆顶、压入当前元素（堆顶始终是堆中最小的，也就是"K 大的门槛"）。
  • 遍历完，堆里的 K 个元素就是最大的 K 个。
  • 复杂度 O(n log K)，空间 O(K)——10 亿数据里找 Top100 也只占 100 个元素的内存。
// Java 直接用 PriorityQueue（默认小顶堆） PriorityQueue<Integer> heap = new PriorityQueue<>(); for (int x : data) { if (heap.size() < k) heap.offer(x); else if (x > heap.peek()) { heap.poll(); heap.offer(x); } } // heap 中即为最大的 k 个元素（堆顶是其中最小的）

6. 常见变体：求第 K 大 / 第 K 小，也可用快排 partition（快速选择），平均 O(n)，但会改动原数组且最坏 O(n²)，工程上更推荐堆。

二分查找怎么写才不出错？有哪些常见变体？
查找双指针高频

1. 前提：数组有序（通常是升序）且支持随机访问。核心是每次排除一半区间，复杂度 O(log n)。

2. 防错三板斧（面试最常挂在这）：

  • mid 防溢出：int mid = left + (right - left) / 2; 而不是 (left + right) / 2。
  • 循环条件用 left <= right，配套收缩为 right = mid - 1 / left = mid + 1（闭区间写法，最不容易错）。
  • 明确区间定义并全程保持一致：要么全用闭区间 [left, right]，要么全用左闭右开 [left, right)。

3. 标准写法（闭区间）：

public static int binarySearch(int[] a, int target) { int l = 0, r = a.length - 1; while (l <= r) { int mid = l + (r - l) / 2; // 防溢出 if (a[mid] == target) return mid; else if (a[mid] < target) l = mid + 1; else r = mid - 1; } return -1; }

4. 常见变体（左闭右开，找左边界）：

// 返回第一个 >= target 的下标（lower_bound）；不存在则返回 a.length public static int lowerBound(int[] a, int target) { int l = 0, r = a.length; // 注意：右开区间，r 取 length while (l < r) { // 注意：无等号 int mid = l + (r - l) / 2; if (a[mid] >= target) r = mid; // 不减 1，保留 mid 作为候选 else l = mid + 1; } return l; // l == r，插入位置 }
  • 找左边界（第一个等于 target）：lowerBound(a, target)，再判断下标是否越界且值是否相等。
  • 找右边界（最后一个等于 target）：lowerBound(a, target + 1) - 1（整数场景）。
  • 旋转数组找最小值：比较 a[mid] 与 a[r]，判断最小值落在哪半边。

5. 进阶：二分答案。不只在数组上二分，也可在答案区间上二分 + 判定函数（如"木头切割""最小运输能力""第 K 小"类问题），把求最优解转成判定可行性，复杂度 O(logRange × check)。

如何找出数组中第 K 大的元素？（TopK / 快速选择）
排序分治高频

1. 三种解法与取舍：

  • 排序后取下标：O(n log n)，最简单，数据量小时直接用。
  • 小顶堆（推荐，尤其海量数据 / 流式数据）：维护容量 K 的堆，O(n log K)、空间 O(K)。数据无法一次性载入内存时也适用。
  • 快速选择 QuickSelect（平均 O(n)）：基于快排 partition，但每次只递归一边。

2. 快速选择的思路：

partition 后基准落在下标 p。目标下标是 n - K（第 K 大即升序第 n-K 位）：

  • p == n - K → 找到了，直接返回。
  • p < n - K → 目标在右半边，只递归右边。
  • p > n - K → 只递归左边。

平均每次排除一半，总比较次数 n + n/2 + n/4 + ... ≈ 2n，即 O(n)；最坏 O(n²)（可用随机基准规避）。

3. Java 代码：

public static int findKthLargest(int[] a, int k) { int target = a.length - k; // 第 k 大在升序数组中的下标 int l = 0, r = a.length - 1; while (l <= r) { int p = partition(a, l, r); if (p == target) return a[p]; else if (p < target) l = p + 1; else r = p - 1; } return -1; } private static int partition(int[] a, int l, int r) { int k = l + (int)(Math.random() * (r - l + 1)); swap(a, k, r); int pivot = a[r], i = l; for (int j = l; j < r; j++) if (a[j] <= pivot) swap(a, i++, j); swap(a, i, r); return i; }

4. 面试怎么答：数据量小直接说排序；数据量大 / 内存受限 / 流式必定答小顶堆；追求理论最优、且能改动原数组时用快速选择。若 K 很小而 n 极大（如 10 亿中取 Top10），堆法优势最明显。

两数之和：有序数组怎么用双指针做？和哈希解法有什么区别？
双指针哈希高频

1. 有序数组 → 对撞双指针（O(n) 时间、O(1) 空间）：

  • left 指向最小元素，right 指向最大元素。
  • sum 太小 → left++（增大和）；sum 太大 → right--（减小和）。
  • 关键在于单调性：因为数组有序，移动指针能确定性地逼近目标，不会漏解。
public static int[] twoSum(int[] a, int target) { // a 已升序 int l = 0, r = a.length - 1; while (l < r) { int sum = a[l] + a[r]; if (sum == target) return new int[]{l + 1, r + 1}; // 题目要求 1-based else if (sum < target) l++; else r--; } return new int[]{-1, -1}; }

2. 无序数组 → 哈希表（O(n) 时间、O(n) 空间）：

边遍历边查表：对每个 x，先查 target - x 是否已在表中，命中即返回；否则把 x 存入表。一次遍历，避免了"先全量建表"的两次循环。

public static int[] twoSumHash(int[] a, int target) { Map<Integer, Integer> seen = new HashMap<>(); for (int i = 0; i < a.length; i++) { int need = target - a[i]; if (seen.containsKey(need)) return new int[]{seen.get(need), i}; seen.put(a[i], i); } return new int[]{-1, -1}; }

3. 两者取舍：

  • 数组已排序 → 双指针，O(1) 额外空间，还能顺便处理"返回所有配对"。
  • 数组无序 → 哈希法 O(n)；若先排序再用双指针则是 O(n log n)，但省空间且便于去重。
  • 要求返回所有不重复的数对时，排序 + 双指针更好写（跳过相邻重复元素去重）。

三数之和（3Sum）怎么做？如何去重？
双指针排序高频

1. 思路：排序 + 固定一个数 + 双指针（O(n²)）：

  • 先排序。
  • 枚举 i 作为第一个数，在 [i+1, n-1] 区间用对撞双指针找和为 -a[i] 的两个数。
  • 三层循环会到 O(n³)，用双指针把 innermost 降为 O(n)。

2. 去重（关键扣分点）：

  • 枚举 i 时：if (i > 0 && a[i] == a[i-1]) continue; 跳过重复的基准数。
  • 命中一组解后：l++、r-- 的同时跳过所有与当前值相同的元素，避免重复三元组。
  • 另外可剪枝：a[i] > 0 时直接 break（排序后三数都 ≥ a[i] > 0，和不可能为 0）。

3. Java 代码：

public static List<List<Integer>> threeSum(int[] nums) { List<List<Integer>> res = new ArrayList<>(); Arrays.sort(nums); for (int i = 0; i < nums.length - 2; i++) { if (i > 0 && nums[i] == nums[i - 1]) continue; // 基准去重 if (nums[i] > 0) break; // 剪枝 int l = i + 1, r = nums.length - 1; while (l < r) { int sum = nums[i] + nums[l] + nums[r]; if (sum == 0) { res.add(Arrays.asList(nums[i], nums[l], nums[r])); while (l < r && nums[l] == nums[l + 1]) l++; // 左去重 while (l < r && nums[r] == nums[r - 1]) r--; // 右去重 l++; r--; } else if (sum < 0) l++; else r--; } } return res; }

4. 复杂度：时间 O(n²)（排序 O(n log n) 被覆盖），空间 O(1)（不计返回值；若排序用快排会改动原数组）。

5. 扩展：4Sum 就是多套一层循环 + 双指针，O(n³)；更一般的 kSum 可递归降维，最后都落到 2Sum 双指针。全部都要注意去重 + 剪枝。

滑动窗口：如何求"无重复字符的最长子串"？
滑动窗口字符串高频

1. 滑动窗口适用场景：求连续子数组/子串的最值（最长、最短、和最大等），且窗口左右端只增不减时，可把 O(n²) 枚举降到 O(n)。

2. 思路（维护一个始终无重复的窗口 [l, r]）：

  • 右指针 r 逐个字符右移，把字符最近一次出现的下标记入哈希表/数组。
  • 若新字符已在窗口内（last[c] >= l），说明出现重复，把左边界 l 直接跳到 last[c] + 1（不能只 +1，否则窗口内仍有重复）。
  • 每次更新 ans = max(ans, r - l + 1)。

3. Java 代码：

public static int lengthOfLongestSubstring(String s) { int[] last = new int[128]; // ASCII 字符 → 最近下标+1，0 表示未出现 int ans = 0, l = 0; for (int r = 0; r < s.length(); r++) { char c = s.charAt(r); if (last[c] > l) l = last[c]; // 窗口内重复 → 左边界右移 last[c] = r + 1; ans = Math.max(ans, r - l + 1); } return ans; }

4. 复杂度：时间 O(n)，每个字符最多进出窗口一次；空间 O(min(n, 字符集大小))。

5. 同类模板（面试高频）：

  • 最小覆盖子串：用 need/window 两个计数 map + 一个 valid 计数器判断窗口是否覆盖。
  • 长度最小的子数组（和 ≥ target）：先累加右端，满足时循环收缩左端更新最小值。
  • 找所有字母异位词：定长窗口 + 计数比较。

通用模板：for r: 扩大窗口 → while(窗口不满足/满足条件) 收缩左端 → 更新答案。记住"右端扩张，左端收缩"这个节奏就不会乱。

如何反转单链表？（迭代与递归两种写法）
链表高频

1. 迭代法（推荐，O(n) 时间 O(1) 空间）：

维护 prev（已反转部分的头）和 cur（待处理节点）。每步先用 next 暂存后继（否则断链后找不到），再把 cur.next 指向 prev，然后整体右移。

public static ListNode reverse(ListNode head) { ListNode prev = null, cur = head; while (cur != null) { ListNode next = cur.next; // 1. 暂存后继 cur.next = prev; // 2. 反转指针 prev = cur; // 3. prev 前进 cur = next; // 4. cur 前进 } return prev; // prev 即新头节点 }

2. 递归法（代码短但栈深 O(n)，链表长时可能 StackOverflow）：

public static ListNode reverseRec(ListNode head) { if (head == null || head.next == null) return head; ListNode newHead = reverseRec(head.next); // 先反转后半段 head.next.next = head; // 让后继指回自己 head.next = null; // 断开原指针，防止成环 return newHead; }

3. 易错点：

  • 必须先存 next 再改 cur.next，否则链表断裂。
  • 递归写法最后一定要 head.next = null，否则首尾会形成环。
  • 返回的是 prev（原尾节点），不是 head。

4. 常见变体（同一套模板）：

  • 反转前 N 个节点：递归到 N，记录第 N+1 个节点做「后继锚点」，再把 head.next 接回去。
  • 反转区间 [m, n]：先走 m-1 步找到前置节点，再对区间做局部反转。
  • K 个一组反转：每 K 个调用区间反转，注意组与组的连接（prevGroupTail）。
  • 判断回文链表：快慢指针找中点 + 反转后半段 + 逐位比较（进阶要求 O(1) 空间）。

如何判断链表是否有环？如何找到入环的第一个节点？
链表快慢指针高频

1. 快慢指针（Floyd 判圈）：

  • slow 每次走 1 步，fast 每次走 2 步。
  • 若无环，fast 会先到 null；若有环，两者必定在环内相遇（相对速度 1，fast 必然追上 slow）。
  • 时间 O(n)，空间 O(1)。用 HashSet 也能做但要 O(n) 空间。

2. 找入环点（关键结论）：

相遇后，把 其中一个指针移回头节点，另一个留在相遇点，两者改为每次各走 1 步，再次相遇的位置就是入环的第一个节点。

推导：设头到入环点距离 a，入环点到相遇点距离 b，相遇点再走到入环点距离 c。相遇时 slow 走 a+b，fast 走 a+b+c+b（多绕一圈），且 fast 路程是 slow 的 2 倍 → 2(a+b) = a+2b+c → a = c。所以从头走 a 步与从相遇点走 c 步会同时抵达入环点。

3. Java 代码：

public static ListNode detectCycle(ListNode head) { ListNode slow = head, fast = head; while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; if (slow == fast) { // 相遇，有环 ListNode p = head; // 一个回到头节点 while (p != slow) { p = p.next; slow = slow.next; } // 同步前进 return p; // 入环点 } } return null; // 无环 }

4. 易错点：

  • 循环条件要同时判断 fast != null 和 fast.next != null，否则 fast.next.next 会 NPE。
  • 判断有环用 slow == fast（引用比较），链表节点未重写 equals 时不可用 equals。
  • 求环长：相遇后固定一个不动，另一个继续走并计数，再次回到该点时的步数即环长。

如何合并两个有序链表？如何合并 K 个有序链表？
链表分治高频

1. 两个有序链表（迭代，O(n+m) 时间 O(1) 空间）：

用哨兵节点（dummy）统一处理"头节点不确定"的问题：每次取较小的节点接到 tail 后面，最后把剩余段整体接上。

public static ListNode mergeTwo(ListNode a, ListNode b) { ListNode dummy = new ListNode(0), tail = dummy; while (a != null && b != null) { if (a.val <= b.val) { tail.next = a; a = a.next; } else { tail.next = b; b = b.next; } tail = tail.next; } tail.next = (a != null) ? a : b; // 接上剩余段 return dummy.next; }

2. K 个有序链表 —— 两种解法：

  • 小顶堆（优先队列）：把每个链表的头节点入堆，每次弹出最小节点接到结果上，再把该节点的下一个入堆。
    复杂度 O(N log K)（N 为总节点数），空间 O(K)。适合链表数量多、需要流式输出的场景。
  • 分治两两合并：像归并排序一样，把 K 个链表两两配对合并，轮轮减半。
    复杂度同样是 O(N log K)，空间 O(1)（复用原节点），无需额外数据结构。
// 归并分治 public static ListNode mergeKLists(ListNode[] lists) { if (lists == null || lists.length == 0) return null; int n = lists.length; while (n > 1) { // 每轮两两合并，数量减半 for (int i = 0; i < n / 2; i++) lists[i] = mergeTwo(lists[i], lists[n - 1 - i]); n = (n + 1) / 2; } return lists[0]; }

3. 面试提示：分治法体现了归并思想，和"合并 K 个有序数组""多路归并排序"是同一类问题；若追问"外部排序 / 大文件归并"，思路完全一样，只是 IO 换成文件流。

如何手写一个 LRU 缓存？
设计题哈希高频

1. LRU（Least Recently Used）：容量满时淘汰最久未使用的数据。要求 get 和 put 都 O(1)。

2. 数据结构选型（核心考点）：

  • 哈希表：O(1) 定位节点（key → node）。
  • 双向链表：O(1) 删除与插入。用双向是因为删除节点需要拿到前驱，单链表删除是 O(n)。
  • 约定顺序：链表头部是最近使用，尾部是最久未使用。访问/新增放头，淘汰删尾。
  • 用 dummy head / tail 哨兵，省掉各种空指针边界判断。

3. Java 代码：

class LRUCache { class Node { int k, v; Node prev, next; Node(int k, int v) { this.k = k; this.v = v; } } private final int cap; private final Map<Integer, Node> map = new HashMap<>(); private final Node head = new Node(0, 0); // 哨兵头（最近使用侧） private final Node tail = new Node(0, 0); // 哨兵尾（最久未使用侧） public LRUCache(int capacity) { this.cap = capacity; head.next = tail; tail.prev = head; } public int get(int key) { Node n = map.get(key); if (n == null) return -1; moveToHead(n); // 访问即"最近使用" return n.v; } public void put(int key, int value) { Node n = map.get(key); if (n != null) { n.v = value; moveToHead(n); return; } Node node = new Node(key, value); map.put(key, node); addAfterHead(node); if (map.size() > cap) { // 超容量：淘汰尾部 Node last = tail.prev; remove(last); map.remove(last.k); // 别忘同步删 map } } private void moveToHead(Node n) { remove(n); addAfterHead(n); } private void remove(Node n) { n.prev.next = n.next; n.next.prev = n.prev; } private void addAfterHead(Node n) { n.prev = head; n.next = head.next; head.next.prev = n; head.next = n; } }

4. 面试加分点：

  • Java 一行实现：new LinkedHashMap<>(cap, 0.75f, true) —— 第三个参数 accessOrder=true 即 LRU，重写 removeEldestEntry 即可限制容量。
  • 缺点与改进：朴素 LRU 会被批量扫描污染（一次性把热点数据挤掉）。工业级实现有 LRU-K、2Q，MySQL InnoDB 用的是改进 LRU（分 young/old 区 + 停留时间阈值）。
  • 并发场景：全局加锁会成为瓶颈，Caffeine 采用分段 + 环形缓冲区异步回放实现高并发近似 LRU（W-TinyLFU）。

二叉树的层序遍历（BFS）怎么写？有哪些常见变体？
树BFS高频

1. 思路：用队列。根节点入队；每次出队一个节点就访问它，并把其左右孩子入队。队列 FIFO 的特性天然保证"按层从左到右"访问。

2. 分层输出的关键：每层开始前先记录当前队列长度 size，只循环 size 次，这样就能把同一层的节点归到一组。

3. Java 代码（分层返回）：

public static List<List<Integer>> levelOrder(TreeNode root) { List<List<Integer>> res = new ArrayList<>(); if (root == null) return res; Queue<TreeNode> q = new LinkedList<>(); q.offer(root); while (!q.isEmpty()) { int size = q.size(); // 当前层的节点数 List<Integer> level = new ArrayList<>(); for (int i = 0; i < size; i++) { TreeNode n = q.poll(); level.add(n.val); if (n.left != null) q.offer(n.left); if (n.right != null) q.offer(n.right); } res.add(level); } return res; }

4. 复杂度：时间 O(n)，空间 O(n)（队列最宽处约为树的最大层宽，最坏 O(n)）。

5. 常见变体（都用同一套模板改）：

  • 自底向上层序：每层结果 res.add(0, level)（或最后 reverse）。
  • 锯齿形（之字形）遍历：用 LinkedList 双端队列，偶数层 addLast、奇数层 addFirst；或正常收集后按层号奇偶 reverse。
  • 每层最大值 / 层平均值：在 size 循环内取 max / 累加。
  • 二叉树最大/最小深度：BFS 层数即最小深度；也可 DFS 递归。
  • 填充右侧指针（next）：在 size 循环里把前一个节点的 next 指向当前节点，最后一个指向 null。

6. DFS vs BFS 怎么选：求最短路径/最少步数/按层处理用 BFS；求所有路径、是否满足条件、深度相关用 DFS（递归更简洁）。递归 DFS 要注意树退化成链时栈溢出。

如何求二叉树的最近公共祖先（LCA）？
树递归高频

1. 后序遍历 + 递归（O(n) 时间、O(h) 空间）：

对节点 root 而言，p、q 的位置只有三种情况：

  • 分别在左右子树 → root 就是 LCA。
  • 都在同一侧子树 → LCA 在那一侧，返回该侧的递归结果。
  • root 本身就是 p 或 q → 直接返回 root（另一节点必在其子树中）。
public static TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) { if (root == null || root == p || root == q) return root; // 基线 TreeNode left = lowestCommonAncestor(root.left, p, q); TreeNode right = lowestCommonAncestor(root.right, p, q); if (left != null && right != null) return root; // 分居两侧 return (left != null) ? left : right; // 都在一侧 / 都没找到 }

2. 为什么是后序遍历？因为判断"是否分居两侧"必须先拿到左右子树的结果，即"左右中"的顺序 —— 这是典型的后序位置利用子树返回值。

3. 变体一：二叉搜索树（BST）的 LCA（更优 O(h)）：

利用 BST 有序性：p.val 和 q.val 都小于 root → 去左子树；都大于 → 去右子树；一大一小（或其一等于 root）→ root 即为 LCA。可用迭代，无需递归。

public static TreeNode lcaBST(TreeNode root, TreeNode p, TreeNode q) { while (root != null) { if (p.val < root.val && q.val < root.val) root = root.left; else if (p.val > root.val && q.val > root.val) root = root.right; else return root; // 分叉点 } return null; }

4. 变体二：节点带父指针 / 普通树：转化为两个链表求交点——先分别走到根算出深度，深的先走差值步，再同步前进，第一个相同节点即 LCA（同链表相交的双指针法）。

5. 注意：若题目不保证 p、q 都存在于树中，需要额外做一次存在性校验（递归统计命中次数），否则可能返回错误结果。面试时先问清这一点。

动态规划入门：0-1 背包问题怎么解？如何做空间优化？
动态规划背包高频

1. 问题：N 个物品，重量 w[i]、价值 v[i]，背包容量 W，每个物品只能选一次，求最大价值。

2. 动规五步：

  • 状态定义：dp[i][c] = 只考虑前 i 个物品、容量为 c 时的最大价值。
  • 状态转移：对第 i 个物品，不选 → dp[i-1][c]；选（需 c ≥ w[i]）→ dp[i-1][c-w[i]] + v[i]。取 max：
    dp[i][c] = max(dp[i-1][c], dp[i-1][c-w[i]] + v[i])
  • 初始化：dp[0][*] = 0（无物品价值为 0），其余默认 0。
  • 遍历顺序：i 从 1 到 N，c 从 0 到 W（本题两层顺序可交换）。
  • 答案：dp[N][W]。

3. 空间优化（一维滚动数组，必考）：

因为 dp[i] 只依赖 dp[i-1]，可压缩成一维 dp[c]。但此时容量 c 必须倒序遍历（从 W 到 w[i]），否则同一物品会被重复选取，退化成完全背包。

// 一维优化：c 必须倒序（0-1 背包） public static int knapsack(int[] w, int[] v, int W) { int[] dp = new int[W + 1]; for (int i = 0; i < w.length; i++) { for (int c = W; c >= w[i]; c--) { // 倒序！正序会变成完全背包 dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]); } } return dp[W]; }

4. 复杂度：时间 O(N × W)，空间 O(W)。注意这是伪多项式复杂度，容量很大时不可行。

5. 三种背包对比（面试高频追问）：

  • 0-1 背包（每个物品 1 个）：容量倒序遍历。
  • 完全背包（物品无限个）：容量正序遍历。
  • 多重背包（每个物品 s[i] 个）：二进制拆分（1,2,4...）转成 0-1 背包，或单调队列优化到 O(N×W)。

6. 常见变体："能否装满容量 W"（boolean dp）、"恰好装满的方案数"（dp[0]=1，求 dp[W]）、"输出具体选了哪些物品"（记录 choice 数组回溯）。

最长递增子序列（LIS）：O(n²) 与 O(n log n) 两种解法？
动态规划二分高频

1. 解法一：动态规划 O(n²)：

  • dp[i] = 以 nums[i] 结尾的 LIS 长度（注意定义必须"以 i 结尾"，否则无法转移）。
  • 转移：dp[i] = max(dp[j] + 1)，其中 j < i 且 nums[j] < nums[i]；都不满足则 dp[i] = 1。
  • 答案是 max(dp)，不是 dp[n-1]。
public static int lisDP(int[] nums) { int[] dp = new int[nums.length]; int ans = 0; for (int i = 0; i < nums.length; i++) { dp[i] = 1; // 至少包含自己 for (int j = 0; j < i; j++) if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1); ans = Math.max(ans, dp[i]); } return ans; }

2. 解法二：贪心 + 二分 O(n log n)（加分项）：

维护数组 tails，tails[k] 表示长度为 k+1 的递增子序列的最小结尾元素。tails 始终保持递增：

  • 新元素 x 用二分找到 tails 中第一个 ≥ x 的位置并替换（让结尾尽可能小，给后面留空间）。
  • 若 x 比所有元素都大，则追加到末尾，LIS 长度 +1。
public static int lisBinary(int[] nums) { int[] tails = new int[nums.length]; int len = 0; for (int x : nums) { int l = 0, r = len; // 在 tails[0..len) 中找 lower_bound(x) while (l < r) { int m = l + (r - l) / 2; if (tails[m] < x) l = m + 1; else r = m; } tails[l] = x; if (l == len) len++; // 接在末尾 → 长度增加 } return len; }

3. 注意：二分法得到的 tails 不一定是一条真实的子序列，只有长度是正确；需要输出具体序列时要记录前驱（prevIndex 数组）还原。

4. 变体：最长非递减子序列用 lower_bound(> x)（即第一个 > x 的位置）；"俄罗斯套娃信封"先按一维升序、同值按另一维降序排序，再套 LIS。

最长公共子序列（LCS）怎么求？和最长公共子串有什么区别？
动态规划字符串高频

1. 区别：

  • 子序列（Subsequence）：可不连续，但保持相对顺序。
  • 子串（Substring）：必须连续。

2. LCS 状态与转移：

  • dp[i][j] = a[0..i) 与 b[0..j) 的 LCS 长度。
  • 若 a[i-1] == b[j-1] → dp[i][j] = dp[i-1][j-1] + 1。
  • 否则 → dp[i][j] = max(dp[i-1][j], dp[i][j-1])（丢弃 a 末尾或 b 末尾）。
  • 答案 dp[m][n]。
public static int lcs(String a, String b) { int m = a.length(), n = b.length(); int[][] dp = new int[m + 1][n + 1]; for (int i = 1; i <= m; i++) for (int j = 1; j <= n; j++) dp[i][j] = (a.charAt(i - 1) == b.charAt(j - 1)) ? dp[i - 1][j - 1] + 1 : Math.max(dp[i - 1][j], dp[i][j - 1]); return dp[m][n]; }

3. 最长公共子串（续接 vs 归零）：转移中不相等时直接置 0（因为必须连续），并沿途记录最大值。

int[][] dp = new int[m + 1][n + 1]; int ans = 0; for (int i = 1; i <= m; i++) for (int j = 1; j <= n; j++) { if (a.charAt(i - 1) == b.charAt(j - 1)) dp[i][j] = dp[i - 1][j - 1] + 1; else dp[i][j] = 0; // 断开，不能继承 ans = Math.max(ans, dp[i][j]); }

4. 复杂度：均为 O(mn) 时间；空间 O(mn)，可滚动数组优化到 O(min(m,n))（LCS 需保留对角线 dp[i-1][j-1]，要用变量 prev 暂存）。

5. 应用：diff 工具、Git 的差异比对、编辑距离（Levenshtein Distance，转移多一个"替换"分支）、DNA 序列比对，本质都是同一族二维 DP。

回溯算法：如何求全排列？模板是什么？
回溯DFS高频

1. 回溯本质：在决策树上做 DFS。做选择 → 递归 → 撤销选择。"撤销"（恢复现场）是回溯区别于普通递归的关键。

2. 通用模板：

void backtrack(路径, 选择列表) { if (满足结束条件) { 结果.add(路径的拷贝); return; } for (选择 : 选择列表) { if (不合法 / 已使用) continue; // 剪枝 做选择; // path.add + 标记 used backtrack(路径, 选择列表); // 递归 撤销选择; // path.remove + 清除 used } }

3. 全排列（含去重，处理重复元素）：

public static List<List<Integer>> permuteUnique(int[] nums) { List<List<Integer>> res = new ArrayList<>(); boolean[] used = new boolean[nums.length]; Arrays.sort(nums); // 排序是去重前提 dfs(nums, used, new ArrayList<>(), res); return res; } private static void dfs(int[] nums, boolean[] used, List<Integer> path, List<List<Integer>> res) { if (path.size() == nums.length) { res.add(new ArrayList<>(path)); return; } for (int i = 0; i < nums.length; i++) { if (used[i]) continue; // 去重：同一层里，重复元素只允许用第一个（前一个相等且未被使用 → 跳过） if (i > 0 && nums[i] == nums[i - 1] && !used[i - 1]) continue; used[i] = true; path.add(nums[i]); dfs(nums, used, path, res); path.remove(path.size() - 1); used[i] = false; // 撤销 } }

4. 复杂度：全排列 O(n × n!)（共 n! 个解，每个拷贝 O(n)）；子集 O(n × 2ⁿ)；组合 C(n,k)。

5. 去重原理（高频追问）：!used[i-1] 为什么这么写？它区分了同一层与同一树枝：used[i-1] == false 表示前一个相同元素在本层已尝试并回溯过（属于同一层的重复分支）→ 跳过；used[i-1] == true 表示前一个相同元素正在当前路径上使用（不同深度，是合法的不同位置）→ 保留。

6. 同类问题：子集、组合、组合总和、N 皇后、括号生成、分割回文串、解数独 —— 全都套这个模板，区分点只在"选择列表的起始下标 start"（组合类用 start 推进避免重复，排列类每次从 0 开始配 used）。

接雨水问题：双指针和单调栈两种解法？
双指针单调栈高频

1. 核心观察：位置 i 能接的雨水量 = min(左侧最高 maxL, 右侧最高 maxR) - height[i]（结果 ≥ 0 才计入）。

2. 解法一：双指针（最优，O(n) 时间 O(1) 空间）：

  • left/right 从两端向中间靠拢，并维护 maxL、maxR。
  • 每轮处理较矮的那一侧：因为木桶效应，只要另一侧存在更高的柱子，当前侧的积水就由 maxL 决定。
  • 若 maxL < maxR → 结算左指针位置：ans += maxL - h[l]，然后 l++；反之结算右侧。
public static int trap(int[] h) { int l = 0, r = h.length - 1, maxL = 0, maxR = 0, ans = 0; while (l < r) { maxL = Math.max(maxL, h[l]); maxR = Math.max(maxR, h[r]); if (maxL < maxR) ans += maxL - h[l++]; // 左侧高度受 maxL 限制 else ans += maxR - h[r--]; // 右侧高度受 maxR 限制 } return ans; }

3. 解法二：单调栈（按"层"横向计算，O(n) 时间 O(n) 空间）：

维护递减栈（存下标）。当遇到 h[i] > h[栈顶] 时，说明形成了凹槽：弹出栈顶作为槽底，新的栈顶是左边界，i 是右边界，宽度 = i - left - 1，高度 = min(h[left], h[i]) - h[bottom]，累加。

public static int trapStack(int[] h) { Deque<Integer> st = new ArrayDeque<>(); int ans = 0; for (int i = 0; i < h.length; i++) { while (!st.isEmpty() && h[i] > h[st.peek()]) { int bottom = st.pop(); if (st.isEmpty()) break; // 没有左边界，接不住水 int left = st.peek(); ans += (Math.min(h[left], h[i]) - h[bottom]) * (i - left - 1); } st.push(i); } return ans; }

4. 怎么选：面试优先写双指针（更简洁、O(1) 空间）；若追问"按层计算 / 输出每段积水区间"，用单调栈。此外还有预处理前缀最大值数组的 O(n) 空间写法，最容易理解但不够优雅。

5. 单调栈的通用价值：专门解决"找某个元素左/右第一个比它大/小的元素"——每日温度、下一个更大元素、柱状图最大矩形，都是同一套模板。

海量数据问题：如何在 10 亿个数中找 TopK、去重、找中位数？
海量数据分治高频

核心思路都是"分而治之 + 哈希分流"，把单机内存装不下的问题拆成能装下的小问题。

1. TopK（最大 K 个）：

  • 单机能遍历、只需 TopK：容量为 K 的小顶堆，O(n log K)、内存 O(K)。
  • 数据量极大（TB 级）：先用 hash(x) % M 哈希分治到 M 台机器 / M 个文件，保证相同的值一定落在同一分片；各分片独立求自己的 TopK；最后对 M × K 个候选再求一次全局 TopK。
  • 数据有范围且分布均匀（如 0~65535 的整数）：用计数数组 / 桶，从大到小累加计数直到 K，O(n)。

2. 去重 / 统计出现次数：

  • 精确方案：hash(x) % M 分到 M 个文件，每个文件用 HashSet 去重，最后合并（同值必在同一文件，天然去重）。
  • 近似方案（省内存）：布隆过滤器，O(1) 空间/元素，但有假阳性（"存在"是可能），且不支持删除；需要删除用 Cuckoo Filter 或计数布隆过滤器。

3. 找中位数 / 第 K 小：

  • 范围已知且均匀：桶排序思想——先扫描一遍统计每个桶的元素个数，定位中位数落在哪个桶，再只对那个桶做排序/统计。两次扫描，内存 O(桶数)。
  • 范围未知：哈希分片后各片排序，再用多路归并（小顶堆）合并后取第 K 个；或各片返回自己的第 K 小候选后二次筛选。

4. 查两个大文件的交集 / 找只出现一次的数：同样哈希分治到同一编号的文件，再对每一对文件分别处理，避免全量载入。

5. 面试答题框架（照着说就很稳）：

  • 先估算内存：1 个 int 4 字节，10 亿个约 4GB，装不下 → 必须分治。
  • 再选分流函数：hash % M，M 由可用内存决定，强调"同值/同键必落同片"。
  • 然后分片内求解（堆、Set、排序、位图）。
  • 最后合并结果。
  • 如果允许近似，主动提布隆过滤器 / 位图 (BitMap) / HyperLogLog（Redis 的 HLL 做 UV 统计，12KB 内存统计 2⁶⁴ 量级基数，误差 0.81%）。
