CAP 理论是什么？BASE 理论呢？
分布式高频

CAP：三者最多满足两个

  • C(Consistency)：一致性，所有节点同一时刻数据相同。
  • A(Availability)：可用性，非故障节点正常响应。
  • P(Partition Tolerance)：分区容错性，网络分区时系统仍可工作。

P必须保证，所以实际是CP或AP的选择。Zookeeper→CP，Eureka→AP。

BASE：AP方案的补充

  • BA(Basically Available)：基本可用。
  • S(Soft State)：软状态，允许中间状态。
  • E(Eventually Consistent)：最终一致性。

什么是分布式事务？解决方案有哪些？
分布式事务

分布式事务是指事务的参与者、资源服务器、事务管理器分别位于不同分布式节点上。简单说，一个业务操作需要跨多个服务/数据库完成，且要保证数据一致性。例如：下单（订单服务）扣库存（库存服务）扣余额（账户服务），三步要么全成功、要么全回滚。

与单机事务的核心区别：单机事务靠数据库的 ACID 机制保证；分布式事务中网络不可靠、各节点独立，无法简单套用 ACID，需要额外的协调协议。

常见解决方案：

  • 2PC(两阶段提交)：准备阶段→提交阶段。强一致但性能差、协调者单点。
  • TCC(Try-Confirm-Cancel)：Try预留→Confirm确认→Cancel回滚。最终一致。
  • 本地消息表：本地事务+消息表，定时重试。最终一致。
  • RocketMQ事务消息：半消息+本地事务+回查。最终一致。
  • Seata：阿里分布式事务中间件，支持AT/TCC/Saga模式。

💡 大部分场景用最终一致性方案即可，强一致代价太高。

分布式 ID 生成方案有哪些？
分布式实战
  • UUID：简单但无序，作为主键时B+树分裂严重。
  • 数据库自增ID：单点瓶颈。
  • 数据库号段模式：一次获取一批ID，减少DB压力。
  • 雪花算法(Snowflake)：64位ID=时间戳+机器ID+序列号。趋势递增，最常用。
  • 美团Leaf、百度UidGenerator。

💡 雪花算法需注意时钟回拨问题。

什么是服务雪崩？如何解决？
微服务高频

服务雪崩：一个服务故障→调用方阻塞等待→调用方资源耗尽→级联故障→整个系统崩溃。

解决方案（Hystrix/Sentinel/Resilience4j）：

  • 熔断（Circuit Breaker）：错误率达标→快速失败→定期探测恢复。
  • 降级（Fallback）：备用逻辑（返回默认值/缓存/提示）。
  • 限流（Rate Limiter）：控制请求速率，超过则拒绝。
  • 隔离：线程池隔离/信号量隔离，避免资源争抢。
  • 超时：设置合理超时，快速释放资源。

Nacos 的 CAP 模型是怎样的？如何实现？
NacosCAP

Nacos同时作为注册中心和配置中心，支持AP和CP切换：

  • 注册中心：
  • 临时实例(live=true)：AP（Distro协议），宕机自动剔除。
  • 持久化实例(live=false)：CP（Raft协议），数据一致性优先。
  • 配置中心：CP（强一致），数据不能错。

ZooKeeper 的选举机制（ZAB协议）？
ZK选举

ZAB（ZooKeeper Atomic Broadcast）实现一致性：

Leader选举：

  • 节点状态：LOOKING→LEADING/FOLLOWING。
  • 比较规则：先比Epoch（任期）→再比ZXID（事务ID）→最后比SID（节点ID）。
  • 超过半数投票即当选。

数据同步：Leader将提案Proposal发给Followers→过半ACK→提交。

💡 ZK集群建议奇数台（3/5/7）。

分布式Session如何解决？
分布式Session
  • Session粘性（IP Hash）：Nginx ip_hash，同一用户固定到同一服务器（不推荐）。
  • Session复制：Tomcat Cluster，间节点复制（内存开销大）。
  • 集中存储（推荐）：Redis存储Session，Spring Session统一管理。
  • 无状态JWT：用Token替代Session（推荐）。

Seata 分布式事务的几种模式？
Seata分布式事务
  • AT模式（默认）：自动补偿，无侵入。需要undo_log表。基于全局锁+数据库本地事务隔离。
  • TCC模式：手动定义Try-Confirm-Cancel，性能高但编码复杂。
  • Saga模式：长事务，正向执行+反向补偿。适合老系统。
  • XA模式：数据库层面2PC，需数据库支持XA协议。

API 网关的作用和常见选型？
网关微服务

作用：统一入口、路由转发、鉴权认证、限流熔断、日志监控、灰度发布、协议转换。

常见选型：

  • Spring Cloud Gateway：响应式、非阻塞、Spring生态好。国内首选。
  • Zuul 2：Netflix，非阻塞。
  • Kong：基于OpenResty/Nginx，插件丰富。
  • Nginx+Lua/OpenResty：高性能、灵活。
