什么是 Cuckoo Filter（布谷鸟过滤器）？
概率型数据结构哈希

1. 定义：

Cuckoo Filter（布谷鸟过滤器）是一种概率型数据结构，由 Fan 等人在 2014 年提出，常被视作 Bloom Filter 的替代方案。它最突出的特点是原生支持删除操作，同时能在较低的误判率下保持不错的空间效率。

2. 工作原理：

🐦 Cuckoo Filter 基于"布谷鸟哈希"（Cuckoo Hashing）设计，可以把它想象成一个特殊的哈希表，里面存的不是原始数据，而是数据的指纹（一个短哈希值）。

  • 两个候选位置：
    每个元素通过哈希计算，会得到两个可能的桶位置。
  • 指纹存储：
    元素本身不存进去，只存一个短小的"指纹"（比如 8 位或 16 位）。
  • 踢出机制：
    插入时如果两个桶都满了，它会随机踢走一个已有的指纹，让这个指纹去它自己的另一个位置。这个过程就像布谷鸟把别的鸟蛋踢出巢一样，可能连锁触发，直到找到空位。

3. Redis 中的 Cuckoo Filter（RedisBloom 模块）：

命令以 CF. 开头：

  • 添加：
    CF.ADD key item 或 CF.INSERT key [CAPACITY cap] ITEMS item...。
  • 查询：
    CF.EXISTS key item 或批量 CF.MEXISTS key item...。返回 1 表示可能存在，0 表示一定不存在。
  • 删除：
    CF.DEL key item，这是它区别于 Bloom Filter 的关键操作。

4. ⚠️ 需要注意的"坑"：

虽然设计上 Cuckoo Filter 号称没有假阴性（即已插入的元素一定查得到），但实际的工程实现中，在高负载或特定哈希冲突下，可能会出现假阴性。有研究指出，在过滤器接近满载时，部分实现会因踢出机制和哈希截断的相互作用，导致本该存在的元素查不到。所以，如果业务上不允许漏判，使用前最好针对具体实现做测试验证。

什么是布隆过滤器（Bloom Filter）？
概率型数据结构高频

1. 定义：

布隆过滤器（Bloom Filter）是 1970 年由 Burton Howard Bloom 提出的一种概率型数据结构，由一个很长的位数组和若干个哈希函数组成，用来判断一个元素是否在集合中。

它的判断结果是"概率性"的：

  • 说不存在，就一定不存在（无假阴性）。
  • 说存在，只是可能存在（有假阳性，即误判率）。

2. 工作原理：

布隆过滤器由一个长度为 m 的位数组（初始全 0）和 k 个相互独立的哈希函数组成，每个哈希函数都能把元素映射到 [0, m-1] 范围内的某个下标。

  • 插入流程：
    将元素 x 依次经过 k 个哈希函数，得到 k 个下标 h1(x)、h2(x)、…、hk(x)，把位数组中这 k 个位置全部置为 1。如果某个位置原本就是 1，保持不变（位只能从 0 变 1，不能变回 0）。
  • 查询流程：
    同样计算 k 个下标并检查对应位：
    只要任意一位为 0 → 一定不存在（若元素插入过，这些位必然都已是 1）；
    如果全部为 1 → 可能存在，因为这些位可能是其它元素各自"凑"出来的，这就是假阳性（误判）的来源。
  • 误判率与参数关系：
    位数组越大（m 越大）、哈希函数个数 k 选取合适，误判率越低；插入元素越多（n 越大），位数组越"满"，误判率越高。近似公式：误判率 p ≈ (1 - e^(-kn/m))^k。
    工程上通常按预期元素量 n 和目标误判率 p 反推出所需的 m 和 k（如 m = -n·lnp / (ln2)²，最优 k ≈ (m/n)·ln2）。
  • 为什么用多个哈希函数：
    单个哈希函数冲突率高；多个独立哈希函数要求所有位同时"撞车"才误判，概率大幅降低。工程上常用双重哈希（Double Hashing）模拟 k 个函数：hi(x) = h1(x) + i·h2(x)，只算两次哈希即可。

3. 核心特点：

  • 空间效率极高：
    不存储元素本身，只存比特位，比 HashMap 等结构节省几十倍空间。
  • 查询时间恒定：
    O(k)，k 为哈希函数个数（通常个位数），与数据量无关。
  • 不支持删除：
    位数组的一个位可能被多个元素共享，直接置 0 会影响其它元素。想支持删除需用计数布隆过滤器（Counting Bloom Filter）或改用 Cuckoo Filter。
  • 存在误判率：
    由位数组大小 m、哈希函数个数 k、已插入元素数 n 共同决定；装载越满误判率越高。

4. 使用示例（Redis RedisBloom 模块）：

  • 添加：
    BF.ADD key item 或批量 BF.MADD。
  • 查询：
    BF.EXISTS key item，返回 1 表示可能存在，0 表示一定不存在。
  • 创建时指定参数：
    BF.RESERVE key 0.001 1000000（误判率 0.1%、预计 100 万元素）。

Java 侧可用 Guava 的 BloomFilter：

// Guava 示例 BloomFilter<String> filter = BloomFilter.create( Funnels.unencodedCharsFunnel(), 1000000, 0.001); filter.put("hello"); filter.mightContain("hello"); // true（可能存在）

5. 典型应用场景：

  • 缓存穿透防护：
    请求先过布隆过滤器，不存在的 Key 直接拦截，不打到数据库。
  • 爬虫 URL 去重、垃圾邮件/黑名单过滤、推荐系统已读去重。

6. ⚠️ 注意事项：

  • 误判率需提前评估并预留足够空间，接近满载时误判率急剧上升，应重建或扩容。
  • 不支持删除，元素过期场景要考虑定期重建或改用 Cuckoo Filter。
  • 哈希函数需相互独立且分布均匀（工程上常用双重哈希模拟 k 个函数）。
  • 它只能做"存在性判断"，不能取出原始元素，不能遍历。
