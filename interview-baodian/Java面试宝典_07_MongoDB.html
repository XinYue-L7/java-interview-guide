MongoDB 是什么？和关系型数据库（MySQL）有什么区别？
基础高频

一句话概括：MongoDB 是面向文档（Document）的 NoSQL 数据库，数据以 BSON 文档存储，支持水平扩展，与 MySQL 的"表 + 行"关系模型完全不同。

对比项MongoDBMySQL
数据模型BSON 文档（Json 风格）表 + 行 + 列
Schema动态（字段可随时增减）固定（需 DDL 变更）
事务4.0+ 支持多文档事务强 ACID，天然支持
扩展方式分片（Sharding）水平扩展主从 / 分库分表，偏垂直
复杂关联查询弱（需 $lookup）强（JOIN 丰富）
典型场景海量数据、结构多变强一致、强事务业务

💡 选型：结构多变、读写并发高、海量数据（用户画像/日志/商品）→ MongoDB；强事务、复杂关联查询（订单/财务）→ MySQL。

2
MongoDB 的 BSON 和 JSON 有什么区别？
数据模型

一句话概括：BSON 是 MongoDB 的二进制 JSON，比 JSON 支持更多数据类型、解析更快、存储更紧凑。

  • 数据类型更多：Date、ObjectId、BinData、Decimal128、正则、内嵌数组/文档等。
  • 二进制存储：带类型标记和长度，遍历/解析快，省去文本解析。
  • 遍历更快：字段名旁直接带类型和长度，可直接跳读。
  • JSON：人可读的纯文本，跨语言通用，但类型弱（数字都是 number）。

💡 面试可说：MongoDB 文档天然就是 BSON，内部存储、索引、复制均基于 BSON。

3
MongoDB 的 ObjectId 是怎么生成的？
数据模型

一句话概括：ObjectId 是 12 字节的十六进制字符串，由 时间戳 + 机器标识 + 进程ID + 自增计数器四部分构成，无需中心自增即可全局唯一。

  • 4 字节：秒级时间戳（可按 _id 排序约等于按插入时间排序）。
  • 3 字节：机器标识（主机名 hash）。
  • 2 字节：进程 ID。
  • 3 字节：同一秒内的自增计数器（随机起点）。

优点：客户端本地即可生成，天然支持分布式；自带时间信息。

💡 对比：MySQL 自增主键需要中心协调；UUID 是 128 位更长、无序。

4
MongoDB 的文档模型：范式化与反范式化如何选择？
建模高频

一句话概括：范式化（引用）减少冗余但查询要多次；反范式化（内嵌）一次查询出数据但要维护一致性。

内嵌（Embedded）：

  • 适合：一对一 / 一对少；子文档总是随主文档一起读；读多写少。
  • 例子：用户 + 收货地址、文章 + 评论。

引用（Reference）：

  • 适合：一对多 / 多对多；子文档独立变化；数据量大不宜内嵌。
  • 例子：用户 + 订单、商品 + 库存。

💡 实务：混用——高频一起读的内嵌，低频或独立的用引用，必要时用 $lookup 关联。

5
MongoDB 有哪些索引类型？
索引高频

一句话概括：MongoDB 索引底层用 B-Tree，类型丰富，覆盖单字段、复合、数组、全文、地理位置等场景。

  • 单字段索引：默认 _id 唯一索引；可对任意字段建升/降序。
  • 复合索引：多字段，遵循"最左前缀"原则（ESR：相等字段 → 排序 → 范围）。
  • 多键索引：对数组字段建索引，自动展开数组元素。
  • 文本索引：全文检索，支持中文分词（需指定语言）。
  • 地理空间索引：2dsphere，支持附近的人/距离查询。
  • TTL 索引：字段到期自动删除文档（如验证码、会话）。
  • 哈希索引：用于分片键均衡分布。
  • 唯一索引：保证字段唯一性。

💡 排查：db.collection.getIndexes() 查看；explain("executionStats") 判断是否走索引。

6
MongoDB 的 WiredTiger 存储引擎有什么特点？
存储引擎

一句话概括：WiredTiger 是 MongoDB 3.2+ 的默认存储引擎，基于 B-Tree，提供文档级锁 + 压缩 + 快照隔离（MVCC）+ 崩溃恢复。

  • 文档级并发控制：取代旧版 MMAPv1 的集合级锁，并发能力大幅提升。
  • 压缩：Snappy / Zlib 压缩数据和索引，显著节省磁盘。
  • 检查点 + Journal：定期 checkpoint + 预写日志（WAL），崩溃后快速恢复。
  • 内存缓存：默认使用 50% 内存（需显式配置，避免与 OS 冲突）。
  • 快照隔离：支持多版本并发控制，为事务提供基础。

💡 面试加分：提到 MMAPv1 → WiredTiger 的演进，说明锁粒度从集合级到文档级。

7
MongoDB 复制集（Replica Set）的原理和选举机制？
高可用高频

一句话概括：复制集是一主多从的高可用架构：主节点负责写，从节点通过复制 oplog 异步同步数据，主节点故障时自动选举出新主。

  • 写入：只写主节点，写入记录到 oplog（本地集合）。
  • 同步：从节点拉取并应用 oplog，默认异步复制。
  • 心跳：节点间每 2 秒心跳，超时（默认 10s）触发重新选举。
  • 选举：基于 Raft 算法；必须有大多数节点（n/2+1）在线才能选主，防止脑裂。
  • 优先级：priority 高的节点优先成为主；可配置隐藏节点、延迟节点（备份）。
  • 读写分离：secondaryPreferred 读从节点，但可能读到旧数据。

💡 典型规模：3 节点（1 主 2 从）或 5 节点，最多可容忍 n/2 台故障。

8
MongoDB 的分片集群（Sharding）原理？
分片架构

一句话概括：分片集群将集合按分片键水平切分到多个 shard，mongos 做路由，Config Server 保存元数据，数据按块（chunk）自动均衡。

  • 组件：mongos（路由）、Config Server（元数据副本集）、Shard（每个 shard 本身是副本集）。
  • 分片键选择：基数大、分布均匀、读写在它上面分散（避免热点）。
  • 数据分布方式：hashed（哈希取模，分布均匀）与 ranged（范围分片，利于范围查询）。
  • 均衡器：chunk 超过阈值自动迁移，动态扩缩容。

💡 什么时候分片：数据量单机放不下、写入吞吐超单机、需要线性扩展；分片键一旦选定不可修改，务必慎重。

MongoDB 支持事务吗？如何实现？
事务高频

一句话概括：MongoDB 4.0 起支持副本集多文档事务（ACID），4.2 起支持分片集群分布式事务。

  • 底层原理：基于 WiredTiger 的 快照隔离（MVCC） + Journal 日志，事务内读到一致快照。
  • 使用方式：session.startTransaction() → 多次操作 → commitTransaction() / abortTransaction()。
  • 限制：事务有时长限制（默认 60s）；事务内不能创建/删除集合；不能跨不同分片键的分布式事务做任意操作。
  • 注意：事务会放大锁冲突，谨慎控制事务内操作数量。

💡 面试点：提到事务演进 2.6（单文档原子性）→ 4.0（多文档）→ 4.2（分布式事务）。

10
MongoDB 的聚合管道（Aggregation Pipeline）是什么？
聚合高频

一句话概括：聚合管道类似 Linux 管道，把多个阶段（stage）依次作用于文档流，前一个阶段的输出作为下一阶段的输入。

  • 常用阶段：$match（过滤）→ $group（分组）→ $sort（排序）→ $project（投影）→ $unwind（展开数组）→ $lookup（跨集合关联，类似 JOIN）→ $limit/$skip（分页）。
  • 内存限制：单阶段默认内存上限 100MB，超出可用 allowDiskUse 落盘。
  • 优化：尽早 $match、$sort 尽量靠前（可复用索引），避免全量 $unwind。

💡 对比：聚合管道比旧版 MapReduce 高效得多，是 Mongo 数据分析的主流方式。

MongoDB 的读写关注级别（Write Concern / Read Concern）？
一致性

一句话概括：Write Concern 决定写多少节点确认才算成功；Read Concern 决定读取哪种已提交状态的数据，两者共同平衡一致性与性能。

Write Concern：

  • w=1（默认）：主节点确认即返回，性能好。
  • w=majority：多数节点确认，数据不丢（选举后不丢写）。
  • j=true：journal 落盘后才确认。
  • wtimeout：等待超时上限，避免一直阻塞。

Read Concern：

  • local（默认）：读到本节点最新数据，可能未提交。
  • available：类似 local，分片场景可用。
  • majority：只读已提交到多数副本的数据（不读脏数据）。
  • linearizable：最强一致（结合 writeConcern majority 使用）。
  • snapshot：事务快照读。

💡 组合建议：核心数据 w=majority + readConcern majority；缓存类数据用默认级别换性能。

MongoDB 和 Redis 有什么区别？如何选择？
对比高频

一句话概括：MongoDB 是磁盘文档数据库（持久化核心数据），Redis 是内存 key-value 缓存（高并发热点数据）。

对比项MongoDBRedis
定位文档数据库（NoSQL）内存数据库 / 缓存
数据模型BSON 文档，复杂结构String / Hash / List / Set / ZSet
存储介质磁盘为主（WiredTiger）内存为主，持久化是补充
数据量海量（TB 级可分片）受内存限制（GB 级）
事务多文档 ACID（4.0+）Lua 脚本 / MULTI 弱事务
典型场景核心数据存储、查询分析缓存、计数器、排行榜、分布式锁

💡 常见组合：Redis 扛高并发缓存 + MongoDB 存主数据，缓存击穿时回源 MongoDB。

13
MongoDB 的 GridFS 是什么？应用场景？
大文件

一句话概括：GridFS 是 MongoDB 存储超过 16MB 大文件的规范：文件拆成小块存入 chunks 集合，元数据存入 files 集合。

  • files 集合：存文件名、大小、上传时间、MD5 等元数据。
  • chunks 集合：存二进制分块（默认每块 255KB），带 files_id 关联。
  • 优点：随 MongoDB 分片/副本集扩展；支持断点续传；免搭建文件服务器。
  • 缺点：查询性能不如专业对象存储（OSS/S3）；不支持文件内随机修改（需整块重写）。

💡 场景：中小规模的文件存储（头像、日志归档、内部资料）；大规模场景优先 OSS/S3。

14
MongoDB 慢查询如何排查和优化？
性能优化高频

一句话概括：开启 Profiler 记录慢操作 → 用 explain 分析执行计划 → 对症下药（建索引/改查询/调分页）。

  1. 开启慢查询日志：db.setProfilingLevel(1, {slowms: 100})，慢操作写入 system.profile 集合。
  2. 分析执行计划：db.collection.find(...).explain("executionStats")，关注 COLLSCAN（全表扫描）→ 应改为 IXSCAN。
  3. 建索引：针对查询条件、排序字段建复合索引（遵循 ESR 顺序）。
  4. 限制返回：只查需要的字段（$project），避免大文档全量传输。
  5. 分页优化：深分页用 skip 很慢，改用键集分页（_id > 上次值）或 find().sort().limit() 游标式。
  6. 监控：db.serverStatus()、mongostat 观察内存、连接数、队列。

MongoDB 与 Elasticsearch 的区别？
对比

一句话概括：MongoDB 是文档数据库（负责存储、事务、查询），Elasticsearch 是搜索引擎（负责全文检索、分析聚合），二者定位不同常配合使用。

对比项MongoDBElasticsearch
定位文档数据库（NoSQL）分布式搜索引擎
索引结构B-Tree（字段索引）倒排索引（全文检索）
写入一致性事务 ACID近实时（秒级可见）
强项存储、查询、事务全文搜索、相关度评分、聚合分析
弱项全文检索能力弱不适合强一致业务存储

💡 常见组合：MongoDB 存业务数据，ES 同步数据做全文搜索（如商品搜索、日志检索）。
