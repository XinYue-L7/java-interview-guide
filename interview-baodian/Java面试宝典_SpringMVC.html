Spring MVC 的请求处理流程？
SpringMVC高频

一句话概括

Spring MVC 的请求处理流程，就是一条"流水线"：

请求先由DispatcherServlet（前端控制器）统一接收，然后通过HandlerMapping找到该由哪个 Controller 处理，再由HandlerAdapter调用 Controller 执行业务逻辑，最后通过ViewResolver找到视图并渲染，把结果返回给浏览器。

核心组件及作用

组件作用类比
DispatcherServlet前端控制器，统一入口，所有请求都先经过它像公司前台，所有人来访先找前台登记
HandlerMapping根据 URL 找到对应的 Handler（Controller + 方法）像前台的"楼层导航牌"，告诉你去几楼找谁
HandlerAdapter适配调用 Handler，支持多种 Controller 类型（如 @Controller、HttpRequestHandler）像"翻译官"，不同部门的人说话方式不同，翻译官统一转成老板能听懂的方式
Handler（Controller）执行业务逻辑，返回 ModelAndView 或数据像业务部门的同事，真正干活的人
ViewResolver解析视图名称，找到具体的视图文件（如 JSP、Thymeleaf）像"排版部"，把业务同事写的内容排成漂亮的页面
View渲染视图，生成最终的 HTML 响应像"印刷厂"，把排版好的内容印出来给用户看

六步流程

  1. 接收请求：
    浏览器发来 HTTP 请求，DispatcherServlet 统一接收。
  2. 查找处理器：
    HandlerMapping 根据 URL 匹配规则，找到对应的 Controller 方法。
  3. 适配调用：
    HandlerAdapter 适配并调用 Controller 方法，传入解析好的参数。
  4. 执行业务：
    Controller 里的业务逻辑执行完毕，返回 ModelAndView（或 @ResponseBody 直接返回数据）。
  5. 解析视图：
    ViewResolver 根据视图名称找到具体的视图模板。
  6. 渲染响应：
    View 把模型数据填充到视图模板中，生成 HTML，返回给浏览器。

举例讲解

场景：

用户访问 /user/123 查看用户信息

  1. 浏览器发请求 GET /user/123。
  2. DispatcherServlet 收到请求，交给 HandlerMapping。
  3. HandlerMapping 发现 @GetMapping("/user/{id}") 匹配到 UserController.getUser() 方法。
  4. HandlerAdapter 把 URL 里的 123 解析成参数 id，调用 getUser(123)。
  5. Controller 查数据库得到用户信息，返回 ModelAndView("userDetail", model)。
  6. ViewResolver 找到 userDetail.jsp，View 把用户名、手机号等数据填进去，生成 HTML 返回给浏览器。

Spring MVC 处理请求的完整流程？
SpringMVC高频

一句话概括

Spring MVC 处理请求的完整流程，在第1题六步的基础上，更加细化：

加入了拦截器（preHandle/postHandle/afterCompletion）、参数解析（把请求参数转成方法参数）、返回值处理（把方法返回值转成响应），以及 @ResponseBody 场景下跳过视图渲染、直接用 HttpMessageConverter 序列化 JSON 返回。

完整流程（含内部细节）

  1. 请求到达 DispatcherServlet
    所有请求先经过这个前端控制器，它是整个 Spring MVC 的"总调度"。
  2. 拦截器 preHandle()
    DispatcherServlet 先调用拦截器链的 preHandle()。
    如果某个拦截器返回 false，请求直接中断，不会继续往下走。
  3. HandlerMapping 查找 Handler
    根据 URL 找到对应的 Controller 方法（Handler）。
  4. HandlerAdapter 适配调用
    • 参数解析：
      HandlerMethodArgumentResolver 把请求里的参数（URL 参数、表单数据、JSON 体、PathVariable 等）解析成方法参数。
    • 反射调用 Controller 方法：
      执行业务逻辑。
  5. 返回值处理
    • 如果是 ModelAndView：
      交给 ViewResolver 解析视图。
    • 如果是 @ResponseBody：
      跳过视图，由 HttpMessageConverter（如 MappingJackson2HttpMessageConverter）把返回值序列化成 JSON/XML，直接写入响应体。
  6. 拦截器 postHandle()
    Controller 执行完但视图还没渲染之前调用。
    可以在这里修改 Model 数据。
  7. 视图渲染（如有）
    ViewResolver 解析视图名 → View 渲染 → 生成 HTML。
  8. 拦截器 afterCompletion()
    整个请求处理完（包括视图渲染）后调用，用于资源清理、日志记录等。
    无论前面是否异常，这个方法都会执行。
  9. 响应返回
    把最终的响应数据写给浏览器。

关键扩展点

扩展点作用使用场景
HandlerInterceptorpreHandle / postHandle / afterCompletion登录校验、权限检查、日志记录
HandlerMethodArgumentResolver自定义参数解析把 Token 解析成当前用户对象注入方法参数
HandlerMethodReturnValueHandler自定义返回值处理统一包装返回值（如 {"code":0, "data":xxx}）
HttpMessageConverter请求体/响应体的序列化反序列化@RequestBody 接收 JSON、@ResponseBody 返回 JSON
ExceptionHandler统一异常处理@ControllerAdvice + @ExceptionHandler 全局捕获异常

第1题 vs 第2题的区别

  • 第1题回答的是宏观的六步流程，适合快速概述。
  • 第2题回答的是完整的内部细节，包含拦截器的三个阶段、参数解析、返回值处理、@ResponseBody 的 JSON 序列化等，适合深入追问。

举例讲解

场景：

用户提交登录表单，@ResponseBody 返回 JSON

  1. 浏览器 POST /api/login，带上 JSON 请求体 {"username":"tom","password":"123"}。
  2. DispatcherServlet 接收请求。
  3. 拦截器 A（登录校验）的 preHandle() 发现这是登录接口，放行返回 true。
  4. HandlerMapping 匹配到 AuthController.login()。
  5. HandlerAdapter 调用参数解析器：
    @RequestBody 对应的 HttpMessageConverter 把 JSON 请求体反序列化成 LoginRequest 对象。
  6. 反射调用 login(loginRequest)，Controller 查数据库验证密码，生成 Token。
  7. 方法返回 Result.success(token)，因为加了 @ResponseBody，返回值处理器调用 Jackson 把 Result 对象序列化成 JSON。
  8. 拦截器 A 的 postHandle() 被调用（视图已跳过，这里可以做一些后处理）。
  9. 拦截器 A 的 afterCompletion() 记录本次请求的耗时日志。
  10. JSON 响应 {"code":0,"data":"eyJhbGc..."} 返回给浏览器。

说说你对 Spring MVC 的了解？
SpringMVC基础

一句话概括

Spring MVC 是 Spring 家族中基于 Servlet 的 MVC 轻量级 Web 框架，核心是前端控制器 DispatcherServlet：

所有请求统一由它接收，再分发给 Controller 处理，配合视图解析完成页面或 JSON 响应。

MVC 是什么

  • M（Model）模型：
    业务数据与逻辑，如 Service、DAO。
  • V（View）视图：
    展示层，如 JSP / Thymeleaf / JSON。
  • C（Controller）控制器：
    接收请求、调用模型、选择视图。

Web 开发模式演进

阶段模式特点
Model 1JSP 直接处理请求+展示控制逻辑和页面混在一起，维护困难
Model 2JSP + Servlet + JavaBeanServlet 控制、JavaBean 模型、JSP 展示，即 MVC 雏形
框架化Spring MVC / Struts2框架封装了控制器分发、参数绑定、视图解析，开发效率大幅提升

Spring MVC 的核心特点

  • 基于 Servlet：
    以 DispatcherServlet 为统一入口，天然兼容 Servlet 容器（Tomcat 等）。
  • 注解驱动：
    @Controller、@RequestMapping、@GetMapping 等，告别 XML 配置。
  • 视图灵活：
    支持 JSP / Thymeleaf / FreeMarker；
    @ResponseBody 可直接返回 JSON。
  • 与 Spring 无缝集成：
    IoC 管理 Controller、AOP 支持事务、参数自动注入。
  • 扩展点丰富：
    拦截器（HandlerInterceptor）、参数解析器、HttpMessageConverter、@ControllerAdvice 统一异常处理。

与其他框架对比（Struts2）

对比项Spring MVCStruts2
入口DispatcherServlet（单例）Filter 拦截
映射粒度方法级（@RequestMapping）类级（Action）
性能方法直接调用，更快Action 实例创建开销较大
集成与 Spring 原生一体需要额外整合

举例讲解

一个典型的 Spring MVC 接口：

@RestController + @GetMapping("/hello")，浏览器访问后 DispatcherServlet 找到对应方法、注入参数、执行业务、返回 JSON —— 全程无需手动 new Servlet，开发体验简单高效。
