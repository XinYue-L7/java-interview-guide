讲讲 Java 面向对象编程的三大特性：封装、继承、多态
OOP高频

一句话概括

Java 面向对象有封装、继承、多态三大特性，一句话记住："封装管好内部、继承管好复用、多态管好扩展"。

定义

封装（Encapsulation）：把对象的属性和方法包装成一个整体，对外隐藏内部细节，只暴露必要的访问接口（通过 private + getter/setter 实现）。

继承（Inheritance）：子类通过 extends 获得父类的属性和方法，实现代码复用，子类还可以在父类基础上扩展或重写。

多态（Polymorphism）：同一类型的对象，在不同时刻可以表现出不同的行为——"同一个调用，不同的实现"。Java 多态靠继承 + 重写 + 父类引用指向子类对象实现。

三大特性对比

特性关注点核心机制解决什么问题
封装内部细节隐藏private + getter/setter保护数据安全，降低耦合
继承代码复用extends + super消除重复代码，形成层级
多态动态扩展重写 + 父类引用指向子类对象 + 动态绑定提高扩展性，面向接口编程

举例讲解

例1：封装 —— 像 ATM 取款机

  • 你只知道插卡、输密码、取钱、查余额（对外暴露的接口），完全不用关心 ATM 内部是怎么验证密码、怎么联网、怎么数钱的（内部细节隐藏）。
  • 你的账户余额是 private 的，别人不能直接改，只能通过银行提供的合法接口（getter/setter 或取款方法）操作，数据就安全了。

例2：继承 —— 像"动物"和"狗"

  • Animal 是父类，定义了共有的 eat()、sleep() 方法（代码复用）。
  • Dog extends Animal，自动拥有了吃和睡的能力，不用重写；狗还可以新增自己特有的 bark()（扩展）。

例3：多态 —— 像"都是动物，行为不一样"

class Animal { void sound() { } // 父类方法 } class Dog extends Animal { @Override void sound() { System.out.println("汪汪"); } } class Cat extends Animal { @Override void sound() { System.out.println("喵喵"); } } // 父类引用指向子类对象 Animal a1 = new Dog(); // 编译看左边，运行看右边 Animal a2 = new Cat(); a1.sound(); // 汪汪 —— 动态绑定到 Dog 的实现 a2.sound(); // 喵喵 —— 动态绑定到 Cat 的实现

都是 Animal 类型，但调用 sound() 时，实际执行的是各自子类的实现，这就是多态。"编译看左边（声明类型），运行看右边（实际对象）" 是判断多态的关键口诀。

多态存在的三个必要条件

  • 有继承关系（实现类继承接口/父类）。
  • 子类重写了父类的方法。
  • 父类引用指向子类对象。

面试速记口诀

"封装管内部（private + getter/setter），继承管复用（extends + super），多态管扩展（重写 + 父类引用指向子类 + 动态绑定）。口诀：编译看左边，运行看右边。"

Java 是值传递还是引用传递？
基础语法高频

Java只有值传递。

  • 基本类型：传递值的副本，不改变原值。
  • 引用类型：传递引用的副本（地址值的拷贝），可通过该引用修改对象内容，但无法让原引用指向新对象。

本质：传递的都是栈中存储的值（基本类型的值 or 引用的地址值），都是值的副本。

Java 是值传递还是引用传递？
基础语法高频

Java 只有值传递，没有引用传递。

  • 基本类型：传递值的副本，修改不影响原变量。
  • 引用类型：传递的是引用地址的副本，形参和实参指向同一对象，修改对象内容会生效，但修改引用本身（如指向新对象）不生效。

💡 容易误解：能修改对象内容≠引用传递，这是共享对象引用而非传递引用本身。

public void swap(Integer a, Integer b) { Integer t=a; a=b; b=t; } // 不生效
public void modify(User u) { u.setName("new"); }            // 生效

String 常量池（String Pool）是什么？
StringJVM

String常量池是JVM在堆内存中维护的一个字符串缓存区域（JDK7+ 移到堆中）。

  • 字面量赋值：String s="abc" 先去常量池找，有则复用，无则创建。
  • new String("abc")：堆中创建对象，再检查常量池（无则创建），共创建1-2个对象。
  • intern()：手动将字符串加入常量池，返回池中引用。
  • + 拼接：字面量拼接→编译期优化；变量拼接→StringBuilder→new String。
String s1="a"+"b";      // 编译优化→"ab"，常量池
String s2=new String("a")+new String("b"); // 堆中新建
String s3=s2.intern(); // 将s2放入常量池，返回池中引用
System.out.println(s1==s3); // true

try-catch-finally 的执行顺序？finally 一定会执行吗？
异常处理高频

执行顺序：try (异常→catch) finally (正常后续代码)。

finally不执行的情况：

  • try之前System.exit(0)退出JVM。
  • 守护线程退出时finally可能不执行。
  • try/catch中执行System.exit()。
  • JVM崩溃或断电等不可恢复错误。

return 与 finally：

  • try有return值时，先计算return表达式，再执行finally，最后返回。
  • finally中有return会覆盖try的return！
public int test() { try { return 1; } finally { return 2; } } // 返回2！

反射机制原理和应用场景？
反射高频

原理：类加载时JVM在方法区生成Class对象，反射通过Class对象获取类信息（构造器、方法、字段），并在运行时动态调用。

获取Class的方式：

  • Class.forName("全限定名") — 静态方法，会初始化类。
  • 对象.getClass() — 实例方法。
  • 类名.class — 不会触发类初始化。

应用场景：Spring IOC、动态代理、JDBC驱动加载、注解解析、框架配置注入。

Class.forName 和 ClassLoader.loadClass 的区别？
反射类加载
对比Class.forNameClassLoader.loadClass
初始化执行静态代码块不执行（只加载到JVM）
参数只需全限定名需要指定类加载器
典型场景JDBC驱动加载Spring IOC延迟加载

💡 JDBC中Class.forName("com.mysql.jdbc.Driver")触发静态代码块注册驱动；Spring用ClassLoader延迟加载以支持懒初始化。

两个词分别是什么（先定义再谈区别）：

Class.forName：是java.lang.Class类的静态方法，
只需传入类的全限定名，JVM 会加载该类并立即完成初始化（执行静态代码块、静态变量赋值），
最终返回对应的 Class 对象；
JDBC 用它加载驱动，目的就是让驱动类里的静态代码块执行，从而向 DriverManager 注册自己。

ClassLoader.loadClass：是类加载器对象（ClassLoader）的实例方法，
只负责把类的字节码加载进 JVM（加载 + 链接阶段的验证、准备等），
默认不会触发初始化——初始化被推迟到该类的首次"主动使用"（如 new、反射调用静态成员等）时才进行，
所以 Spring IOC 利用它先把类加载好但不初始化，等真正创建 Bean 时再完成初始化，从而实现懒加载。

Integer 的缓存机制是怎样的？
包装类高频

Integer内部维护了IntegerCache，默认缓存-128 ~ 127之间的Integer对象。

  • 自动装箱Integer i=100 从缓存取，返回同一对象。

Integer c=200, d=200;   System.out.println(c==d); // false (超出缓存)

💡 同样有缓存的包装类：Byte/Short/Long(-128~127)、Character(0~127)、Boolean(TRUE/FALSE)。Double/Float没有缓存。

Lambda 表达式的原理是什么？有什么限制？
Java8Lambda

什么是 Lambda 表达式？

Lambda 表达式是一种匿名函数的简洁写法，允许将函数作为参数传递，是函数式编程在 Java 中的核心体现。

作用：

  • 替代冗长的匿名内部类写法，使代码更简洁、可读性更高。
  • 尤其适用于集合遍历、事件监听、Stream 操作等场景。

原理：

编译器将 Lambda 体转换为类的私有方法，通过 invokedynamic 指令在运行时由 LambdaMetafactory 生成对应的函数式接口实现对象，避免了每次编译都生成匿名类的字节码膨胀问题。

相比匿名内部类：

  • 不会生成额外的 class 文件，减少 Jar 包大小。
  • 不创建新对象（无捕获时），性能更好。
  • this 指向外层类而非匿名内部类自身。

限制：

  • 只能用于函数式接口（只有一个抽象方法）。
  • 不能修改外部局部变量（需 effectively final）。
  • 不能抛出受检异常（除非接口声明）。

示例：

// 遍历集合
list.forEach(o -> System.out.println(o));

// 排序
list.sort((a, b) -> a.getAge() - b.getAge());

// Stream 过滤 + 映射
list.stream()
    .filter(e -> e.getSalary() > 5000)
    .map(e -> e.getName())
    .collect(Collectors.toList());

// Runnable 线程
new Thread(() -> System.out.println("Running")).start();

Java 中如何实现不可变类？String 为什么被设计为不可变？

  1. 类声明为final，防止继承。
  2. 所有字段private final。

  4. 构造方法中防御性拷贝（引用类型字段）。

  • 安全性：避免被篡改（如类加载、网络连接参数）。

  • Hash缓存：hashCode可缓存，HashMap key性能高。

面向对象和面向过程的区别？
OOP高频

一句话概括

面向过程是"按步骤做"，关注的是"怎么一步步把事情做完"；面向对象是"找对象来做"，关注的是"有哪些对象、对象之间怎么协作"。Java 是典型的面向对象语言，C 是典型的面向过程语言。

定义

面向过程（Procedure Oriented）：以"过程/函数"为核心，把要解决的问题拆解成一个个步骤，用函数实现每个步骤，再按顺序调用。数据和操作数据的函数是分离的。

面向对象（Object Oriented）：以"对象"为核心，把现实世界的事物抽象成类和对象，将数据（属性）+ 操作数据的方法（行为）封装在一起，通过对象之间的消息传递来完成功能。

核心区别对比

维度面向过程面向对象
核心思想步骤、函数、流程对象、类、协作
数据与操作分离（数据结构 + 一堆函数）封装在一起（属性 + 方法）
代码组织按功能拆函数按业务抽象成类
可维护性差，改一处流程可能牵动全局好，高内聚、低耦合，改内部不影响外部
可扩展性差，新增功能要改动流程主线好，继承 + 多态天然支持扩展
代码复用函数复用，粒度小类复用 + 继承复用，粒度大
性能高（函数直接调用，开销小）略低（有对象创建、方法调用开销）
适用场景简单流程、底层驱动、嵌入式大型复杂业务系统、多人协作项目

举例讲解

例1：做饭

  • 面向过程：像照着菜谱做——洗菜() → 切菜() → 热锅() → 炒菜() → 装盘()，一步步调用函数，食材（数据）被传来传去。
  • 面向对象：像餐厅后厨——厨师对象有自己的拿手菜技能，食材对象有新鲜度属性，锅对象有温度属性。你只需要"厨师.做菜(食材)"，具体怎么洗、怎么切、怎么炒是厨师自己的事（封装）。以后想换做法，换个厨师即可（多态）。

例2：洗衣机

  • 面向过程：主程序里按顺序调用 注水()、洗涤()、排水()、脱水()，水、电机等状态数据暴露在外，改一个功能可能要改好几个函数。
  • 面向对象：封装一个洗衣机类，把水位、转速、洗衣模式当属性，把启动()、注水()、洗涤()、脱水()当方法，外部只需调用"洗衣机.一键洗衣()"，内部细节全部隐藏。

面试速记口诀

"面向过程是流水线，一步一步照着办，数据和函数分两边；面向对象是搭积木，对象封装又协作，继承多态好扩展。性能选过程，复杂系统选对象，两者结合最实在（Java 方法内部其实也是过程式思路）。"

一句话：应用程序是"独立自主的完整程序"，小程序是"寄生在浏览器里的一段程序"。两者最大的差别在于"有没有 main 方法"和"靠谁启动运行"。

定义

应用程序（Application）：有 main 方法，能独立运行，是完整的 Java 程序。

小程序（Applet）：没有 main 方法，必须嵌入到网页中，由浏览器配合 JVM 加载执行。

两者差别对比

维度应用程序（Application）小程序（Applet）
运行入口main 方法init / start / paint / stop / destroy 生命周期方法
运行环境独立，只需 JRE必须嵌入 HTML，依赖浏览器 + JVM 插件

应用程序 就像一部"单机游戏"：安装好（JRE 就绪）就能自己启动（运行 main），从头玩到尾，不需要其他东西配合。

构造器 Constructor 是否可被 override？
面向对象高频

一句话概括

一句话：构造器（构造方法）不能被 override（重写）。因为重写的前提是"父类和子类方法签名完全一样"，而构造器的名字必须和类名相同，父类和子类类名不同，构造器名字就不同，所以永远无法满足重写的条件。

定义

构造器（Constructor）：与类名同名、没有返回值的方法，在 new 对象时自动调用，用于初始化对象。

override（重写）：子类重新定义父类中同名同参的方法，实现多态。

为什么不能 override

  • 名字不同：构造器必须与类名同名，Father() 和 Child() 构造器名字不一样，签名无法一致，自然不构成重写。
  • 没有返回值概念：重写要求返回类型兼容，而构造器没有返回类型（连 void 都没有），根本谈不上返回类型一致。
  • 构造器不属于多态范畴：重写依赖对象的多态分派，而构造器是"对象创建时"触发的，没有对象可以多态。

那子类如何"改造"父类构造行为？

手段说明
重载（Overload）构造器可以被重载，即一个类里可以有多个参数不同的构造器（如无参、有参）。
调用父类构造器子类构造器第一行用 super(...) 调用父类的某个构造器。
子类自己的构造器子类写自己的构造器，实现自己的初始化逻辑，这不是"重写"，而是"定义新构造器"。

举例讲解

class Father { Father() { } // 父类构造器 void eat() { } // 普通方法，可被重写 } class Child extends Father { // Child() 是子类自己的构造器，名字不同，不是重写 Child() { super(); } // 通过 super() 调用父类构造器 @Override void eat() { } // 普通方法 eat() 可以被重写 ✔ }

就像父子的姓氏：父亲叫"王爸爸"，儿子叫"王儿子"，名字肯定不一样，所以儿子没法"重写"爸爸的名字（构造器），但儿子可以调用爸爸的名字（super()），也可以用自己不同的名字（自己的构造器）。而普通的吃饭习惯（eat 方法）儿子是可以"重写"成自己喜欢的方式的。

面试速记口诀

"构造器不能重写，因为重写要同名同参，而构造器名字跟类名走，父类子类名字不同；重写是普通方法的特权，构造器只能重载 + 用 super() 调用父类构造器。"

String 为什么是不可变的？

一句话概括

一句话：String 被设计成不可变，核心靠三点——final 修饰类、final 修饰字符数组、值存储为私有且没有修改方法。不可变的字符串保证了安全、缓存高效、线程安全。

定义

不可变对象：对象一旦创建，其内部状态就不能被改变。String 是典型的不可变类。

String 不可变是怎么实现的

  • 类被 final 修饰：public final class String，不能被继承，防止子类破坏不可变特性。
  • 存储字段被 final 修饰：底层用 private final byte[] value;（JDK9+ 用 byte[]，JDK8 是 char[]），数组引用不可变。
  • 字段是 private 且无修改方法：没有提供 setter，外部拿不到数组引用，无法直接改内部数据。
  • 不暴露内部引用：substring()、toCharArray() 等方法都返回新对象或拷贝，不会泄露原始数组。

为什么一定要设计成不可变

原因说明
1. 字符串常量池复用相同字面量复用同一对象。如果 String 可变，改一个就会影响所有引用它的变量。
2. 安全网络传输、文件路径、数据库 URL 等常依赖字符串，若可变易被恶意篡改。
3. 线程安全不可变对象天然线程安全，多个线程同时访问不会出问题。
4. 作为 HashMap 的 keykey 要求不可变且 hashCode 稳定。String 不可变，hashCode 才安全，作为 key 不会"换身份证"。
5. 缓存 hashCodeString 内部缓存了 hashCode，不可变保证了缓存永远有效，提高哈希效率。

举例讲解

例1：常量池复用 就像一本"公共词典"，大家共用同一页内容。如果字符串可变，你改了这页，所有人看到的都变了——所以必须锁死（不可变）。

例2：HashMap key 想象用身份证号（String）当柜子的钥匙。如果身份证号可变，今天改了号码，明天就拿原来的钥匙打不开柜子了（hashCode 变了找不到 key）。所以身份证号必须是不可变的，才能稳定当钥匙。

public final class String implements java.io.Serializable, Comparable<String> { // JDK9+ 底层是 byte[]，且 final + private private final byte[] value; // 没有提供修改 value 的方法 }

面试速记口诀

"String 不可变靠三连：final 类、final 数组、私有无 setter。好处四句话：常量池能复用、安全防篡改、线程天然安全、能当 HashMap 的 key。"

在一个静态方法内调用一个非静态成员为什么是非法的？
关键字static

一句话概括

一句话：非静态成员（实例成员）依赖"具体的对象"才能访问，而静态方法不依赖对象、直接用"类名"就能调用，方法里没有 this，也就找不到是哪个对象，所以是非法的。

定义

静态成员（static 成员）：属于类本身，随类加载而存在，通过 类名.成员 直接访问，不依赖任何对象。

非静态成员（实例成员）：属于某个具体的对象，必须先 new 出对象，再用 对象名.成员 访问。

根本原因

  • 生命周期不同：静态成员在类加载时就存在；非静态成员要等对象创建（new）后才存在。
  • 静态方法没有 this：静态方法执行时，可能还没创建任何对象，没有 this 指向具体实例，自然无法访问"某个对象的"成员。
  • 无法确定目标对象：非静态成员每个对象各有一份，静态方法里直接调用非静态成员，编译器不知道你要访问的是哪个对象的，只能报编译错误。

对比说明

class Demo { int count = 10; // 非静态成员（实例变量） static void f() { // 静态方法 // count = 20; // 编译错误！静态方法里不能直接访问实例成员 } static void g(Demo d) { // 但可以传入对象再访问 d.count = 20; // 合法：通过具体的对象 d 访问 ✔ } }

静态方法里想用非静态成员怎么办？先创建一个对象，再用对象访问，例如在静态方法里 new Demo().count 或把对象作为参数传入。

举例讲解

把类比作一家工厂，静态成员像"工厂的公共设备"（如厂房大门的打卡机），工厂一建好就在，任何人都能用（不依赖某个员工）。非静态成员像"每个员工的私人工牌"（姓名、工号），只有这个员工入职（new 对象）后才有。

  • 你站在"厂房公共区域"（静态方法）想直接刷某个"员工的私人工牌"（非静态成员），但厂房里可能一个人都没有（还没 new 对象），不知道该刷谁的。
  • 所以必须先指定具体是哪位员工（传入对象引用），才能刷他的工牌。

面试速记口诀

"静态成员类加载就有、不靠对象；非静态成员靠对象 new 出来才有。静态方法里没有 this，找不到对象，所以不能直接访问非静态成员；想用就先 new 一个对象或把对象当参数传进来。"

成员变量（实例变量 / 静态变量）：定义在类体内、方法体外的变量，属于类或对象，随对象创建而存在。

局部变量（方法变量）：定义在方法内部、构造器或代码块中的变量，随方法调用而创建，方法结束就销毁。

核心区别对比

维度成员变量局部变量
定义位置类体内、方法体外方法内、构造器内、代码块内

把类比作一个宿舍楼：

  • 成员变量 像宿舍楼的"公共设施"或每个房间的"配套设施"：宿舍建成（new 对象）时就有，直到宿舍楼拆除（对象回收）才消失，整个楼里都能用（整个类可访问）。
  • 局部变量 像某个人出门时的"随身物品"：出门（调用方法）时带上，回到宿舍（方法结束）就放下，只在出门这段时间有效，别人看不到也不能用。

基础概念

一句话概括

一句话：创建对象用 new 运算符；对象实体是"真正存在内存里的数据"，对象引用只是"指向它的一个地址（遥控器/门牌号）"，引用不等于对象本身。

定义

new 运算符：在 Java 中创建对象时使用 new 类名(...)，它会在堆内存中分配空间并调用构造器完成初始化。

对象实体（Object）：new 出来后在堆内存中真正占有的那部分数据（字段值、方法等），是实实在在的存在。

对象引用（Reference）：指向对象实体地址的一个变量（类似 C 的指针，但更安全），通过它才能访问对象。

创建对象的方式与 new

Student s = new Student(); // new 创建对象 // 右边 new Student() 是对象实体，分配在堆中 // 左边 Student s 是对象引用，指向堆中的对象

对象实体 vs 对象引用对比

维度对象实体（Object）对象引用（Reference）
本质堆中真正存放的数据指向对象的内存地址（变量）
存储位置堆内存（Heap）栈内存（方法局部变量时）
创建方式通过 new 创建用引用变量指向 new 出来的对象
可被多个引用指向一个对象可被多个引用同时引用多个引用可指向同一个对象
生命周期无引用指向时被 GC 回收声明它的方法结束可能销毁
关系被引用指向指向对象实体

举例讲解

把对象实体比作一套真实的房子，把对象引用比作房子的地址/遥控器：

  • new 房子() 是真正盖好了一栋房子（对象实体，占一块地/内存）。
  • 房子的引用 r 只是拿到了这栋房子的地址（门牌号），不是房子本身。
  • 同一栋房子可以有多个地址指向它（多个引用指向同一个对象），通过任何一个地址都能找到这栋房子。
  • 如果所有地址都失效了（引用为 null 或超出作用域），这栋房子没人能找到，就会被拆迁队（GC）拆除回收。

面试速记口诀

"new 是造房子的机器，对象实体是盖好的房子，引用是房子的地址；一个房子多个地址很正常，地址全没了房子就被 GC 拆了。引用 ≠ 对象。"

在 Java 中定义一个不做事且没有参数的构造方法的作用？
面向对象构造器

一句话概括

一句话：定义一个空的、无参的构造方法，核心作用就是确保这个类可以用 new 类名() 无参方式创建对象，防止"因为写了其他构造方法而失去默认无参构造器"导致编译报错。

定义

默认无参构造器：当一个类没有写任何构造方法时，编译器会自动提供一个"无参空构造器"。

自定义无参空构造器：public 类名() { }，方法体什么都不做，但它"占据"了构造器名额，让无参 new 仍可用。

为什么需要它（作用）

  • 保证无参创建对象：只要一个类写了任何构造方法（哪怕只有一个带参的），编译器就不再自动生成默认无参构造器。此时若代码里还要 new 类名()，就会编译报错。
  • 适配反射/框架：很多框架（如 Spring、Jackson、MyBatis）通过反射创建对象时，经常要求有无参构造器。写一个空的无参构造器能保证这些框架能正常实例化对象。
  • 继承的兜底：子类构造器默认调用父类无参构造器 super()。如果父类没有无参构造器，子类也必须显式指定 super(...)，否则编译报错。定义一个无参构造器可避免这类麻烦。

举例讲解

class Student { String name; // 只写了带参构造器 → 编译器不再自动生成无参构造器 public Student(String name) { this.name = name; } } new Student(); // 编译错误！因为没写无参构造器 // ── 解决办法：补一个空的无参构造器 ── class Student2 { String name; public Student2() { } // 空无参构造器，什么都不做 public Student2(String name) { this.name = name; } } new Student2(); // 合法 ✔

把类比作"入住登记"：

  • 默认无参构造器就像"入住时前台自动给你一本空白登记册"（编译器送的）。
  • 一旦你自定义了"必须填名字的登记册"（带参构造器），编译器就不再送空白册子了，这时 new 类名()（空手入住）就没法登记（报错）。
  • 你手动放一本"空白登记册"（空的、无参构造器）在桌上，就能保证随时可以空手入住（无参创建），也能让框架（前台系统）顺利初始化。

面试速记口诀

"写不做事、无参的构造器，是为了保住 new 类名() 的能力：写了带参构造器编译器就不送默认无参了，所以手动补一个，既保证无参创建，也让 Spring 等反射框架能正常实例化。"

什么是方法的返回值？返回值在类的方法里的作用是什么？
基础语法方法

一句话概括

一句话：返回值就是方法执行完后交给调用者的结果，通过 return 语句送出；它的作用就是让方法能把计算结果传回给调用方，让方法成为"有产出"的零件。

定义

方法返回值：方法执行结束后，通过 return 返回给调用者的数据。方法的声明中要写明返回类型（int、String、自定义类等），若没有返回值则用 void。

返回值的作用

  • 传递结果：让调用者能拿到方法计算/处理后的结果，比如 int sum = add(1,2) 拿到的 3。
  • 实现复用与封装：一个方法把逻辑封装起来，把结果返回出去，调用方只需关注"输入输出"，不用关心内部实现。
  • 支持链式调用/后续逻辑：返回值可以继续作为其他方法的输入，或参与赋值、判断等后续处理。
  • 表达方法执行状态：常用返回值表示成功/失败（如返回 true/false、返回错误码），方便调用方做分支处理。

举例讲解

class Calculator { // 有返回值：把计算结果返回给调用者 int add(int a, int b) { return a + b; // 返回 和 } // 无返回值(void)：只做事，不返回结果 void printHello() { System.out.println("Hello"); // 没有 return } } class Main { public static void main(String[] args) { Calculator c = new Calculator(); int result = c.add(3, 4); // 返回值 7 赋给 result System.out.println(result); // 7 c.printHello(); // 只打印，无返回值 } }

把方法比作外卖点餐：

  • 参数是"你报给店家的需求"（点的菜品）。
  • 方法体是"店家在后厨制作"。
  • 返回值是"做好后递给你的成品"——你做加法方法，店家把"7"端出来给你；没返回值的 void 方法，就像"店家只帮你热了个菜但不给你端出来"（比如只打印一条消息），你自己不需要拿到结果。

面试速记口诀

"返回值是方法递给调用者的结果，靠 return 送出；void 就是没产出只做事。作用：传结果、封装复用、支持链式处理、表达执行状态。"

构造方法有哪些特性？
面向对象构造器

一句话概括

一句话：构造方法是"同名、无返回类型、new 时自动调用、可以重载、不能重写"的特殊方法。记住这五条特性，构造方法就基本拿下了。

定义

构造方法（Constructor）：与类名同名、没有返回类型（连 void 都不写）的特殊方法，在 new 创建对象时被自动调用，用来完成对象的初始化。

构造方法的核心特性

特性说明
1. 方法名与类名相同名字必须和类名完全一致（大小写也一致），这是硬性规定。
2. 没有返回类型不能写 int、void 等任何返回类型，写了就变成普通方法。
3. new 时自动调用创建对象时由系统自动调用，不需要手动写"方法名()"。
4. 可以重载（Overload）一个类可有多个参数不同的构造器，如无参、一个参数、两个参数。
5. 不能重写（Override）构造器名字跟类名走，父子类类名不同，无法构成重写。
6. 不能被 static/final/synchronized 修饰构造器属于实例创建阶段，不能是静态的，也谈不上 final/synchronized。
7. 可以有访问修饰符可为 public/private/protected 等，private 可限制外部创建（单例模式）。

补充特性说明

  • 自动提供默认构造器：类没写任何构造器时，编译器自动生成一个空的 类名() 默认构造器；一旦写了任何构造器，编译器就不再自动提供无参构造器。
  • 第一行限制：构造器第一行必须是 this(...)（调用本类其他构造器）或 super(...)（调用父类构造器），且两者只能出现一个；都不写时默认调用父类无参 super()。
  • 不能手动调用：构造器只能用 new 触发，不能像普通方法一样用 对象.构造器名() 调用。

举例讲解

class Student { String name; // 特性：与类名相同、无返回类型、可以重载 public Student() { } // 无参构造器 public Student(String n) { // 带参构造器（重载） this.name = n; } // 没有写 int 等返回类型，写了就是普通方法而非构造器 } class Demo { public static void main(String[] args) { Student s = new Student(); // new 时自动调用无参构造器 Student s2 = new Student("张三"); // new 时自动调用带参构造器 } }

把构造方法比作办理入住：

  • 名字跟酒店一致（与类同名）——"某某酒店前台"必须挂在"某某酒店"里。
  • 入住时前台自动接待（new 时自动调用）——你刚进门（new），前台（构造器）就自动帮你登记，不用你喊"前台，来登记"。
  • 可以选不同房型（重载）——无参是"标准房"，带参是"带名字的豪华房"，都能办入住。
  • 不能重写——每家酒店都有自己的前台，酒店不同前台名字就不同，没法"重写"别人家的前台。

面试速记口诀

"构造方法七特性：同名、无返回类型、new 自动调用、能重载、不能重写、不能 static/final/synchronized、可有访问修饰符。再加三条：没写自动送默认构造器、第一行只能 this 或 super、不能手动点调用。"

静态方法和实例方法有何不同？
关键字static

一句话概括

一句话：静态方法属于"类"，用 类名. 直接调、不依赖对象；实例方法属于"对象"，必须先 new 出对象再调用。核心区别在"从属于谁"和"能不能访问实例成员"。

定义

静态方法（static 方法）：用 static 修饰，属于类本身，随类加载而存在，通过 类名.方法() 直接调用，不依赖任何对象实例。

实例方法（非静态方法）：没有 static 修饰，属于某个具体的对象，必须先创建对象（new）再通过 对象.方法() 调用。

核心区别对比

维度静态方法实例方法
从属于类本身具体的对象
调用方式类名.方法() 或直接调用对象.方法()，必须 new 对象
生命周期类加载时就有，直到程序结束对象创建后才有，对象销毁随 GC
是否依赖对象不依赖，没有 this依赖，有 this 指向当前对象
访问静态成员可以可以
访问实例成员不能直接访问（无对象），除非传入对象引用可以
能否被重写不能（静态方法没有多态，可隐藏）可以
占用内存类加载分配，方法区/元空间对象创建后，随对象存堆中
使用场景工具类方法、工厂方法、主方法 main操作对象状态的业务方法

关键注意点

  • 静态方法不能直接访问实例成员：因为静态方法执行时可能还没有对象，没有 this，无法确定访问哪个对象的成员。想用就必须 new 一个对象或把对象作为参数传入。
  • 静态方法没有多态，不能被重写：子类可以定义同名静态方法，但那是"隐藏（hiding）"而非"重写（override）"，调用时按引用类型而非对象类型决定。
  • 实例方法可以访问静态成员：因为类一定存在，静态成员随时可用。
  • 静态方法只能用静态成员，实例方法两者都能用——这是面试常考点。

举例讲解

class Counter { static int count = 0; // 静态成员（属于类） int instanceNum; // 实例成员（属于对象） // 静态方法：可直接访问静态成员，不能直接访问实例成员 static void staticShow() { count++; // 合法 ✔ 静态成员 // instanceNum = 1; // 编译错误 ✘ 不能直接访问实例成员 } // 实例方法：静态成员和实例成员都能访问 void instanceShow() { count++; // 合法 ✔ instanceNum = 1; // 合法 ✔ } } class Demo { public static void main(String[] args) { Counter.staticShow(); // 类名调用静态方法 ✔ Counter c = new Counter(); // 先 new 对象 c.instanceShow(); // 对象调用实例方法 ✔ } }

把静态方法和实例方法比作工厂的公共设备和员工的私人物品：

  • 静态方法像工厂的"公共饮水机"——只要工厂在（类加载），任何人都能直接用（类名.方法()），不用等某个员工来。
  • 实例方法像"员工的专属技能"——必须等这位员工入职（new 对象）后才有，用的时候得叫他的名字（对象.方法()）。
  • 公共饮水机（静态方法）不能碰"员工的私人物品"（实例成员），因为工厂里可能还没人，不知道碰谁的；但员工（实例方法）既能用自己的私人物品（实例成员），也能用公共饮水机（静态成员）。

面试速记口诀

"静态方法属于类、类名直接调、不依赖对象、没有 this、只能碰静态成员；实例方法属于对象、先 new 再调、有 this、静态实例都能碰。静态方法不能重写只能隐藏。"

对象的相等与指向他们的引用相等，两者有什么不同？
基础equals

一句话概括

一句话："引用相等"比的是"两个引用是否指向同一个对象"（同一把钥匙开同一扇门），"对象相等"比的是"两个对象的内容/状态是否一样"（两扇不同的门但里面一样）。引用相等用 ==，对象相等用 equals()。

定义

引用相等（Reference Equality）：用 == 判断，比较的是两个引用变量是否指向堆中的同一个对象（即内存地址是否相同）。

对象相等（Object Equality）：用 equals() 判断，比较的是两个对象内部的状态/内容是否相等（逻辑上是否等价），即使它们是不同的对象。

核心区别对比

维度引用相等（==）对象相等（equals()）
比较的是什么引用（内存地址）对象的内容/状态
使用符号/方法==equals()
判断标准是否指向同一个对象逻辑上是否等价（可自定义）
基本类型比较数值不适用
引用类型比较地址默认比较地址，可重写为比较内容
两个不同对象内容相同falsetrue（重写 equals 后）
同一个对象truetrue

关键理解

  • Object 的默认 equals() 等价于 ==：如果类没有重写 equals()，那么它内部就是用 == 比较地址，此时"对象相等"和"引用相等"没有区别。
  • 重写 equals() 才是"对象相等"：String、Integer 等包装类重写了 equals()，比较内容，所以两个内容相同的不同对象 equals 为 true。
  • 注意自动装箱的坑：Integer a=100, b=100，缓存范围内 a==b 为 true（同一缓存对象）；超出范围 a==b 为 false（不同对象）。所以包装类比较一律用 equals。
  • 重写 equals 必须重写 hashCode：保证相等的对象有相同的哈希值，否则 HashMap/HashSet 会出问题。

举例讲解

// String 重写了 equals()，比较内容 String s1 = new String("hello"); String s2 = new String("hello"); // 引用相等：两个不同对象，地址不同 → false System.out.println(s1 == s2); // false // 对象相等：内容相同 → true System.out.println(s1.equals(s2)); // true // 同一个对象：== 和 equals 都是 true String s3 = s1; System.out.println(s1 == s3); // true System.out.println(s1.equals(s3)); // true

把引用和对象比作"地址"和"房子"：

  • 引用相等（==）是问："这两个地址是不是同一个门牌号？"——如果两个引用都指向同一栋房子（同一个地址），就是 true。
  • 对象相等（equals）是问："这两栋房子内部装修/内容是不是一样？"——两栋不同门牌号的房子（不同地址），但里面住的人、布局完全相同，逻辑上就算相等。
  • 同一个门牌号（== true）的房子内容肯定一样（equals 也 true）；但内容一样的房子（equals true）不一定是同一栋（== 可能是 false）。

面试速记口诀

"== 比地址（是不是同一扇门），equals 比内容（两扇门里的东西一样不一样）。默认 equals 就是 ==，重写 equals 才比内容；重写 equals 必须重写 hashCode，包装类比较一律用 equals。"

在调用子类构造方法之前，会先调用父类没有参数的构造方法，其目的是？
面向对象继承构造器

一句话概括

一句话：在调用子类构造方法前，会先调用父类的无参构造方法，目的是先完成父类的初始化，保证子类继承到的"父类部分"是就绪的。这就像盖房子先打好地基，子类对象才能建立在完整的父类基础之上。

定义

构造执行顺序：在 Java 中，创建一个子类对象时，会先执行父类的构造方法，再执行子类的构造方法（先父后子）。子类构造器第一行隐含调用 super()（父类无参构造器）。

根本目的

  • 保证父类部分初始化完成：子类对象在内存中其实"包含"一个父类对象（父类的成员变量和方法是子类的一部分）。不先初始化父类，子类继承到的属性就可能是未初始化的（null、0），无法使用。
  • 符合"先有父再有子"的逻辑：对象构造是自顶向下的，父类是子类存在的前提，只有父类先构建好，子类才能在此基础上扩展。
  • 保证继承成员可用：子类构造方法里可能用到父类的字段或调用父类的方法，如果父类没初始化，这些成员就没有正确状态。

执行顺序说明

class Animal { public Animal() { System.out.println("父类构造执行"); // 先执行 } } class Dog extends Animal { public Dog() { super(); // 隐含调用，可省略 System.out.println("子类构造执行"); // 后执行 } } new Dog(); // 输出顺序：父类构造执行 → 子类构造执行
  • 子类构造器第一行必须是 super(...) 或 this(...)，不写就默认 super() 调用父类无参构造器。
  • 如果父类没有无参构造器（只有带参构造器），子类必须显式 super(参数) 调用父类某个构造器，否则编译报错。
  • 多层继承时层层向上：爷爷 → 爸爸 → 儿子，最顶层的父类最先执行。

举例讲解

把对象比作一栋建筑，把类继承比作"地基 → 框架 → 装修"：

  • 父类是地基和框架，子类是在这基础上做的装修。
  • 必须先打好地基、建好框架（先执行父类构造），才能开始装修（再执行子类构造）。如果不先建好父类部分，装修（子类）就无处可施。
  • 也像"先有父，后有子"——子类继承自父类，父类没初始化，子类继承到的属性就是残缺的。

面试速记口诀

"先父后子是铁律：创建子类对象，先执行父类构造再执行子类构造。目的是先把父类部分初始化好，子类继承的属性才可用。子类构造第一行隐含 super()，父类只有带参构造时得显式 super(参数)。"

hashCode 与 equals 的区别？
基础equalshashCode

一句话概括

一句话：equals 判断两个对象是否"相等"（内容是否一样），hashCode 返回对象的"哈希值"（一个散列编号）。两者关系紧密：equals 相等的对象，hashCode 必须相等；hashCode 相等，equals 不一定相等。

定义

equals()：Object 类的方法，判断两个对象是否相等。默认比较地址，String 等类重写后比较内容。

hashCode()：Object 类的方法，返回对象的一个int 类型的哈希值，通常根据对象的字段计算出来，用于在哈希结构（HashMap、HashSet 等）中快速定位。

两者的关系（重要约定）

约定说明
1. equals 相等 → hashCode 必须相等两个对象 equals 为 true，它们的 hashCode 一定相同，否则违反散列约定。
2. hashCode 相等 → equals 不一定相等哈希值相同不代表对象内容相同（哈希碰撞），还需用 equals 精确判断。
3. hashCode 不同 → equals 必为 false哈希值不同，说明两个对象一定不相等。
4. 重写 equals 必须重写 hashCode否则在 HashMap/HashSet 中会出现"相等对象哈希不同"的 bug。

区别对比

维度equals()hashCode()
作用判断两个对象是否相等返回对象的哈希值（散列编号）
返回类型booleanint
核心用途逻辑上的对象比较哈希结构快速定位/散列存储
性能可能遍历比较所有字段，较慢计算一个数值，较快
是否必须重写需要时重写重写 equals 时必须一起重写

在 HashMap 中如何配合工作

  • 放入 HashMap 时，先算 hashCode 找到桶（bucket）位置，再在桶内用 equals 判断是否已存在相同 key。
  • 所以 hashCode 负责"分桶提速"，equals 负责"精确判断"。二者配合，既能快速定位，又保证正确性。

举例讲解

class Person { String name; int age; Person(String name, int age) { this.name=name; this.age=age; } @Override public boolean equals(Object o) { if (!(o instanceof Person)) return false; Person p = (Person) o; return name.equals(p.name) && age == p.age; // 内容相等 } @Override public int hashCode() { return name.hashCode() + age; // 重写 equals 必须重写 hashCode } }

把 hashCode 比作图书馆的索书号/书架编号，把 equals 比作逐字核对书本内容：

  • hashCode 像先根据书名算出它在几楼几排书架（分桶），能快速缩小范围。
  • equals 像在这个书架上逐本核对，确认到底是不是你要的那本书（精确判断）。
  • 两本一样的书（equals 相等），索书号（hashCode）必然一样；但索书号一样的书（hashCode 相等），可能是上下册或同名不同内容（equals 不一定相等，哈希碰撞）。

面试速记口诀

"equals 比相等，hashCode 算编号；equals 相等 hashCode 必相等，hashCode 相等 equals 不一定相等，hashCode 不同 equals 必 false。重写 equals 必须重写 hashCode，否则 HashMap/HashSet 出 bug。"

为什么 Java 中只有值传递？
基础语法高频

一句话概括

一句话：Java 方法调用时，参数传的都是"栈中存的值的副本"，基本类型传数值副本，引用类型传"引用地址值的副本"，所以本质只有值传递，不存在"把变量本身传进去"的引用传递。

定义

值传递（Pass by Value）：方法调用时，把实参的值复制一份传给形参，形参的修改不影响实参。

引用传递（Pass by Reference）：把实参的变量本身（地址）传给形参，形参和实参指向同一内存，修改会互相影响。

为什么只有值传递（核心原因）

  • 方法参数存的是"栈中的值"：Java 所有变量（基本类型和引用类型）在栈中都存一个"值"——基本类型存数值本身，引用类型存"指向堆中对象的地址值"。
  • 传参时复制的是这个"栈中的值"：不管传什么，都是把这个值拷贝一份给形参，形参拿到的是副本，不是变量本身。
  • 形参和实参是不同的变量：它们各自持有值，修改形参（重新赋值）不会改变实参持有的值。
  • 引用类型"能改对象内容"≠引用传递：因为形参和实参的地址值相同，指向同一个对象，所以通过形参obj.xxx能改对象内容——但这是"通过引用访问对象"，不是"传递了引用变量本身"。若给形参重新赋新对象（obj = new ...），实参不受影响，这就证明了只是值传递。

验证方式：两个典型例子

// 例1：基本类型，值传递，实参不变 static void f(int a) { a = 100; } int x = 10; f(x); // x 仍为 10，形参 a 的修改不影响实参 // 例2：引用类型，传的是"地址值副本"，重新赋值实参不变 static void g(Person p) { p = new Person(); } // 重新指向新对象 Person p1 = new Person(); g(p1); // p1 仍指向原来的对象，没变成新对象 → 证明只传了地址副本 // 例3：但通过形参修改对象内容会生效（因地址相同指向同一对象） static void h(Person p) { p.name = "新名字"; } h(p1); // p1.name 被改成"新名字" → 因为 p1 和形参 p 指向同一对象

关键理解

  • 引用类型变量 = 持有地址的变量，传参传的是这个"地址值"的副本。
  • 通过形参改对象内容生效，是因为地址值副本仍指向同一个对象，不是引用传递。
  • 通过形参改形参自身指向（重新赋值）不生效，实参不会跟着变——这是判断"值传递"的铁证。
  • C++ 才有真正的引用传递（&）；Java 借鉴了 C 的指针但更安全，只允许值传递。

举例讲解

把参数传递比作复印文件：

  • 值传递就像你把一张复印件的副本交给对方，对方在副本上乱涂乱画（修改形参），原件（实参）完全不受影响。
  • 引用类型传参，相当于你复印了"一张写有地址的小纸条"给对方，对方按地址能找到你的房子（改房子内部=改对象内容会生效），但对方把这张纸条改成另一个地址（重新赋值），你的房子地址不会变。
  • 所以 Java 永远是"给复印件/地址纸条副本"，从没有把"原件"或"地址本"整个交出去，故只有值传递。

面试速记口诀

"Java 只有值传递：基本类型传数值副本，引用类型传地址副本。判断铁证——给形参重新赋值（指向新对象）实参不变就是值传递；通过形参改对象内容生效是因为地址相同，不是引用传递。"

简述线程、程序、进程的基本概念，以及它们之间的关系是什么？
并发进程线程

一句话概括

一句话：程序是"静态的代码"，进程是"程序的一次运行"，线程是"进程内的执行单元"。关系是层层包含：程序 → 进程 → 线程，一个程序可对应多个进程，一个进程可包含多个线程。

基本概念

  • 程序（Program）：一组静态的指令和数据的有序集合，是存在磁盘上的可执行代码，本身不占用 CPU 资源，是"死的"。
  • 进程（Process）：程序的一次执行过程，是操作系统进行资源分配（CPU、内存、IO）的基本单位，是"活的"、动态的，有独立的地址空间。
  • 线程（Thread）：进程内的一个更小的执行单元，是 CPU 调度的基本单位，多个线程共享所属进程的资源（内存、文件），线程之间可并发执行。

三者关系对比

维度程序进程线程
本质静态指令/代码集合程序的一次运行进程内的执行单元
动态性静态，不执行动态，正在运行动态，正在执行
资源不占 CPU/内存资源系统资源分配的基本单位共享进程资源，CPU 调度基本单位
地址空间存在磁盘上拥有独立地址空间共享所属进程的地址空间
数量关系一个程序可多次运行对应多个进程一个进程可有多个线程
系统开销—创建/切换开销大创建/切换开销小（更轻量）

三者关系详解

  • 程序 → 进程：一个程序可以被执行多次，每次执行就产生一个进程。比如同一个记事本程序，你可以同时打开多个窗口，就是多个进程。
  • 进程 → 线程：一个进程可以包含一个或多个线程。线程是进程内的执行路径，多线程让进程能同时做多件事。
  • 包含关系：进程是程序的动态实例，线程是进程的动态执行单元，层层向下包含。

举例讲解

把三者比作"剧本、演出、演员"：

  • 程序 = 剧本：写在纸上的台词和情节（静态代码），放在那里不会自己演，也不占舞台资源。
  • 进程 = 一场演出：把剧本搬上舞台实际演起来（程序运行），需要舞台、灯光、道具（CPU、内存等资源），每次演出都是一场独立的"演出"（进程）。同一个剧本（程序）可以演很多场（多个进程）。
  • 线程 = 舞台上的演员：一场演出（进程）里有多个演员（线程）在同时表演，他们共用同一个舞台（共享进程资源），协同完成整场戏。

再形象一点：程序是"菜谱"（静态文字），进程是"照着菜谱做出来的那锅菜"（实际烹饪过程），线程是"炒菜时同时切菜、烧火、放调料等多个动作"（进程内并行的动作单元）。

面试速记口诀

"程序是死的代码，进程是程序的一次运行，线程是进程里的执行单元。层层包含：程序→进程→线程，一个程序多个进程，一个进程多个线程；进程是资源分配单位，线程是 CPU 调度单位。"

关键字final经典

一句话概括

一句话：final 是 Java 的"不可变/不可覆盖"修饰符——修饰类不可继承、修饰方法不可重写、修饰变量不可重新赋值。三句话记住它的核心作用。

定义

final 关键字：用来修饰类、方法、变量的关键字，表示"最终状态"，一旦设定后不可再改变。

final 的三大核心用途

修饰对象作用示例/注意点

  • final 方法像"固定的操作流程"——后人只能照着用，不能改流程（重写），保证核心逻辑不被破坏。
  • final 变量像"盖了章的房产证"——房产证主人（引用）不能换（不能重新指向新对象），但房子里的家具（对象内容）可以随意摆放（可修改内容）。

Java 中的异常处理有哪些？
异常处理经典

一句话概括

一句话：Java 异常处理的核心是 try-catch-finally 机制 + throw/throws 关键字，再加上异常分类体系（Error / Exception），用它们来捕获、抛出和兜底处理程序运行中的异常情况。

异常处理的核心机制

  • try-catch：把可能出错的代码放在 try 块中，用 catch 捕获并处理指定类型的异常。
  • finally：无论是否发生异常都会执行的代码块（除非 System.exit），常用于释放资源（关闭流、连接）。
  • throw：手动抛出一个异常对象（方法体内）。
  • throws：声明方法可能抛出的异常，交给调用方处理（方法签名上）。
  • try-with-resources：JDK7+，自动关闭实现 AutoCloseable 的资源，简化资源释放。

异常分类体系

Throwable（所有异常/错误的根类） ├── Error（严重错误，不处理） │ ├── OutOfMemoryError │ └── StackOverflowError └── Exception（程序可处理） ├── RuntimeException（运行时异常，可选处理） │ ├── NullPointerException │ ├── IndexOutOfBoundsException │ └── ClassCastException └── Checked 检查异常（必须处理） ├── IOException ├── SQLException └── ClassNotFoundException

异常处理的几种写法

写法说明
try-catch捕获异常并处理，程序继续运行。
try-catch-finally捕获异常 + 无论如何执行 finally 清理资源。
try-finally不捕获，只保证 finally 执行（异常向上抛）。
try-with-resourcesJDK7+，资源自动 close，代码更简洁安全。
多个 catchJDK7+ 可用 catch(A | B e) 合并捕获多个异常。

基本使用示例

public void readFile(String path) throws IOException { // throws 声明 try (BufferedReader br = new BufferedReader(new FileReader(path))) { String line; while ((line = br.readLine()) != null) { System.out.println(line); } } catch (FileNotFoundException e) { // 精确捕获 throw new IllegalArgumentException("文件不存在: " + path, e); } finally { // 兜底清理 System.out.println("清理完成"); } }

使用原则与注意事项

  • 不要吞异常：catch 里空实现或只打印不处理会让问题被隐藏，应记录日志或重新抛出。
  • catch 顺序：子类异常在前、父类异常在后，否则父类会提前捕获。
  • finally 与 return：finally 中有 return 会覆盖 try 的返回值，尽量避免。
  • 用异常还是返回值：业务校验类用返回值/断言，不可预期的错误用异常。
  • 避免 catch 一切（catch(Exception e)）：过度捕获会掩盖真实错误，应精确到具体异常类型。

举例讲解

把异常处理比作"厨房做菜遇到问题"：

  • try 是"开始炒菜"（正常流程）。
  • catch 是"菜烧糊了"（异常），赶紧补救——少放盐就加盐（处理异常），菜还能吃（程序继续）。
  • finally 是"不管菜好不好，最后都要洗锅关火"（清理资源），是必须做的事。
  • throw 是"我发现食材变质了，主动喊厨师长"（主动抛出异常）。
  • throws 是"这道菜可能做糊，我提前告诉客人"（声明可能异常，让调用方处理）。
  • Error 是"厨房着火了"（严重错误 OOM/StackOverflow），没法补救，只能终止。

面试速记口诀

"异常处理五板斧：try-catch 抓、finally 清、throw 抛、throws 声明、try-with-resources 自动关。体系是 Throwable 分 Error 和 Exception，Runtime 可选、Checked 必处理。"

Java 序列化中如果有些字段不想进行序列化，怎么办？
序列化transient

一句话概括

一句话：用 transient 关键字修饰不想序列化的字段，序列化时该字段会被跳过，反序列化后其值为默认值（引用为 null、基本类型为 0/false）。

定义

transient：Java 序列化关键字，修饰字段后，该字段在对象序列化时不会被写入字节流，从而不被持久化或传输。

如何使用

import java.io.Serializable; class User implements Serializable { private static final long serialVersionUID = 1L; private String name; // 正常序列化 private int age; // 正常序列化 private transient String password; // 不想序列化，加 transient private transient static String salt; // 静态字段本身就序列化不了，加 transient 更保险 }

为什么要跳过某些字段

  • 敏感信息：密码、token、银行卡号等，不应被持久化或传输到磁盘/网络。
  • 非必要的缓存数据：如派生字段、临时缓存，反序列化后可按需重新计算。
  • 不可序列化的引用：字段类型没实现 Serializable，避免序列化抛 NotSerializableException。

关键注意点

注意点说明
transient 只修饰字段只能修饰成员变量，不能修饰类、方法、局部变量。
静态字段天然不序列化static 字段属于类，本来就不随对象序列化，加 transient 无实际意义（但可加双保险）。
反序列化后是默认值transient 字段反序列化后为默认值：引用 null、int 为 0、boolean 为 false。
final 字段也可 transientfinal transient 字段反序列化后为默认值，不是其初始值。
不影响内存使用transient 只是序列化时跳过，对象在内存中该字段仍正常存在、可用。

补充：更灵活的自定义方式

如果对序列化有更复杂的需求（如想加密后再序列化），可以重写 writeObject() 和 readObject() 方法，自定义序列化逻辑，自由决定哪些字段、以什么形式写入。

举例讲解

把序列化比作"打包托运包裹"：

  • 对象的字段像包裹里的物品，序列化就是装箱托运。
  • transient 字段像"不能托运的违禁品或私密物品"（如密码、银行卡），装箱时被单独拿出来不放进包裹（不序列化）。
  • 到达目的地（反序列化）后，私密物品（transient 字段）位置是空的（null / 默认值），因为根本就没装箱。
  • 但私密物品在出发地（内存）里一直都在、正常使用，只是不上托运（不序列化）。

面试速记口诀

"不想序列化就加 transient：密码/缓存/不可序列化字段都适用。注意 transient 只修饰字段、反序列化后是默认值、static 本来就不序列化、内存里照常存在。更复杂需求可重写 writeObject/readObject 自定义。"

把两种方式比作"点餐的两种方式"：

  • Scanner 像自助点餐机：可以直接选择"点一份饭"（nextInt 读数字）、"点一份菜"（next 读字符串），界面友好、操作直接，适合日常简单点餐（简单交互）。
  • BufferedReader 像后厨传菜窗口：它不管菜是什么，只是把菜（字符串）一大盘一大盘端出来（readLine 读一行），具体是饭还是菜（转成 int、double）得你自己去分辨转换，但端得快（缓冲、性能高）。

补充：此外还有 Console 类（System.console().readLine()，适合控制台交互且不能重定向输入）等，但最常考的是 Scanner 和 BufferedReader 两种。

面试速记口诀

"键盘输入两把钥匙：Scanner 简单读啥都行（自动转类型）、BufferedReader 只能读字符串（手动转类型）但性能高。刷题常用 Scanner，大数据量用 BufferedReader。"

常见关键字总结：static、final、this、super 等等
关键字经典总结

一句话概括

一句话：static 管"属于类"，final 管"不可变/不可覆盖"，this 管"本类当前对象"，super 管"父类引用"，再加上其他高频关键字（volatile、synchronized、transient、abstract 等）各司其职。

四大核心关键字详解

关键字作用核心要点典型场景
static属于类，不依赖对象静态变量/方法/代码块/内部类；不能直接访问实例成员；不能使用 this工具类方法、常量、主方法 main
final不可变/不可覆盖类不可继承、方法不可重写、变量不可重新赋值；引用类型只锁引用不锁内容String 类、常量 static final
this当前对象引用区分成员变量与局部变量、调用本类构造器 this()、链式编程 return this构造器赋值、链式调用
super父类引用访问父类成员、调用父类构造器 super()；必须放构造器第一行子类构造器、重写时调父类方法

static 详细用法

  • 静态变量：static int count，属于类，所有对象共享一份。
  • 静态方法：static void f()，类名直接调，不能访问实例成员。
  • 静态代码块：类加载时执行一次，用于初始化静态变量。
  • 静态内部类：不依赖外部类实例，只能访问外部类静态成员。
  • 静态导入：import static xxx，直接使用静态成员名。

final 详细用法

  • final 类：不可继承（String、Integer）。
  • final 方法：不可重写，可被继承调用。
  • final 变量：不可重新赋值；引用类型内容可变。
  • static final：常量，命名全大写，如 MAX_VALUE。

class Animal { String name; public Animal(String name) { this.name = name; } // this 区分参数与成员 void eat() { System.out.println("吃"); } } class Dog extends Animal { static final String TYPE = "犬类"; // static final 常量 static int count; // static 静态变量 public Dog(String name) { super(name); // super 调父类构造器 count++; // 静态变量所有对象共享 } @Override void eat() { super.eat(); // super 调父类方法 System.out.println("狗粮"); } }

用一句话记住四个关键字：

  • static 像"公司公共会议室"——属于公司（类）而不是某个员工（对象），谁都能预约使用。
  • final 像"公司制度"——定死了不能改：公司章程（final 类）不能被子公司继承，核心流程（final 方法）不能改，年度预算（final 变量）不能超。
  • this 像"说'我自己'"——员工说"我自己来做"（this），指的就是当前这个员工自己。
  • super 像"找我师傅/领导"——徒弟做不了找师傅（super 父类），先让师傅处理（父类构造/方法）再自己补充。

面试速记口诀

"static 属于类、final 不可变、this 指本对象、super 指父类；this() 和 super() 只能二选一且放首行、静态方法里都不能用 this 和 super。再记 volatile 可见、synchronized 加锁、transient 不序列化、abstract 不能配 final。"

Arrays 工具类常见方法有哪些？
工具类Arrays高频

一句话概括

一句话：Arrays 是 java.util 包下专为数组服务的工具类，最常用的是 sort 排序、binarySearch 二分查找、copyOf 拷贝、toString 打印、fill 填充、equals 比较、asList 转 List。

定义

Arrays：java.util.Arrays，提供了一系列操作数组的静态方法（排序、查找、拷贝、填充、比较、打印、转换等），全部是 static 方法，直接 Arrays.方法名() 调用。

常见方法总结

方法作用示例
sort()数组排序（默认升序，可传 Comparator 自定义）Arrays.sort(arr)
binarySearch()二分查找，返回下标；未找到返回负数插入点Arrays.binarySearch(arr, 5)
copyOf()拷贝数组（可指定新长度）Arrays.copyOf(arr, len)
copyOfRange()拷贝数组指定范围Arrays.copyOfRange(arr, from, to)
toString()把数组转成字符串打印Arrays.toString(arr)
deepToString()多维数组转字符串Arrays.deepToString(arr2d)
fill()用指定值填充数组Arrays.fill(arr, 0)
equals()比较两个数组是否相等（长度+元素）Arrays.equals(a, b)
asList()数组转 List（注意：返回固定长度 List）Arrays.asList(1,2,3)
stream()数组转 Stream（JDK8+）Arrays.stream(arr)
parallelSort()并行排序（JDK8+，大数据量更快）Arrays.parallelSort(arr)

使用示例

import java.util.Arrays; public class Demo { public static void main(String[] args) { int[] arr = {3, 1, 4, 1, 5}; Arrays.sort(arr); // 排序 → [1,1,3,4,5] System.out.println(Arrays.toString(arr)); // [1, 1, 3, 4, 5] int idx = Arrays.binarySearch(arr, 4); // 二分查找 → 3 int[] copy = Arrays.copyOf(arr, 3); // 拷贝前3个 → [1,1,3] int[] filled = new int[3]; Arrays.fill(filled, 7); // 填充 → [7,7,7] boolean eq = Arrays.equals(arr, copy); // 比较 → false java.util.List<Integer> list = Arrays.asList(1, 2, 3); // 转 List } }

易错点提醒

  • binarySearch 前提：必须先排序，否则结果不确定。
  • asList 的坑：返回的是 Arrays 内部类 ArrayList（固定长度），不能 add/remove，会抛 UnsupportedOperationException；想可变需 new ArrayList<>(Arrays.asList(...))。
  • asList 泛型：Arrays.asList(1,2,3) 返回 List<Integer>；传基本类型数组如 int[] 会把整个数组当作一个元素，需用包装类数组。
  • equals vs deepEquals：一维用 equals，多维数组比较用 Arrays.deepEquals()。

举例讲解

把 Arrays 比作"数组的万能工具箱"：

  • sort 像"整理书架"——把乱序的书按顺序排好。
  • binarySearch 像"查字典"——前提是字典已经按字母排好（先排序），翻找才快（二分）。
  • copyOf 像"复印文件"——把原数组复印一份，复印份数（新长度）可指定。
  • toString 像"报菜名"——把数组内容用一行字念出来，方便查看。
  • fill 像"给格子贴同一种标签"——所有位置填成同一个值。
  • asList 像"把散装货装进固定货架"——转成 List，但货架是固定死的（不能增删）。

面试速记口诀

"Arrays 七件套：sort 排序、binarySearch 查找（先排序）、copyOf 拷贝、toString 打印、fill 填充、equals 比较、asList 转 List。记坑：asList 固定长度不能增删、binarySearch 必须先排序。"
