什么是 Nginx？有哪些优势和功能？
概述高频

1. 定位：

Nginx 是开源的高性能 HTTP 服务器和反向代理服务器，也可做邮件（IMAP/POP3）代理、TCP/UDP 负载均衡器。

2. 三大核心功能：

  • HTTP 服务器：承载静态资源（图片、CSS、JS、视频），响应速度快。
  • 反向代理 + 负载均衡：隐藏后端真实服务，把流量分发到多个应用节点。
  • API 网关能力：限流、鉴权、缓存、动静分离、协议转换。

3. 优势：

  • 高并发：epoll + 异步非阻塞，单机可轻松支撑数万并发连接。
  • 内存消耗小：进程模型轻量，事件驱动无大量线程开销。
  • 热部署：nginx -s reload 平滑重载配置，不断连接。
  • 稳定：分阶段请求处理，某一模块异常不至于拖垮整个服务。

💡 使用场景：静态资源服务器、反向代理、负载均衡、Web 服务缓存、限流。

正向代理和反向代理有什么区别？Nginx 是哪种？
反向代理

1. 正向代理（代理客户端）：

服务器不知道真实客户端是谁。客户端主动配置代理，请求经代理转发给目标服务器 —— 典型场景：VPN 翻墙、公司统一出口。

2. 反向代理（代理服务端）：

客户端不知道真实服务器是谁。请求打到 Nginx，由 Nginx 转发给内网集群，对客户端完全透明 —— 典型场景：负载均衡、SSL 终结、隐藏架构、CDN。

3. 一句话区分：

正向代理隐藏客户端（服务端看不清访问者），反向代理隐藏服务端（客户端不知道背后有几台机器）。Nginx 主要用作反向代理：客户端不感知后端节点数量与拓扑，Nginx 负责转发、负载均衡与故障摘除。

Nginx 为什么不使用多线程？如何实现超高并发？
C10Kepoll高频

1. 不用多线程的原因：

  • 线程/进程切换开销大（上下文切换、栈内存），C10K 问题下上万个连接一个线程一条开销巨大。
  • 线程间同步复杂，易死锁。

2. 核心设计：异步非阻塞 + IO 多路复用（epoll）

  • 非阻塞：数据未就绪不傻等，直接返回去做别的，等 epoll 事件通知再回来处理。
  • epoll：一个 worker 进程监视成千上万个连接的事件（读写就绪），事件驱动处理，连接再多数千也只是"注册进内核"，不增加活跃线程。
  • 进程数与 CPU 核数绑定：每个 worker 单线程跑满一个核，无锁串行处理，CPU 亲和性绑定减少缓存失效。

💡 Nginx 是 C10K 问题（单机 1 万并发连接）的标准答案之一；Node、Redis、Netty 同属"单线程 + 事件驱动"流派。

Nginx 的 Master 进程和 Worker 进程分别做什么？
进程模型

1. Master 进程（管理者，root 身份）：

  • 读取、校验配置文件（nginx -t）。
  • 创建、监听端口，fork 出 Worker 进程，监控其生死并自动拉起。
  • 处理信号：reload 平滑重载（新起 Worker 加载新配置，旧 Worker 处理完存量请求后退出）、平滑升级二进制。

2. Worker 进程（干活的，普通用户身份）：

  • 实际处理网络连接与请求（epoll 事件循环）。
  • 数量通常等于 CPU 核数（worker_processes auto），彼此独立、互不干扰。
  • Master/Worker 分离的好处：Worker 挂了 Master 自动拉新；reload 不断服务；权限分离（Worker 普通用户，降低提权风险）。

💡 所有 Worker 通过锁竞争 accept 同一监听端口的连接（惊群已由内核解决）。

Nginx 负载均衡的实现过程？常用哪些算法？
负载均衡高频

1. 实现过程：

upstream backend { server 192.168.1.1:8080 weight=5; server 192.168.1.2:8080; server 192.168.1.3:8080 backup; } server { listen 80; location / { proxy_pass http://backend; } }

请求先到 Nginx，Nginx 按 upstream 里配置的策略挑一台后端转发，把响应回传客户端；节点挂了自动标记失败并在失败时间内不再分发。

2. 常用算法：

  • 轮询（默认）：依次分发。
  • weight 权重轮询：性能强的机器多接流量。
  • ip_hash：同一客户端 IP 固定打到同一节点（会话保持）。
  • least_conn：当前连接数最少的节点优先。
  • hash：按自定义 key（如 URL、cookie）一致性哈希。
  • fair（第三方）：按响应时间智能分配。

💡 backup 备机只在主节点全挂时启用；健康检查配合 max_fails/fail_timeout 实现故障摘除。

什么是动静分离？为什么要做动静分离？
架构

1. 概念：

把网站的静态资源（HTML/CSS/JS/图片/视频）与动态内容（API 接口、需要计算生成的数据）分开部署、分开处理。

location ~* \.(jpg|css|js|png)$ { # 静态：Nginx 直接返回 root /data/www/static; expires 30d; } location /api/ { # 动态：转发给后端集群 proxy_pass http://backend; }

2. 为什么分离：

  • 静态请求由 Nginx 直接吐文件，不用进应用服务器，大幅降低 Tomcat 等后端压力。
  • 静态资源可单独加 CDN、设置长缓存头，浏览器命中缓存后直接本地读取，响应更快。
  • 前后端彻底解耦：前端独立部署发布，不牵扯后端发版。

Nginx 的高可用是怎么做的？
Keepalived高可用

问题：Nginx 单机部署时，它自己就是单点 —— 挂了整个入口都不可用。

方案：Keepalived + VIP（虚拟 IP）双机主备

  • 两台 Nginx 装相同配置，对外共用一个虚拟 IP（VIP）。
  • Keepalived 通过 VRRP 协议在两台机器间通信：Master 持有 VIP 并广播心跳。
  • Master 挂掉 → Backup 收不到心跳 → 抢占 VIP 接管流量，客户端无感知（DNS 仍指向 VIP）。
  • Master 恢复后按抢占/非抢占策略夺回 VIP。

💡 更高阶：LVS+Keepalived 四层做前置、Nginx 集群做七层；云上则用 SLB/ALB 等托管负载均衡替代自建。

Nginx 常用命令有哪些？
运维
命令作用
nginx启动
nginx -s stop快速停止（立即）
nginx -s quit优雅停止（处理完当前请求）
nginx -s reload平滑重载配置（不中断服务）
nginx -s reopen重新打开日志文件（日志切割）
nginx -t检测配置文件语法（改配置后先测）
nginx -v / -V版本信息 / 编译参数详情
nginx -c file指定配置文件路径

日志切割实战：mv 移走旧日志后执行 nginx -s reopen，或用 logrotate 定时切割；改配置的标准流程是 nginx -t 校验 → nginx -s reload 热加载。
